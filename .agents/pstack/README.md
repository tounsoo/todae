# Pinned pstack

This folder holds the copy of [pstack-claude](https://github.com/michael-denyer/pstack-claude) that todae's agent threads use. Threads read it from the checkout and download nothing. [0015](../../docs/decisions/0015-pinned-pstack-copy.md) records why.

- `plugin/` is upstream's `plugins/pstack` folder at one commit: the skills, the agents and the rest, with the MIT licenses and notice in `plugin/skills/poteto-mode/references/licenses/`. Don't edit it by hand. Todae's changes to pstack belong in `.agents/playbooks/`, `.claude/thread-start.md` and `.claude/models.md`.
- `pin.json` names the upstream commit the copy is at, and Git's tree id for the copy. CI's Forbidden paths job runs [`.github/scripts/pstack-upstream.sh`](../../.github/scripts/pstack-upstream.sh) whenever `pin.json` changes, which fails unless that id is upstream's folder at that commit and the commit is on upstream's default branch.
- `check.sh` checks that the committed copy has that tree id and no uncommitted changes or extra files, ignored ones included, that it has a license and the skill and agents threads use, and that every quoted anchor in `.agents/playbooks/` is still in the pstack playbook it extends. Threads run it at the start, as `.claude/thread-start.md` says, and CI's Forbidden paths job runs it on every change. It reads text only.
- `update.sh` replaces `plugin/` with upstream's folder at a commit and rewrites `pin.json`. It builds the copy from upstream's own tree, so `.gitignore` and `.gitattributes` change nothing in it, and it refuses a folder with links, submodules or no license. Only the update workflow runs it, because it downloads code.

## Updates

[`.github/workflows/pstack-update.yml`](../../.github/workflows/pstack-update.yml) runs every Monday at 9:17 AM Seoul time, and by hand from the Actions tab. Its steps are in [`.github/scripts/pstack-update.sh`](../../.github/scripts/pstack-update.sh), which `pstack-update.test.mjs` tests. It reads upstream's newest commit. If an update pull request is open, it merges `main` into that pull request's branch, runs `update.sh` and commits the update on top. Otherwise, when `main`'s copy isn't at that commit, it commits the update to a `pstack-update/<commit>` branch and opens a pull request, picking up the branch if an earlier run pushed it and then failed to open the pull request. No branch is rewritten or deleted. The pull request body links upstream's changes from `main`'s commit, lists the files upstream added or removed and the changed files that name Fable, and gives the result of `check.sh`. It opens nothing when the copy is current, or when a pull request for the same upstream commit was closed without merging: reopen it to take that commit. Each update reaches threads only once Ben merges it.

When `check.sh` fails on an update, a todae playbook quotes pstack text that upstream changed, and CI fails. Change that playbook in the same pull request before it merges.

## The first copy

The copy this folder started with came from todae's own history, not from a download: the vendored copy removed on 2026-11-02, at upstream `49b68501b075ec1eb2755dd0d22fbf2492d67e97`, with todae's Fable-to-Opus rewrites taken back out. It lacks five skills that the old copy skipped (`babysit`, `fix-ci`, `fix-merge-conflicts`, `get-pr-comments` and `setup-pstack`) and any upstream file the old copy never held, such as the plugin manifest. Its `effort-agents/` and `hooks/` folders are rebuilt from where the old update script put them. `pin.json` says so in `restored_from`, and its tree id is that rebuilt copy's own, so `check.sh` catches any edit to it, but nothing has compared it with upstream. The first update pull request brings in upstream's folder word for word.
