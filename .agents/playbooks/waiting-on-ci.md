### Waiting on CI

Cloud sessions have no `gh` and no `watch-pr`, and GitHub stays silent about some pull request states. These changes replace the watcher with GitHub pull request events and GitHub MCP reads.

- **Replace** "Babysitting starts when the user asks for it, which is normally once a phase or a whole stack is built, not when a PR opens." with: A session drives every pull request it opened, from the moment it opens, in `drive` mode.
- **Replace** "A conflict and the watcher's `behind-base` gate are the two blockers you report rather than resolve." with: Resolve a conflict yourself and don't mention it. Merge `origin/main` into the branch (no rebase or force-push), keep both sides, regenerate generated files with `pnpm schema` and `pnpm --filter docs i18n:stamp`, run the review round from `.agents/playbooks/review-before-pr.md` on `<base>..HEAD`, then push. Tell the user only about a conflict you can't settle, such as two pull requests that change the same behavior in incompatible ways.
- **Replace** "On GitHub, status comes from the watcher at `skills/poteto-mode/scripts/watch-pr/watch-pr` under the installed plugin." with: Status comes from the GitHub MCP tools. Read the pull request's `mergeable_state`, the check runs on the head commit, and the open review threads. GitHub runs no `pull_request` workflow on a pull request that conflicts with its base, and every job on a draft finishes as `skipped`, which is not a result. Right before opening, pushing or marking ready, fetch `origin/main` and run `git merge-tree --write-tree HEAD origin/main`, which exits 1 on a conflict.
- **Replace** "Run `drive` and `background` under `/loop` in dynamic mode. Rearm the watcher after every push wave and every verdict you act on. Watcher output drives wakeups. Never add a second sleep loop." with: After opening the pull request, call `subscribe_pr_activity` for it and end the turn. GitHub pull request events (check results, reviews, comments and merge-conflict notices) wake the session, so schedule no timed check-ins and never sleep or poll. On each event, test-merge `origin/main` as above and read the status. A pull request whose diff touches only Markdown that the `pull_request` paths in `.github/workflows/ci.yml` leave out runs no CI, so no check event will come. Those paths skip `**.md` but keep `.changeset/`, the package README and CHANGELOG, and `*-body.md`. Read its status once after opening or pushing instead of waiting. When a later event or a message from the user finds the head commit of any other pull request still without a result, tell the user what is missing. Stay subscribed after reporting, so a later review or failure still wakes the session, and call `unsubscribe_pr_activity` when the pull request merges or closes, or when the user says to stop.
- **Replace** "On GitHub, stop at `READY` for one PR (single or stack mode)." with: Stop when the head commit's CI is green, or CI skips the pull request as above, `mergeable_state` is clean, and no blocking review thread is open, then report. Read all three live right before reporting, not from the last event.
