# 토큰

DTCG 파이프라인에서 생성한 카탈로그입니다. 컴포넌트는 contract 변수만 사용합니다. JSON 카탈로그 `@tounsoo/todae/tokens.json`은 각 토큰을 선언한 세트나 모디파이어도 `entry`에 적습니다. 회사 토큰 패키지는 그곳에서 토큰을 오버라이드합니다.

코드에서 프로바이더 값을 읽으려면, `useAppearance()`는 가장 가까운 ThemeProvider의 확정된 appearance(`light` 또는 `dark`)를, `useDensity()`는 가장 가까운 DensityProvider의 density를 반환합니다. 위에 프로바이더가 없으면 `light`와 `comfortable`을 반환합니다.

```tsx
function Panel() {
  const appearance = useAppearance(); // 'dark'
  const density = useDensity(); // 'compact'
  return <Text.Root>{appearance}, {density}</Text.Root>;
}

<ThemeProvider appearance="dark">
  <DensityProvider density="compact">
    <Panel />
  </DensityProvider>
</ThemeProvider>
```

## 언제 쓰나요

### ThemeProvider

**언제:** `data-appearance`로 하위 트리의 appearance(system / light / dark)를 설정합니다. 중첩된 프로바이더가 덮어쓰고, 값을 주지 않으면 바깥 프로바이더의 값을 따릅니다. `overrides`는 허용 목록에 있는 토큰 경로에만 씁니다.

**쓰지 않을 때:** 간격 밀도 → DensityProvider. 원시 CSS나 알 수 없는 토큰 키(거부됩니다).

`THEME_OVERRIDE_KEYS`는 `overrides`가 받는 토큰 경로의 목록입니다. `@tounsoo/todae`에서 import하세요. 이 목록은 raw 키, semantic 키, component 키를 잇습니다. 회사 토큰 빌드의 `overrideTypes`를 넘기지 않으면 그 목록 밖의 경로는 거부됩니다. 그 빌드는 [Todae로 디자인 시스템 만들기](/guides/build-on-todae)에 있습니다. [`themeOverrideStyle`](/utilities/theme-override-style)은 `ThemeProvider`를 렌더링하지 않고 같은 오버라이드를 `--todae-*` 커스텀 프로퍼티로 씁니다.

```ts
import { THEME_OVERRIDE_KEYS, type ThemeOverrideKey } from '@tounsoo/todae';

function listed(key: ThemeOverrideKey) {
  return THEME_OVERRIDE_KEYS.includes(key);
}
```

### DensityProvider

**언제:** `data-density`로 하위 트리의 간격 밀도(compact / comfortable / spacious)를 설정합니다. 값을 주지 않은 중첩 프로바이더는 바깥 프로바이더의 값을 따릅니다. 간격에만 씁니다.

**쓰지 않을 때:** 색상이나 라이트 / 다크 → ThemeProvider. 글자 크기 → `font.size.*` 토큰.

### useAppearance

**언제:** 이미지를 고르는 것처럼, 자체 컴포넌트가 라이트인지 다크인지 알아야 할 때.

**쓰지 않을 때:** 색상 → CSS에서 appearance를 따르는 토큰.

### useDensity

**언제:** 자체 컴포넌트가 JavaScript에서 밀도를 알아야 할 때.

**쓰지 않을 때:** 간격 → CSS에서 밀도를 따르는 토큰.

### categoryTone

**언제:** 사용자 id나 태그 이름 같은 키마다 늘 같은 카테고리 톤이 필요할 때.

**쓰지 않을 때:** 상태처럼 의미가 있는 톤 → 직접 고르세요.

## 대비

토큰 빌드는 텍스트 쌍을 WCAG 2 비율이 아니라 APCA로 측정합니다. 각 쌍은 텍스트 색상, 배경, 허용하는 최저 Lc를 지정합니다. 예를 들어 `color.bg.elevated` 위의 `color.fg.muted`는 Lc 60입니다. 선택된 행처럼 배경이 반투명한 쌍은 그 배경이 놓일 수 있는 불투명한 표면을 `over`에 나열하며, 표면마다 측정됩니다. 어느 appearance에서든 쌍이 기준에 못 미치면 빌드가 실패하고, 통과할 가장 가까운 텍스트 또는 배경 색의 명도를 알려 줍니다.

쌍은 `tokens/resolver.json`의 `$extensions["dev.todae"].contrast`에 있습니다. 시맨틱 색상의 쌍은 appearance 모디파이어에, `field.bg.default` 위의 `field.fg.placeholder`처럼 Field, Nav, OptionList, Tree의 텍스트와 그 배경의 쌍, 그리고 네 가지 `color.bg` 표면과 `popover.bg` 위의 `text.label.fg` 쌍은 contract 세트에 있습니다. 회사 토큰 패키지는 이를 상속하므로, 리브랜딩한 액센트도, 이 컴포넌트 색상도 검사됩니다. 회사는 자체 세트나 모디파이어 어디에든 같은 `fg`와 `bg`로 쌍을 나열해 최솟값을 바꿀 수 있으며, 직접 나열하지 않으면 Todae의 `over` 표면을 그대로 씁니다. 자체 토큰에 대한 쌍을 더할 수도 있습니다.

브랜드 액센트는 appearance마다 네 개의 토큰입니다. `color.accent.default`, `color.accent.hover`, `color.accent.active`, `color.on-accent`입니다. Todae의 다크 `on-accent`는 거의 흰색인 잉크 위에 놓이도록 거의 검은색이므로, 넷을 함께 설정하세요. 빌드가 검사하도록 브랜드 액센트는 회사 토큰 패키지에 넣으세요. `ThemeProvider` 오버라이드는 런타임에 적용되며, 개발 환경에서만 콘솔 경고로 검사됩니다.

## 참조와 불투명도

토큰 파일은 DTCG 2025.10을 따릅니다. 별칭은 `{ "$ref": "#/color/gray/900/$value" }`처럼 JSON Pointer `$ref`로 쓰며, `"{color.gray.900}"` 같은 중괄호 별칭은 빌드가 거부합니다. 반투명 색상은 `#/<token>/$value/components/0`부터 `2`까지로 기준 색상의 세 채널을 가리키고, 자체 `alpha`를 설정합니다.

`alpha`는 0에서 1 사이의 숫자이거나 `number` 토큰을 가리키는 `$ref`입니다. Todae의 반투명 색상은 `opacity` 스케일에서 값을 가져오며, `opacity.<n>`은 n 퍼센트입니다. 예를 들어 `"alpha": { "$ref": "#/opacity/12/$value" }`입니다. 빌드는 alpha를 그 토큰의 CSS 변수로 내보냅니다.

## 대소문자

DTCG 2025.10에는 대소문자를 위한 타입이 없어서 Todae가 `textTransform` 타입을 추가합니다. 값은 `none`, `uppercase`, `lowercase`, `capitalize` 중 하나입니다. `font.text-transform.default`은 `none`을 담고, Button, Tabs, Label, Table 헤더, Text의 label 역할은 각자 이 토큰을 가리키는 `font.text-transform` 토큰을 읽습니다. DTCG 타입만 아는 도구는 `textTransform` 토큰을 받아들이지 않을 수 있습니다. DTCG에 대소문자를 위한 표준 타입이 생기면 Todae는 그 타입으로 옮깁니다.

## 상태 톤

네 가지 톤이 상태를 나타냅니다. `info`, `success`, `warning`, `critical`입니다. 각 톤은 appearance마다 세 개의 토큰입니다. 텍스트와 아이콘에 쓰는 `color.status.<tone>.fg`, 채우기에 쓰는 `.bg`, 그리고 `.border`입니다. 빌드는 `bg` 위의 `fg`를 Lc 75로, `color.bg.surface` 위의 `fg`를 Lc 60으로 검사합니다. [Alert](/alert)는 `alert.<tone>` contract 토큰을 거쳐 이 토큰을 읽습니다. `info`는 액센트와 같은 중립적인 잉크이며, 회사는 토큰 패키지에서 여기에 색조를 줄 수 있습니다.

## 카테고리 톤

여덟 가지 톤이 태그나 사람 같은 카테고리를 구분합니다. `color.category.1`부터 `color.category.8`까지이며, 각각 appearance마다 `fg`, `bg`, `border`가 있습니다. 색조 이름이 아니라 번호를 붙였기 때문에 회사는 이름을 바꾸지 않고도 토큰 패키지에서 색조를 바꿀 수 있습니다. 빌드는 `bg` 위의 `fg`를 Lc 75로 검사합니다. [Badge](/badge), [Chip](/chip), [Avatar](/avatar)는 이 톤을 `category-1`부터 `category-8`로 받고, `categoryTone(key)`는 문자열에서 톤 하나를 고릅니다.

### CATEGORY_TONES

`CATEGORY_TONES`는 `category-1`부터 `category-8`까지 여덟 개 이름의 튜플입니다. `CategoryTone`은 그 튜플의 한 원소입니다. `categoryTone(key)`는 문자열에 해당하는 원소를 돌려줍니다. 같은 키는 서버와 브라우저에서 같은 톤을 돌려줍니다. 튜플은 `category-8`에서 끝납니다.

```tsx
import { CATEGORY_TONES, categoryTone, type CategoryTone } from '@tounsoo/todae';

const tones: readonly CategoryTone[] = CATEGORY_TONES;

<Avatar.Root label={name} tone={categoryTone(userId)} />
```

## 포커스 링

`focus.ring`, `focus.ring-width`, `focus.ring-offset`은 Todae의 포커스 링을 정합니다. `button.primary.ring.focus`나 `field.ring.focus` 같은 각 컴포넌트의 `ring.focus` 색상 토큰은 `focus.ring`을 가리키므로, 이 토큰을 바꾸면 그 링들의 색이 바뀝니다. 컴포넌트 자신의 토큰은 여전히 그 컴포넌트에서 이 값을 덮어씁니다. 직접 만든 포커스 가능한 요소에 같은 링을 그리려면 세 토큰을 읽으세요.

```css
.my-card:focus-visible {
  outline: var(--todae-focus-ring-width) solid var(--todae-focus-ring);
  outline-offset: var(--todae-focus-ring-offset);
}
```

## 모션

열리고 닫힐 때 움직이는 컴포넌트에는 모션 토큰이 네 개 있습니다. `dialog.motion.duration.enter`처럼 `motion.duration.enter`, `motion.duration.exit`, `motion.easing.enter`, `motion.easing.exit`입니다. 들어오는 곡선은 자리를 잡으며 느려지는 `cubic-bezier(0.2, 0.8, 0.2, 1)`입니다. 나가는 곡선은 떠나며 빨라지는 `cubic-bezier(0.4, 0, 1, 1)`이고, 나가는 시간은 들어오는 시간과 같거나 더 짧습니다. Dialog, Drawer, BottomSheet(`sheet`), Toast, Popover는 곡선으로 `overlay.motion.easing.enter`와 `overlay.motion.easing.exit`를 가리키므로, 이 두 토큰을 바꾸면 모든 오버레이의 타이밍이 바뀝니다. Disclosure, Nav, Tree와 Message의 액션 줄은 코어 `motion.easing.enter`와 `motion.easing.exit`를 가리킵니다. push와 pop은 각각 한 번의 슬라이드이므로 Drilldown에는 `motion.duration`이 하나 있고, Loader, Progress, Skeleton에는 반복 한 번에 쓰는 `motion.duration`이 하나 있습니다. 화면에 남아 있는 두 상태 사이를 움직이는 컨트롤에는 `motion.duration`과 `motion.easing`이 하나씩 있습니다. Switch의 thumb, Checkbox의 체크, Radio의 점은 `selection.motion.duration`과 `selection.motion.easing`을 읽고, Tabs 인디케이터는 `tabs.motion.duration`과 `tabs.motion.easing`을 읽습니다. 두 곡선 모두 코어 `motion.easing.enter`를 가리킵니다. 얼마나 움직이는지도 시간 옆에 있는 토큰입니다. `popover.motion.scale`은 Popover와 Menu가 커지기 시작하는 크기이고, `dialog.motion.offset`은 다이얼로그가 떠오르는 거리입니다.

각 컴포넌트의 들어오고 나가는 시간은 모션 역할을 가리키고, 모션 역할은 코어 `motion.duration` 단계를 가리킵니다. 역할의 `duration.enter`나 `duration.exit`를 바꾸면 그 역할의 모든 컴포넌트 타이밍이 바뀌고, 컴포넌트 하나의 토큰을 바꾸면 그 컴포넌트만 바뀝니다.

- `motion.reveal`: 제자리에서 펼쳐지는 콘텐츠입니다. Disclosure, Nav, Tree와 Message의 액션 줄이며, 들어올 때 200ms, 나갈 때 200ms입니다.
- `motion.popup`: 트리거에 붙어 있는 표면입니다. Popover, Menu와 필드 피커이며, 들어올 때 240ms, 나갈 때 200ms입니다. Tooltip도 코어 `motion.easing.enter` 곡선으로 이 시간에 맞춰 나타나며, 팁은 바로 닫히므로 나가는 시간이 없습니다.
- `motion.window`: 페이지 가운데에 뜨는 창입니다. Dialog이며, 들어올 때 280ms, 나갈 때 200ms입니다.
- `motion.panel`: 화면 가장자리에서 밀려 들어오는 패널입니다. Drawer와 BottomSheet이며, 들어올 때 280ms, 나갈 때 240ms입니다.
- `motion.notice`: 잠깐 나타나는 메시지입니다. Toast이며, 들어올 때 200ms, 나갈 때 160ms입니다.

역할에는 시간만 있습니다. Drilldown, 두 상태 사이를 움직이는 컨트롤과 BottomSheet의 `sheet.motion.duration.resize`는 코어 단계를 바로 가리키고, Loader, Progress, Skeleton은 반복 한 번의 길이를 따로 가집니다.

사용자가 동작 줄이기를 선호하면 미끄러지거나, 크기가 바뀌거나, 떠오르거나, 도는 것이 없고, 반복 애니메이션은 멈춥니다. 지금은 일부 컴포넌트가 페이드도 건너뜁니다.

## 설명

Todae의 시맨틱 토큰과 density 토큰, 각 컴포넌트의 토큰 그룹에는 무엇에 쓰는지 알려 주는 DTCG `$description`이 있습니다. 자체 설명이 없는 토큰은 같은 파일에서 자신을 감싸는 가장 가까운 그룹의 설명을 씁니다. 토큰 카탈로그(`tokens.json`)와 MCP 토큰 도구는 이를 `description`으로 돌려줍니다. appearance나 density에 따라 바뀌는 토큰은 한 컨텍스트의 파일에서 한 번만 설명하세요. 회사 토큰 패키지도 같은 방식으로 자체 토큰을 설명합니다. 회사가 어느 컨텍스트에서든 Todae 토큰에 단 설명은 Todae의 설명을 대체하고, 설명이 없는 재정의 토큰은 Todae의 설명을 그대로 씁니다.
