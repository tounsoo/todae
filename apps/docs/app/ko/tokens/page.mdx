# 토큰

DTCG 파이프라인에서 생성한 카탈로그입니다. 컴포넌트는 contract 변수만 사용합니다.

코드에서 프로바이더 값을 읽으려면, `useAppearance()`는 가장 가까운 ThemeProvider의 확정된 appearance(`light` 또는 `dark`)를, `useDensity()`는 가장 가까운 DensityProvider의 density를 반환합니다. 위에 프로바이더가 없으면 `light`와 `comfortable`을 반환합니다.

```tsx
function Panel() {
  const appearance = useAppearance(); // 'dark'
  const density = useDensity(); // 'compact'
  return <Text.Root>{appearance}, {density}</Text.Root>;
}

<ThemeProvider appearance="dark">
  <DensityProvider density="compact">
    <Panel />
  </DensityProvider>
</ThemeProvider>
```

## 언제 쓰나요

### ThemeProvider

**언제:** `data-appearance`로 하위 트리의 appearance(system / light / dark)를 설정합니다. 중첩된 프로바이더가 덮어씁니다. `overrides`는 허용 목록에 있는 토큰 경로에만 씁니다.

**쓰지 않을 때:** 간격 밀도 → DensityProvider. 원시 CSS나 알 수 없는 토큰 키(거부됩니다).

### DensityProvider

**언제:** `data-density`로 하위 트리의 간격 밀도(compact / comfortable / spacious)를 설정합니다. 간격에만 씁니다.

**쓰지 않을 때:** 색상이나 라이트 / 다크 → ThemeProvider. 글자 크기 → Text `size`.

### useAppearance

**언제:** 이미지를 고르는 것처럼, 자체 컴포넌트가 라이트인지 다크인지 알아야 할 때.

**쓰지 않을 때:** 색상 → CSS에서 appearance를 따르는 토큰.

### useDensity

**언제:** 자체 컴포넌트가 JavaScript에서 밀도를 알아야 할 때.

**쓰지 않을 때:** 간격 → CSS에서 밀도를 따르는 토큰.

### categoryTone

**언제:** 사용자 id나 태그 이름 같은 키마다 늘 같은 카테고리 톤이 필요할 때.

**쓰지 않을 때:** 상태처럼 의미가 있는 톤 → 직접 고르세요.

## 대비

토큰 빌드는 텍스트 쌍을 WCAG 2 비율이 아니라 APCA로 측정합니다. 각 쌍은 텍스트 색상, 배경, 허용하는 최저 Lc를 지정합니다. 예를 들어 `color.bg.elevated` 위의 `color.fg.muted`는 Lc 60입니다. 선택된 행처럼 배경이 반투명한 쌍은 그 배경이 놓일 수 있는 불투명한 표면을 `over`에 나열하며, 표면마다 측정됩니다. 어느 appearance에서든 쌍이 기준에 못 미치면 빌드가 실패합니다.

쌍은 `tokens/resolver.json`의 `$extensions["dev.todae"].contrast`에 있습니다. 시맨틱 색상의 쌍은 appearance 모디파이어에, `field.bg.default` 위의 `field.fg.placeholder`처럼 Field, Nav, OptionList, Tree의 텍스트와 그 배경의 쌍은 contract 세트에 있습니다. 회사 토큰 패키지는 이를 상속하므로, 리브랜딩한 액센트도, 이 컴포넌트 색상도 검사됩니다. 회사는 자체 세트나 모디파이어 어디에든 같은 `fg`와 `bg`로 쌍을 나열해 최솟값을 바꿀 수 있으며, 직접 나열하지 않으면 Todae의 `over` 표면을 그대로 씁니다. 자체 토큰에 대한 쌍을 더할 수도 있습니다.

브랜드 액센트는 appearance마다 네 개의 토큰입니다. `color.accent.default`, `color.accent.hover`, `color.accent.active`, `color.on-accent`입니다. Todae의 다크 `on-accent`는 거의 흰색인 잉크 위에 놓이도록 거의 검은색이므로, 넷을 함께 설정하세요. 빌드가 검사하도록 브랜드 액센트는 회사 토큰 패키지에 넣으세요. `ThemeProvider` 오버라이드는 런타임에 적용되며, 개발 환경에서만 콘솔 경고로 검사됩니다.

## 참조와 불투명도

토큰 파일은 DTCG 2025.10을 따릅니다. 별칭은 `{ "$ref": "#/color/gray/900/$value" }`처럼 JSON Pointer `$ref`로 쓰며, `"{color.gray.900}"` 같은 중괄호 별칭은 빌드가 거부합니다. 반투명 색상은 `#/<token>/$value/components/0`부터 `2`까지로 기준 색상의 세 채널을 가리키고, 자체 `alpha`를 설정합니다.

`alpha`는 0에서 1 사이의 숫자이거나 `number` 토큰을 가리키는 `$ref`입니다. Todae의 반투명 색상은 `opacity` 스케일에서 값을 가져오며, `opacity.<n>`은 n 퍼센트입니다. 예를 들어 `"alpha": { "$ref": "#/opacity/12/$value" }`입니다. 빌드는 alpha를 그 토큰의 CSS 변수로 내보냅니다.

## 대소문자

DTCG 2025.10에는 대소문자를 위한 타입이 없어서 Todae가 `textTransform` 타입을 추가합니다. 값은 `none`, `uppercase`, `lowercase`, `capitalize` 중 하나입니다. `font.text-transform.default`은 `none`을 담고, Button, Tabs, Label, Table 헤더는 각자 이 토큰을 가리키는 `font.text-transform` 토큰을 읽습니다. DTCG 타입만 아는 도구는 `textTransform` 토큰을 받아들이지 않을 수 있습니다. DTCG에 대소문자를 위한 표준 타입이 생기면 Todae는 그 타입으로 옮깁니다.

## 상태 톤

네 가지 톤이 상태를 나타냅니다. `info`, `success`, `warning`, `critical`입니다. 각 톤은 appearance마다 세 개의 토큰입니다. 텍스트와 아이콘에 쓰는 `color.status.<tone>.fg`, 채우기에 쓰는 `.bg`, 그리고 `.border`입니다. 빌드는 `bg` 위의 `fg`를 Lc 75로, `color.bg.surface` 위의 `fg`를 Lc 60으로 검사합니다. [Alert](/alert)는 `alert.<tone>` contract 토큰을 거쳐 이 토큰을 읽습니다. `info`는 액센트와 같은 중립적인 잉크이며, 회사는 토큰 패키지에서 여기에 색조를 줄 수 있습니다.

## 카테고리 톤

여덟 가지 톤이 태그나 사람 같은 카테고리를 구분합니다. `color.category.1`부터 `color.category.8`까지이며, 각각 appearance마다 `fg`, `bg`, `border`가 있습니다. 색조 이름이 아니라 번호를 붙였기 때문에 회사는 이름을 바꾸지 않고도 토큰 패키지에서 색조를 바꿀 수 있습니다. 빌드는 `bg` 위의 `fg`를 Lc 75로 검사합니다. [Badge](/badge), [Chip](/chip), [Avatar](/avatar)는 이 톤을 `category-1`부터 `category-8`로 받고, `categoryTone(key)`는 문자열에서 톤 하나를 고릅니다.

## 포커스 링

`focus.ring.color`, `focus.ring.width`, `focus.ring.offset`은 Todae의 포커스 링을 정합니다. `button.primary.ring.focus`나 `field.ring.focus` 같은 각 컴포넌트의 `ring.focus` 색상 토큰은 `focus.ring.color`를 가리키므로, 이 토큰을 바꾸면 그 링들의 색이 바뀝니다. 컴포넌트 자신의 토큰은 여전히 그 컴포넌트에서 이 값을 덮어씁니다. 직접 만든 포커스 가능한 요소에 같은 링을 그리려면 세 토큰을 읽으세요.

```css
.my-card:focus-visible {
  outline: var(--todae-focus-ring-width) solid var(--todae-focus-ring-color);
  outline-offset: var(--todae-focus-ring-offset);
}
```
