# Slider

`Slider.Root`는 네이티브 `<input type="range">`입니다. 화살표 키, Page Up과 Page Down, Home과 End는 브라우저가 처리하고 값도 읽어 줍니다. 슬라이더 하나는 모든 브라우저에서 `slider.fill`로 손잡이와 트랙을 직접 그립니다.

<Example of={SliderVolume} block />

Server Components는 `@tounsoo/todae/slider`에서 가져올 수 있습니다. [Fieldset](/fieldset) 안에서 `@tounsoo/todae`의 `Slider.Root`는 Fieldset의 `disabled`와 `invalid`를 따르고, 자신의 `aria-invalid`가 우선합니다. `@tounsoo/todae/slider`는 클라이언트 컴포넌트가 필요하므로 Fieldset을 읽지 않습니다. [Label](/label)로 이름을 붙이고, 정확한 숫자가 중요하면 현재 값을 근처에 텍스트로 보여 주세요. `slider.fill`과 `slider.ring.focus`로 스타일을 바꾸세요. `mode="range"`는 한 트랙에 손잡이 두 개를 둡니다. 손잡이는 다른 손잡이에 닿으면 멈춥니다.

## 범위

`mode="range"`는 한 트랙에 네이티브 range 입력 두 개를 둡니다. `startLabel`과 `endLabel`은 두 손잡이의 이름입니다. `startValueText`와 `endValueText`는 각 손잡이에 대해 스크린 리더가 숫자 대신 읽는 말입니다. `value`는 시작과 끝을 담습니다. `onValueChange`는 다음 쌍을 받습니다. 채워진 구간은 시작 손잡이부터 끝 손잡이까지입니다. `name`은 두 필드의 이름입니다. `name`을 생략하면 어느 입력도 제출하지 않습니다.

## 접근성을 지키는 조합

**Todae가 맡는 것:** 스타일입니다. 손잡이 하나는 `slider` role과 값, 최솟값, 최댓값, 위의 키를 가진 네이티브 `<input type="range">`입니다. `mode="range"`는 손잡이가 다른 손잡이에 닿으면 멈추고, 두 손잡이 사이를 채우며, 빈 트랙을 누르면 더 가까운 손잡이를 옮깁니다. 슬라이더 하나는 모든 브라우저에서 `slider.fill`로 손잡이와 트랙을 직접 그리고, focus-visible인 동안 `slider.ring.focus`로 포커스 윤곽선을 그립니다.

**직접 제공할 것:** 이름입니다. 손잡이 하나에는 `htmlFor`를 쓴 [Label](/label)이나 `aria-label`을 주세요. 손잡이 둘에는 `startLabel`과 `endLabel`을 주세요. 숫자만으로 뜻이 잘 전해지지 않으면 손잡이 하나에는 `aria-valuetext`를, 범위에는 `startValueText`와 `endValueText`를 `"40%"`나 `"Medium"`처럼 주세요. 정확한 숫자가 중요하면 현재 값을 보이는 텍스트로 보여 주고, 힌트가 있으면 `aria-describedby`로 연결하세요.

**주의할 점:** 직접 만든 `div` 슬라이더에는 role, 값 속성, 키를 하나하나 더해야 합니다. Field 안이라면 [useField](/utilities/use-field)를 보세요. 직접 쓴 `outline: none`은 포커스 링을 없앱니다.

## 언제 쓰나요

**쓸 때:** 볼륨이나 확대처럼 정확한 숫자보다 대략적인 위치가 중요한 범위 안의 값을 고를 때.

**쓰지 않을 때:** 정확한 숫자 → [Field.NumberInput](/field/number-input). 이름 붙은 몇 가지 선택지 → [Radio](/radio). 사용자가 조절하지 않는 진행 상황 → [Progress](/progress).
