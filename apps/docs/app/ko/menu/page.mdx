# Menu

동작 목록을 여는 버튼입니다. `Menu.Trigger`는 `aria-haspopup="menu"`와 `aria-expanded`를 가진 `Button.Root`입니다. `Menu.Content`는 CSS 앵커 포지셔닝으로 트리거에 고정된 비모달 팝오버 안의 `role="menu"`이며, [Popover](/popover)와 같은 표면입니다. 메뉴는 `aria-label`이나 `aria-labelledby`를 받지 않으면 트리거로 이름이 붙습니다.

## 키보드

트리거에서 Enter, Space, 클릭 또는 ArrowDown을 누르면 첫 항목에서 메뉴가 열리고, ArrowUp을 누르면 마지막 항목에서 열립니다. 세로 툴바 안에서는 위, 아래 키가 툴바의 컨트롤 사이를 움직입니다. 메뉴 안에서 Up과 Down은 이동하며 끝에서 처음으로 돌아가고, Home과 End는 끝으로 건너뛰고, 글자를 입력하면 그 글자로 시작하는 다음 항목으로 이동합니다. Enter, Space 또는 클릭으로 항목을 고릅니다. 메뉴를 닫는 항목을 고르면, 그 선택이 포커스를 다른 곳으로 옮기지 않은 한 포커스가 트리거로 돌아가고, 목록의 순서를 바꿀 때처럼 그 선택이 트리거를 페이지 안에서 옮겨도 마찬가지입니다. Escape는 메뉴를 닫고 포커스를 트리거로 돌려보냅니다. Tab은 메뉴를 닫고 포커스를 트리거 다음으로 옮깁니다(툴바 안에서는 트리거가 속한 컨트롤 묶음 다음으로). Shift+Tab은 메뉴를 닫고 트리거에 멈춥니다. 스크립트, 스크린 리더, iframe 안을 누르는 동작 등으로 포커스가 메뉴 밖 다른 곳으로 옮겨가도 메뉴가 닫힙니다. 포인터를 움직이면 그 아래 항목에 포커스가 가므로, 포인터와 키보드가 하나의 강조 표시를 함께 씁니다. 비활성 항목은 `aria-disabled`를 가지며, 메뉴의 관례대로 화살표 키 순서에 남아 있어 스크린 리더가 사용할 수 없는 항목으로 알립니다. 이 항목은 고를 수 없습니다. 비활성 항목에 마우스를 올리면 화살표 키처럼 그 항목에 포커스가 가므로, 강조 표시가 다른 항목에 남지 않습니다.

## 체크박스 항목과 라디오 항목

ARIA가 `menuitem`에 대해 정의한 대로, 항목의 자식은 보조 기술에 표현용으로만 전달됩니다. 따라서 항목 안에 링크, 입력, 버튼을 넣지 마세요(링크 섹션처럼 항목 자체는 링크가 될 수 있습니다). 그 안에서 누른 키는 그대로 두지만, 그 안을 클릭하면 항목도 선택됩니다. `Menu.CheckboxItem`은 `aria-checked`를 토글합니다. `Menu.RadioGroup`은 자식 `Menu.RadioItem`들의 값 하나를 소유합니다. 둘 다 선택한 뒤에도 열린 채로 있어 한 번에 여러 설정을 바꿀 수 있습니다. 닫으려면 `closeOnSelect`를 설정하세요. `Menu.Group`과 `Menu.RadioGroup`에는 `aria-label`이나 `aria-labelledby`가 필요합니다.

</Example>

`onOpenChange(open, reason)`은 `trigger`, `context`(`Menu.ContextTrigger`), `escape`, `outside`(밖을 누르거나 밖으로 포커스가 이동), `select`, `tab` 중 하나를 알립니다. 제어 `open`을 갱신하지 않으면 변경이 거부됩니다. 거부된 `outside`에서도 누른 동작은 그대로 전달되듯이, 거부된 `tab`에서도 포커스는 이동합니다.

## 하위 메뉴

`Menu.Submenu`는 목록 안에 목록을 둡니다. `Menu.SubmenuTrigger`는 `aria-haspopup="menu"`를 가지고 줄 끝에 셰브론이 있는 항목이며, `Menu.SubmenuContent`는 그 항목이 여는 `role="menu"`로, 트리거로 이름이 붙습니다. 하위 메뉴는 트리거의 끝 너머에서 첫 항목이 트리거와 같은 높이에 오도록 열리고, 자리가 없으면 반대쪽이나 위쪽으로 뒤집힙니다. 하위 메뉴에는 어떤 항목이든, 그룹이나 또 다른 하위 메뉴도 넣을 수 있습니다.

<Example of={MenuSubmenu} />

트리거에서 오른쪽 화살표, Enter 또는 Space를 누르면 하위 메뉴가 첫 항목에서 열립니다. 오른쪽에서 왼쪽으로 쓰는 페이지에서는 왼쪽 화살표가 엽니다. 왼쪽 화살표(오른쪽에서 왼쪽으로 쓰는 페이지에서는 오른쪽 화살표)나 Escape는 그 하위 메뉴만 닫고 포커스를 트리거로 돌려보냅니다. Up, Down, Home, End와 타입어헤드는 하위 메뉴 자신의 항목 사이에서만 움직입니다. 하위 메뉴 안에서 항목을 고르거나 Tab을 누르면, 메뉴 자체에서와 같이 메뉴 전체가 닫힙니다. 포인터가 트리거 위에 `menu.submenu.delay.show` 동안 머물면 하위 메뉴가 열리고 포커스는 트리거에 남습니다. 클릭이나 탭은 바로 엽니다. 포커스가 하위 메뉴가 놓인 메뉴의 다른 항목으로 옮겨가면 하위 메뉴가 닫힙니다.

트리거에서 하위 메뉴로 가는 길에 포인터가 다른 항목 위를 지날 수 있습니다. `menu.submenu.delay.hide` 동안, 포인터가 트리거를 떠난 지점과 하위 메뉴의 가까운 가장자리 사이의 삼각형 안에 있으면 그 항목들은 포커스를 옮기지 않으므로 하위 메뉴가 열린 채로 있습니다. 포인터가 멈추거나, 되돌아가거나, 시간이 지나면 평소처럼 그 아래 항목에 포커스가 갑니다.

`Menu.Submenu`는 `open`, `defaultOpen`, `onOpenChange(open, reason)`를 받습니다. reason은 `trigger`(트리거를 클릭하거나 키를 누름), `pointer`(포인터가 트리거 위에 머묾), `escape`, `arrow`(줄 시작 쪽 화살표 키), `parent`(포커스가 다른 항목으로 이동했거나, 하위 메뉴가 놓인 메뉴가 닫힘) 중 하나입니다.

## 링크

도움말이나 설정처럼 어딘가로 가는 항목은 링크입니다. `render`를 넘기고, 받은 props를 그대로 넘긴 링크를 반환하세요. 요소는 `role="menuitem"`과 메뉴의 키보드 동작을 그대로 가집니다. Enter, Space, 클릭은 링크를 따라가고, `onSelect`를 실행하고, 메뉴를 닫습니다. 비활성 항목은 선택할 수 없습니다. 가운데 클릭이나 브라우저의 새 탭에서 열기로도 따라가지 않도록 `href`도 빼세요.

```tsx
import NextLink from 'next/link';

<Menu.Item render={(props) => <NextLink {...props} href="/settings" />}>Settings</Menu.Item>
```

## 컨텍스트 메뉴

`Menu.ContextTrigger`는 행, 파일, 메시지 같은 영역으로, 오른쪽 클릭, Android의 길게 누르기, Shift+F10 또는 ContextMenu 키로 메뉴를 엽니다. 포인터로 열면 포인터 위치에, 키로 열면 포커스된 요소 아래에 메뉴가 열립니다. 메뉴는 `Menu.Trigger`에서 열 때처럼 뷰포트 안에 머물도록 뒤집히고, 첫 항목에서 열립니다. Escape는 메뉴가 열릴 때 포커스를 가졌던 요소에 포커스를 돌려주고, 그 요소가 사라졌거나 포커스를 받을 수 없었다면(텍스트를 오른쪽 클릭한 뒤처럼) `Menu.Trigger`에 돌려줍니다. 영역은 `div`를 렌더링합니다. 표의 행이나 목록 항목으로 만들려면 `render`를 넘기고 받은 props를 펼치세요. 메뉴가 열려 있는 동안 영역에는 `data-open`이 붙으므로, 제품은 클릭한 행을 강조할 수 있습니다.

각 영역에는 같은 `Menu.Root` 안에 보이는 `Menu.Trigger`도 두세요. 컨텍스트 메뉴는 눈에 보이지 않고, Shift+F10을 아는 사람은 적으며, Mac 키보드에는 ContextMenu 키가 없고, iOS Safari는 길게 누르기에 `contextmenu`를 보내지 않으므로, 많은 사람은 이 버튼으로 같은 메뉴에 닿습니다.

<Example of={MenuContext} />

영역 안의 텍스트 필드에서 오른쪽 클릭이나 Shift+F10을 누르면 필드의 편집 명령이 담긴 브라우저 메뉴가 그대로 열립니다. 다른 영역 안에 있는 영역이 요청을 먼저 받습니다. 열린 메뉴 안에서 오른쪽 클릭해도 그 위에 브라우저 메뉴가 열리지 않습니다.

## 아이콘

`Menu.CheckboxItem`은 선택된 동안 `check` 글리프를 보여 줍니다. [GlyphsProvider](/utilities/glyphs-provider)가 정하지 않으면 Todae의 체크 표시입니다. `Menu.SubmenuTrigger`는 줄 끝 쪽으로 돌린 `chevron` 글리프를 보여 줍니다. 아이콘만 있는 트리거에는 `Button.Icon`에 어떤 라이브러리의 아이콘도 넣을 수 있으며, 이름이 필요합니다.

```tsx
import { Check, Ellipsis } from 'lucide-react';

<GlyphsProvider glyphs={{ check: <Check /> }}>
  <Menu.Root>
    <Menu.Trigger variant="ghost" aria-label="View options">
      <Button.Icon>
        <Ellipsis />
      </Button.Icon>
    </Menu.Trigger>
    <Menu.Content>
      <Menu.CheckboxItem checked={grid} onCheckedChange={setGrid}>
        Show grid
      </Menu.CheckboxItem>
    </Menu.Content>
  </Menu.Root>
</GlyphsProvider>
```

## 접근성을 지키는 조합

**Todae가 맡는 것:** `Menu.Trigger`는 `aria-haspopup="menu"`, `aria-expanded`, `aria-controls`를 설정하고, 그 id가 `aria-labelledby`로 `role="menu"` 콘텐츠의 이름이 됩니다. 항목은 `role="menuitem"`, `menuitemcheckbox`, `menuitemradio` 중 하나를 가지며, `aria-checked`와 `aria-disabled`는 상태에 맞춰 바뀝니다. `Menu.SubmenuTrigger`는 `aria-haspopup="menu"`, `aria-expanded`, `aria-controls`를 설정하고, 하위 메뉴의 이름이 됩니다. `Menu.Group`과 `Menu.RadioGroup`은 `role="group"`이고, `Menu.Separator`는 `role="separator"`입니다. 메뉴가 열리면 포커스가 메뉴 안으로 들어가고, 위에서 설명한 키보드 모델을 따릅니다. `Menu.ContextTrigger`는 `contextmenu` 이벤트와 Shift+F10, ContextMenu 키를 처리하고, 메뉴를 포인터나 포커스된 요소 위치에 두며, 닫힐 때 포커스를 돌려줍니다. 최대 높이를 넘어 스크롤되는 메뉴와 하위 메뉴는 [ScrollArea](/scroll-area#arrows-at-a-cut-off-edge)에서처럼 잘린 가장자리에 화살표를 보여 줍니다. 포인터를 올려 두면 포커스를 옮기지 않고 스크롤하며, 화살표는 보조 기술에 드러나지 않습니다.

**직접 제공할 것:** 트리거의 이름을 주세요. 이 이름이 메뉴의 이름도 됩니다. 텍스트 자식이면 충분합니다. 아이콘만 있는 트리거에는 `aria-label`이나 `aria-labelledby`가 필요하며, 없으면 개발 환경에서 `Button.Root`가 오류를 기록합니다. `Menu.Trigger` 없이 코드나 `Menu.ContextTrigger`로 여는 메뉴에는 자체 `aria-label`이나 `aria-labelledby`가 필요하며(없으면 메뉴가 열릴 때 개발 환경에서 `Menu.Content`가 오류를 기록합니다), 컨텍스트 메뉴에는 보이는 `Menu.Trigger`도 필요하고, 모든 `Menu.Group`과 `Menu.RadioGroup`에도 타입이 요구하는 대로 하나가 필요합니다. 항목의 자식이 일반 텍스트가 아니면 타입어헤드가 찾을 수 있도록 `textValue`를 넘기세요.

```tsx
import type { ReactNode } from 'react';
import { Button, Menu } from '@tounsoo/todae';
import { Ellipsis } from 'lucide-react';

export function RowActions({ label, children }: { label: string; children: ReactNode }) {
  return (
    <Menu.Root>
      <Menu.Trigger variant="ghost" aria-label={label}>
        <Button.Icon>
          <Ellipsis />
        </Button.Icon>
      </Menu.Trigger>
      <Menu.Content>{children}</Menu.Content>
    </Menu.Root>
  );
}
```

**주의할 점:** `label` prop을 받고도 `Menu.Trigger`에 넘기지 않는 래퍼는 트리거와 메뉴 모두 이름이 없게 만듭니다. 항목 안의 링크, 입력, 버튼은 항목의 내용이 표현용이라 컨트롤로 알려지지 않습니다. 체크나 라디오 표시를 숨기고 상태를 색만으로 나타내지 마세요. `Menu.Trigger`의 `onClick`에서 `preventDefault()`를 호출하면 트리거가 메뉴를 열거나 닫지 않습니다. 동작에 닿는 길이 컨텍스트 메뉴뿐이면 안 됩니다. iOS에서 길게 누르기로는 열리지 않고, Shift+F10을 아는 사람은 적습니다. 링크나 이미지처럼 사람들이 브라우저 메뉴를 쓰는 콘텐츠 위의 컨텍스트 메뉴는 새 탭에서 열기와 이미지 저장을 가립니다. 두 단계보다 깊이 중첩한 하위 메뉴는 따라가기 어렵고 포인터로 닿기도 어렵습니다.

## 언제 쓰나요

**언제:** 행 동작이나 툴바 오버플로처럼, 버튼 하나 뒤에 있는 짧은 명령 목록이나 보기 설정. 버튼과 함께 `Menu.ContextTrigger`를 두어, 행, 파일, 메시지 위의 오른쪽 클릭이나 Shift+F10으로 같은 명령을 엽니다.

**쓰지 않을 때:** 폼의 값 고르기 → `Field.Select` 또는 Combobox 레시피. 페이지 간 이동 → 링크. 자체 컨트롤이나 텍스트가 있는 콘텐츠 → `role="dialog"`를 쓴 Popover.
