# useHotkey

`useHotkey(hotkey, handler, options)`는 페이지 어디에서든 누른 키가 `hotkey`와 일치하면 `handler`를 실행합니다. 문서에서 `keydown`을 듣고, 일치한 키의 기본 동작을 막아 브라우저 자체 단축키가 함께 실행되지 않게 합니다.

Alt+T를 누르세요. 훅은 문서에서 듣습니다. 페이지의 어디에 포커스가 있든 단축키가 실행되고, 버튼은 보조 기술에 그 단축키를 알립니다.

```tsx
import { Button, Stack, Text, useHotkey } from '@tounsoo/todae';
import { useState } from 'react';

export function SearchShortcut() {
  const [open, setOpen] = useState(false);
  const keys = ['Alt+T'];
  useHotkey(keys, () => setOpen(true));
  return (
    <Stack.Root gap="condensed" align="start">
      <Button.Root aria-keyshortcuts={keys.join(' ')} onClick={() => setOpen(true)}>
        Search
      </Button.Root>
      <Text.Root>{open ? 'Search is open' : 'Press Alt+T'}</Text.Root>
    </Stack.Root>
  );
}
```

```tsx
useHotkey(['Control+K', 'Meta+K'], () => setOpen(true));
```

단축키는 `Alt+T`나 `F8`처럼 수정 키와 키를 `+`로 이어 씁니다. 수정 키는 `Alt`, `Control`, `Meta`, `Shift`이고 `Option`, `Ctrl`, `Cmd`로도 쓸 수 있으며, 정확히 일치해야 합니다. 그래서 `Control+K`는 Ctrl+Shift+K에서 실행되지 않습니다. 글자나 숫자는 그 키가 입력하는 문자로 일치시킵니다. 한글 자판처럼 키가 라틴 글자나 숫자를 입력하지 않으면, 그 글자 자리에 있는 키로 일치시킵니다. 훅이 모르는 수정 키 이름이 든 단축키는 꺼지고, 개발 중에는 오류를 기록합니다.

훅은 다른 곳에서 이미 기본 동작을 막은 키, 입력기가 글자를 조합하는 중에 누른 키, 누르고 있어 반복되는 키를 건너뜁니다. 텍스트 필드 안에서는 기능 키나 Meta, 또는 Alt 없는 Control 조합만 실행합니다. `Shift+A`, `Escape`, 화살표 키 같은 나머지 단축키는 필드에 맡깁니다.

최신 `handler`가 실행되므로 인라인 함수도 괜찮습니다. 듣기를 멈추려면 `{ enabled: false }`를 넘기세요. [Command palette](/recipes/command-palette)가 이 훅으로 열립니다.

단축키는 그것이 대신하는 컨트롤의 `aria-keyshortcuts`로 보조 기술에 알리세요.

## 접근성을 지키는 조합

**Todae가 맡는 것:** 위에서 설명한 대로 문서에서 키를 듣고, 수정 키를 정확히 맞추고, 일치하면 브라우저의 기본 동작을 막고, 입력 키는 텍스트 필드와 입력기에 맡깁니다. 속성은 설정하지 않으며 아무것도 알리지 않습니다.

**직접 제공할 것:** 단축키가 대신하는 컨트롤에 `aria-keyshortcuts`를 주고, 단축키마다 공백으로 구분하세요. `Alt`, `Control`, `Meta`, `Shift`라는 이름은 거기서도 유효하므로 목록 하나로 둘 다 채울 수 있습니다. 별칭인 `Ctrl`, `Cmd`, `Option`은 유효하지 않습니다. 컨트롤의 툴팁이나 도움말 페이지처럼 보이는 텍스트로도 단축키를 보여 주세요.

```tsx
const keys = ['Control+K', 'Meta+K'];
useHotkey(keys, () => setOpen(true));

<Button.Root aria-keyshortcuts={keys.join(' ')} onClick={() => setOpen(true)}>
  Search
</Button.Root>
```

**주의할 점:** Shift가 있든 없든 글자, 숫자, 기호 하나로 된 단축키를 조심하세요. 텍스트 필드 밖에서는 키 한 번에 실행되므로 음성 입력이 실수로 실행할 수 있습니다. `{ enabled: false }`로 끌 방법을 주세요. 일치하면 브라우저의 기본 동작을 막으므로, `Control+F` 같은 단축키는 브라우저 자체의 찾기를 대체합니다.

## 언제 쓰나요

**언제:** 검색이나 명령 팔레트를 여는 단축키처럼 페이지 전체에서 쓰는 단축키.

**쓰지 않을 때:** 목록의 화살표 키처럼 위젯 안의 키 → 위젯 자체의 `onKeyDown`. 토스트로 포커스 옮기기 → `Toast.Region`의 `hotkey`.
