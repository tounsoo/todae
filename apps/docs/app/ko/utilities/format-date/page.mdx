# formatDate와 parseDate

`formatDate(date, { locale })`는 날짜를 로캘의 숫자로 씁니다. 예: `en-US`에서는 `10/13/2026`, `de`에서는 `13.10.2026`, `ko`에서는 `2026. 10. 13.`. `parseDate(text, { locale })`는 입력한 텍스트를 `Temporal.PlainDate`로 읽고, 날짜가 아니면 `null`을 돌려줍니다. `locale`이 없으면 둘 다 런타임의 로캘을 씁니다. [Field.DateInput](/field/date-input)은 이 둘로 텍스트를 읽고 쓰며, 직접 만든 [Field.TextInput](/field/text-input)에서도 쓸 수 있습니다.

## parseDate가 읽는 것 {/*#reading-dates*/}

숫자로 쓴 날짜는 `formatDate`가 쓰는 순서나 로캘의 `short` 날짜 스타일의 순서로 읽습니다. 예: `formatDate`가 `2026-10-13`으로 쓰는 `gsw`에서 `13.10.26`. 두 순서 모두 날짜로 읽히면 네 자리 이상의 연도는 `formatDate`의 순서로 읽고, 한두 자리 연도는 `short` 스타일이 연도를 두 자리로 쓸 때 그 스타일의 순서로 읽습니다. 글자가 있는 날짜는 `Intl.DateTimeFormat`이 로캘의 `medium`, `long`, `full` 날짜 스타일로 쓰는 대로 읽습니다. 예: `en-US`에서는 `Oct 13, 2026`, `Tuesday, October 13, 2026`.

대소문자는 상관없고, 숫자는 어느 문자 체계의 숫자여도 되며, 부분 사이는 어떤 문장 부호, 기호, 공백으로 나눠도 됩니다. 달은 `Oct`나 `October`처럼 긴 이름이든 짧은 이름이든 됩니다. 요일은 길게 쓰든 짧게 쓰든 빼든 되지만, 그 날짜의 요일이어야 합니다. `13 de octubre de 2026`의 `de`처럼 스타일의 다른 단어는 공백으로 바꿔도 됩니다. `2026-10-13`처럼 네 자리 이상의 연도로 시작하는 숫자 세 개는 연, 월, 일로 읽는데, 로캘이 연도를 앞에 두고 다른 순서로 쓰면 그 순서를 따릅니다. 연도는 로캘의 달력과 상관없이 그레고리력 연도입니다. 한두 자리 연도는 올해에 가장 가까운 그런 해로 읽으므로, 50년쯤 떨어진 날짜는 네 자리를 모두 써야 하고, 세 자리 연도는 읽지 않습니다.

## Temporal

Todae는 Temporal 폴리필을 싣지 않습니다. 둘 다 `Temporal.PlainDate`를 쓰므로, 브라우저에 Temporal이 없으면 앱이 폴리필을 불러옵니다([네이티브 플랫폼](/platform) 참고).

## 접근성을 지키는 조합

**Todae가 맡는 것:** 넘긴 `locale`로 쓴 텍스트. 넘기지 않으면 런타임의 로캘입니다.

**직접 제공할 것:** 페이지와 맞는 `locale`, 그리고 쓸 때와 읽을 때 같은 `locale`. `parseDate`가 `null`을 돌려줄 때 입력 가까이에 둘 메시지.

**주의할 점:** `locale` 없이 서버에서 렌더링하면 텍스트는 서버의 로캘로 쓰입니다. 날짜로 읽히지만 뜻한 날짜가 아닌 텍스트, 예를 들어 가장 가까운 그런 해로 읽힌 두 자리 연도. 중요할 때는 가까이에 날짜를 글로 보여 주세요.

## 언제 쓰나요

### formatDate

**언제:** 직접 만든 텍스트 입력처럼, 날짜를 로캘에 맞는 텍스트로 쓸 때.

**쓰지 않을 때:** 요일이나 월 이름이 있는 날짜 → `Intl.DateTimeFormat`.

### parseDate

**언제:** 사람이 입력한 날짜를 읽을 때.

**쓰지 않을 때:** `2026-10-13`처럼 형식이 정해진 텍스트 → `Temporal.PlainDate.from`.
