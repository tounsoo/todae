# formatDateRange와 parseDateRange

`formatDateRange(range, { locale })`는 양 끝 날을 모두 포함하는 `DateRange`인 `{ start, end }`의 두 날짜를 [formatDate](/utilities/format-date)가 쓰는 대로 쓰고, 그 사이에 로캘의 범위 구분자를 넣습니다. 예: `en-US`에서는 `10/3/2026 – 10/10/2026`, `ko`에서는 `2026. 10. 3. ~ 2026. 10. 10.`. `parseDateRange(text, { locale })`는 입력한 텍스트를 `DateRange`로 읽고, 범위가 아니면 `null`을 돌려줍니다. `locale`이 없으면 둘 다 런타임의 로캘을 씁니다. [Field.DateRangeInput](/field/date-range-input)은 이 둘로 텍스트를 읽고 씁니다.

## parseDateRange가 읽는 것 {/*#reading-ranges*/}

글자나 숫자가 아닌 문자가 이어진 곳마다, 그리고 로캘의 범위 구분자에서 텍스트를 나누고, 양쪽을 [`parseDate`](/utilities/format-date#reading-dates)로 날짜로 읽습니다. 날짜 두 개로 읽히는 나눔이 정확히 하나일 때 범위를 돌려주므로, `10/3/2026 - 10/10/2026`, `Oct 3, 2026 – Oct 10, 2026`, 그리고 `2026-10-03/2026-10-10` 같은 ISO 8601 구간을 읽습니다. `formatDateRange`가 쓰는 대로 날짜마다 연도가 있어야 하므로, `Oct 3 – Oct 10, 2026`에는 `null`을 돌려줍니다. 종료일을 먼저 쓴 범위도 달력에서 고를 때처럼 앞선 날짜를 시작일로 읽습니다.

## 접근성을 지키는 조합

**Todae가 맡는 것:** 넘긴 `locale`로 쓴 텍스트. 넘기지 않으면 런타임의 로캘입니다.

**직접 제공할 것:** 페이지와 맞는 `locale`, 그리고 쓸 때와 읽을 때 같은 `locale`. `parseDateRange`가 `null`을 돌려줄 때 입력 가까이에 둘 메시지.

**주의할 점:** `locale` 없이 서버에서 렌더링하면 텍스트는 서버의 로캘로 쓰입니다.

## 언제 쓰나요

### formatDateRange

**언제:** 직접 만든 텍스트 입력처럼, 범위를 로캘에 맞는 텍스트로 쓸 때.

**쓰지 않을 때:** `Oct 3 – 10, 2026`처럼 입력용이 아니라 읽기용인 범위 → `Intl.DateTimeFormat`의 `formatRange`.

### parseDateRange

**언제:** 사람이 입력한 범위를 읽을 때.

**쓰지 않을 때:** 폼이나 API에서 온 `2026-10-03/2026-10-10` 같은 ISO 8601 구간. `parseDateRange`도 읽지만, 그런 데이터에는 없어야 할 입력 형태까지 읽습니다 → `/`에서 나눠 각각 ISO만 받는 `Temporal.PlainDate.from`으로 읽으세요.
