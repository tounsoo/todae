# useCombobox

`useCombobox`는 Combobox의 열림 상태, 값, 입력, 하이라이트, id를 관리합니다. 외형은 컴포넌트가 담당합니다. 입력은 `Field`, 표면은 `Popover`, `BottomSheet`, `Dialog`, 목록은 `OptionList`입니다. `Combobox.*` export는 없습니다. [Combobox 레시피](/recipes/combobox)에서 단일, 다중, 시트, 비동기, 생성을 보여 줍니다.

`presentation`의 기본값은 `'auto'`이며, [useSheetPresentation](/utilities/use-sheet-presentation)을 통해 coarse 포인터나 좁은 뷰포트에서 시트를 고릅니다. 고정하려면 `popover`나 `sheet`를 강제하세요. 아래 데모는 `popover`를 강제합니다. `dialog`는 [Command palette](/recipes/command-palette)처럼 입력과 목록을 `Dialog`에 둡니다. 어느 getter가 어느 파트에 가는지는 [조합](/composition)에 나와 있습니다.

```tsx
const cb = useCombobox({ options, presentation: 'popover' });

<Field.Group>
  <Label.Root {...cb.getLabelProps()}>Framework</Label.Root>
  <Field.Root {...cb.getAnchorProps()}>
    <Field.TextInput {...cb.getInputProps()} />
  </Field.Root>
</Field.Group>
<Popover.Root {...cb.getPopoverProps()}>
  <OptionList.Root {...cb.getListboxProps()}>
    {cb.items.map((item) => (
      <OptionList.Option key={item.id} {...cb.getOptionProps(item)} />
    ))}
  </OptionList.Root>
</Popover.Root>
```

## 접근성을 지키는 조합

**Todae가 맡는 것:** `getInputProps()`와 `getChipInputProps()`는 입력을 `role="combobox"`로 만들고 `aria-expanded`, `aria-controls`(listbox id), `aria-autocomplete="list"`, `autoComplete="off"`를 주며, 열려 있는 동안 `aria-activedescendant`로 활성 옵션을 가리켜 포커스가 입력에 머물게 합니다. ArrowDown, ArrowUp, Home, End는 목록을 열고 비활성 옵션을 건너뛰며 활성 옵션을 옮깁니다. 목록이 열려 있으면 Enter는 선택하거나 생성합니다. 현재 쿼리의 목록을 아직 불러오는 중이거나 그 생성이 진행 중이면 Enter는 아무것도 하지 않으며, 폼에도 전달되지 않습니다. 목록이 닫혀 있거나, 열려 있어도 고를 행과 생성 행이 없으면 Enter를 폼에 맡기고 아무것도 생성하지 않습니다. `Field.ChipInput`에 준 다른 `commitKeys`는 목록이 열려 있을 때 같은 방식으로 확정합니다. 닫혀 있을 때는 입력에 텍스트가 있을 때만 그 문자가 입력되지 않게 막습니다. Escape와 Tab은 닫습니다. 목록이 닫혀 있을 때 Escape는 값이 없는 단일 모드에서 입력한 텍스트를 지웁니다. 지울 것이 없으면 페이지에 맡기므로, 필드를 감싼 대화 상자가 닫힙니다. 한국어 단어를 끝내는 Enter처럼 IME 조합에 속한 키는 입력에 맡깁니다. 비동기 `onCreate`가 진행 중인 동안에는 `creating`이 true이고 그 레이블의 생성 행이 `aria-disabled`인 채로 활성 행으로 남으므로, Enter나 클릭을 다시 해도 다시 실행하거나 다른 행을 고르지 않고 아무것도 하지 않습니다. 다른 레이블의 생성은 함께 실행됩니다. 레이블은 대소문자를 구분하지 않고 비교합니다. `onCreate`가 던지거나 거부한 이유는 `createError`에 들어가며, 불러오기 전용인 `error`에는 들어가지 않습니다. 텍스트가 여전히 그 레이블을 가리킬 때만 들어갑니다. 다음 텍스트 변경, 고르기, 제거, `clear()`, 생성, 또는 목록이 열리는 것이 이를 지웁니다. `reject()`나 `throw null`처럼 거짓 같은 값으로 실패하면 그 값을 `cause`로 담은 `Error`가 `createError`나 `error`에 들어가므로 여전히 실패로 읽힙니다. `onValueChange`, `onInputValueChange`, `onOpenChange`가 던진 오류는 생성 실패가 아니라 여러분의 것입니다. 나머지 콜백은 그대로 실행되고, 그 오류는 이벤트 핸들러 밖으로, 비동기 생성 뒤라면 `reportError`를 거쳐 잡히지 않은 오류로, `reportError`가 없는 곳에서는 처리되지 않은 거부로 이어집니다. 단일 모드의 고르기, `clear()`, `reset()`, 언마운트는 진행 중인 생성을 모두 버리며, 필드를 숨기는 `Activity`도 마찬가지입니다. `creating`은 바로 false가 되고, 버려진 생성은 결과를 반영하지도 실패를 알리지도 않습니다. 그 프로미스가 끝날 때까지는 진행 중으로 남으므로 그 레이블로 `onCreate`가 다시 실행되지 않습니다. 그 레이블을 Enter나 생성 행으로 다시 실행하면 그 생성을 되살리며, 끝나면 버려진 적이 없었던 것처럼 반영합니다. `onCreate`는 레이블 다음에 `AbortSignal`을 받습니다. 이 신호는 필드가 언마운트되거나 `Activity`가 필드를 숨길 때 중단되며, 고르기, `clear()`, `reset()`에서는 중단되지 않습니다. 신호가 중단된 생성은 되살리지 않으므로, 그 레이블을 다시 실행하면 `onCreate`를 다시 호출합니다. 단일 모드에서는 생성이 끝날 때 입력이 그 레이블이고 값이 생성을 시작하거나 되살릴 때와 같을 때만 반영하므로, 다른 텍스트나 다른 값이 이깁니다. 다중 모드에서는 버려지지 않은 한, 그사이 사용자가 무엇을 했든 만든 칩이 추가됩니다. `getLabelProps()`는 필드의 Label에 listbox가 이름을 가져오는 id와, 입력을 가리키는 `htmlFor`를 줍니다. 시트나 대화 상자에서는 `htmlFor`가 트리거를 가리킵니다. `getListboxProps()`는 `OptionList.Root`에 listbox id, `tabIndex={-1}`, 그리고 `ids.label`을 가리키는 `aria-labelledby`를 주며, 넘긴 `aria-label`이나 `aria-labelledby`가 있으면 그것을 대신 씁니다. 개발 모드에서는 열린 목록에 이름이 없으면 훅이 경고합니다. `getTriggerProps(props)`는 `aria-haspopup="dialog"`, `aria-expanded`, `aria-controls`를 설정하며, 이 값과 `id`는 넘긴 값보다 우선합니다. `aria-label`이나 `aria-labelledby`를 넘기지 않으면 필드의 Label과 트리거 자신의 텍스트로 트리거 이름을 붙여 "City San Francisco"처럼 읽힙니다. Label이 렌더링되지 않으면 트리거 자신의 텍스트가 이름이 됩니다. 다른 props와 ref는 합치고, 넘긴 `onClick`을 먼저 실행합니다. 거기서 `preventDefault()`를 호출하면 열고 닫지 않습니다. `reset()`은 기본 값, 텍스트, 열림 상태를 변경 콜백을 거쳐 `reset` 이유로 되돌리며, 바뀌지 않는 것은 건너뜁니다. `defaultValue`, `defaultInputValue`, `defaultOpen` props를 보내고, 설정되지 않았다면 빈 값, 빈 텍스트, 닫힌 목록을 보내므로, 제어하는 쪽은 처음 렌더링한 값이 아니라 이것을 받습니다. 팝오버에서 Escape를 누르면 포커스가 입력으로 돌아가고, 시트는 닫힐 때 포커스를 트리거로 돌려줍니다.

**직접 제공할 것:** 입력의 이름을 주세요. 필드의 [Label](/label)에 `getLabelProps()`를 스프레드하고, 시트나 대화 상자 안에서는 검색 필드의 `Field.Root`에 `aria-label`을 주세요. listbox에도 이름이 필요합니다. 필드의 Label에 `getLabelProps()`를 스프레드하거나, 보이는 레이블이 없으면 `getListboxProps()`에 `aria-label`을 넘기세요. 생성 실패 텍스트는 `createError`를 보고 생성 행 옆에 보여 주세요. 트리거 텍스트는 값을 보여 주세요. 필요하면 시트나 대화 상자에 더 구체적인 이름을 주세요. `getSheetProps()`와 `getDialogProps()`는 `options` 문자열(기본값 "Options")을 쓰며, 스프레드 뒤의 `aria-label`이 이를 바꿉니다. 상태 텍스트도 제공하세요. 훅은 `loading`, `error`, `creating`, `createError`, `isEmpty`를 알려 주지만 아무것도 렌더링하거나 읽어 주지 않습니다.

**주의할 점:** 비어 있거나 로딩 중일 때 `OptionList.Root`를 마운트 해제하면 `aria-controls`가 아무것도 가리키지 않습니다. 대신 `hidden`을 지정하세요. 스프레드 뒤에 직접 `onKeyDown`, `onFocus`, `onBlur`를 주면 훅의 핸들러를 대체합니다. 트리거의 핸들러는 대신 `getTriggerProps({ … })`에 넘기세요. `getTriggerProps`에 인라인 콜백 `ref`를 넘기면 렌더링마다 다시 연결됩니다. 옵션 안에 버튼이나 링크를 넣지 마세요.

## 언제 쓰나요

**언제:** 검색 가능한 선택 — 타입어헤드 + 목록. 훅이 열림/값/입력을 관리하고, [레시피](/recipes/combobox)처럼 Field + Popover/BottomSheet + OptionList가 외형을 담당합니다. coarse/좁은 화면에서는 자동으로 시트.

**쓰지 않을 때:** 페이지에 고정된 배타적 선택 → Radio. 검색 없는 목록 → [usePopover](/utilities/use-popover) + OptionList만. 동작 메뉴 → [Menu](/menu). `Combobox.*` 외형 export(금지).
