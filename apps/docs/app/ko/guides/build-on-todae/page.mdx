# Todae로 디자인 시스템 만들기

Todae 위에 만드는 회사 디자인 시스템은 세 가지로 이루어집니다. Todae 토큰 위에 쌓는 토큰 패키지, 몇 가지 TypeScript 선언, 그리고 Todae 파트를 감싸는 얇은 래퍼입니다. 포크하는 것은 없습니다. Todae가 업데이트되면 회사는 토큰을 다시 빌드하고 래퍼는 그대로 유지합니다.

## 토큰 레이어

Todae의 토큰은 `tokens/resolver.json`이 구동하는 DTCG 2025.10 파일입니다. 각 세트와 모디파이어는 `$extensions["dev.todae"].layer`에 자신의 레이어를 적고, 토큰은 더 낮은 레이어의 토큰이나, 같은 레이어에서는 같은 세트나 모디파이어 또는 `resolutionOrder`에서 더 앞에 있는 세트나 모디파이어의 토큰만 참조할 수 있습니다. core처럼 첫 번째 범위 모디파이어보다 앞에 있는 세트의 토큰은 `:root`에만 선언되므로, 리터럴 값을 가지며 아무것도 참조하지 않습니다.

- `core`: `color.gray.900`, `space.4` 같은 원시 스케일.
- `appearance`: `color.fg.muted`, `color.accent.default` 같은 라이트와 다크용 시맨틱 색상.
- `density`: `space.control.x` 같은 밀도별 간격.
- `contract`: `button.bg.default`, `field.border.focus` 같은 컴포넌트가 읽는 값.

컴포넌트는 contract 토큰만 읽습니다. 리브랜딩은 appearance 레이어를 바꾸고, contract는 그 변경을 따라갑니다.

CSS에서 모든 토큰은 경로를 이름으로 하는 커스텀 프로퍼티입니다. `color.accent.default`는 `--todae-color-accent-default`입니다. Todae의 토큰은 `todae.base` 캐스케이드 레이어에 있습니다.

## 회사 리졸버

회사는 토큰 파일 옆에 자체 리졸버를 작성합니다. 세트를 추가하고, Todae의 모디파이어에 컨텍스트를 추가하고, 그 안의 토큰을 교체할 수 있습니다. Todae의 리졸버가 먼저 로드되므로 모든 참조는 Todae의 토큰을 가리킬 수 있습니다.

```json
{
  "$schema": "https://www.designtokens.org/schemas/2025.10/resolver.json",
  "name": "acme",
  "version": "2025.10",
  "sets": {
    "brand": {
      "sources": [{ "$ref": "./brand.json" }],
      "$extensions": { "dev.todae": { "layer": "contract" } }
    }
  },
  "modifiers": {
    "appearance": {
      "contexts": {
        "light": [{ "$ref": "./appearance/light.json" }],
        "dark": [{ "$ref": "./appearance/dark.json" }]
      },
      "$extensions": {
        "dev.todae": { "layer": "appearance", "attribute": "data-appearance", "root": true, "colorScheme": true }
      }
    }
  },
  "resolutionOrder": [{ "$ref": "#/modifiers/appearance" }, { "$ref": "#/sets/brand" }]
}
```

참조는 병합된 토큰 트리를 가리키는 JSON Pointer입니다.

```json
{
  "brand": {
    "ink": { "$type": "color", "$value": { "$ref": "#/color/gray/900/$value" } }
  }
}
```

Todae 자체 토큰을 바꾸려면, 그 토큰을 선언한 Todae의 세트나 모디파이어와 같은 이름의 세트나 모디파이어에 다시 선언하고, `$extensions`에 그 항목의 `layer`와 배치 설정을 그대로 적습니다. 회사의 값이 이기고, 나머지는 Todae의 것으로 남습니다.

- `core`: `color.gray.*`, `radius.*`, `font.family.sans`, `font.weight.*` 같은 원시 스케일.
- `appearance`, `density`: 시맨틱 색상과 간격. `light`, `dark` 또는 밀도 이름의 컨텍스트에 둡니다.
- `focus`: `focus.ring.*`.
- `button`: `button.base.*`. 모든 버튼 변형이 공유하는 형태입니다.
- `buttonVariant`: `button.<variant>.*`. 변형 이름의 컨텍스트에 둡니다.
- `contract`: `card.shadow`, `field.radius` 같은 나머지 컴포넌트 토큰.

```json
"sets": {
  "core": {
    "sources": [{ "$ref": "./core.json" }],
    "$extensions": { "dev.todae": { "layer": "core" } }
  },
  "button": {
    "sources": [{ "$ref": "./button.json" }],
    "$extensions": { "dev.todae": { "layer": "contract" } }
  }
}
```

토큰 카탈로그 `@tounsoo/todae/tokens.json`의 각 행은 `entry`에 그 항목을 적고(버튼 변형이면 `"primary"` 같은 `context` 필드도 있습니다), 잘못된 항목에 둔 토큰은 빌드를 실패시키며 메시지가 그 토큰이 속한 항목을 알려 줍니다. core 토큰은 `:root`에 한 번만 선언되고 아무것도 참조하지 않으므로, 리터럴 값으로만 바꾸세요.

`@tounsoo/todae`를 설치한 프로젝트에서 `todae-tokens` CLI로 빌드합니다. `--no`는 npx가 npm에서 같은 이름의 패키지를 받아 오지 않게 합니다.

```sh
npx --no todae-tokens build --resolver ./tokens/resolver.json
```

세 개의 파일을 씁니다.

- `todae-theme.css`: 회사 토큰만 담으며, Todae 다음에 오는 `todae.theme` 레이어에 있습니다.
- `tokens.catalog.json`: Todae와 회사의 토큰을 함께 담습니다.
- `todae-theme.types.ts`: `ThemeProvider`에 쓸 회사 키의 `THEME_OVERRIDE_TYPES`.

`--css`, `--catalog`, `--types`로 출력 경로를 바꿉니다. CI에서는 `--check`를 더해 출력이 없거나 오래되었을 때 실패하게 합니다. 같은 빌드를 함수로도 쓸 수 있습니다. `@tounsoo/todae/tokens-builder`의 `buildCompanyTokens`입니다.

빌드는 Todae 자체 빌드가 하는 모든 검사를 실행합니다. 경로 형식, 참조 순환, 레이어 순서, 라이트와 다크의 대응, APCA 대비입니다. Todae 리졸버의 대비 쌍은 회사 색상에도 적용되므로, 대비 기준을 통과하지 못하는 브랜드 액센트는 빌드를 실패시킵니다. 대비 쌍과 최솟값을 바꾸는 방법은 [토큰](/tokens)의 Contrast 섹션을 보세요.

검사가 실패하면 메시지가 무엇을 바꿀지 알려 줍니다. 잘못 둔 토큰이 속할 항목, 없거나 순서가 맞지 않는 참조를 읽는 토큰, 한 컨텍스트에는 있고 다른 컨텍스트에는 없는 토큰, 그리고 최솟값에 못 미치는 대비 쌍에는 빌드가 검사하는 다른 쌍을 실패시키지 않고 통과하는 가장 가까운 텍스트 또는 배경의 명도를, 리터럴 값을 가진 토큰에 맞춰 알려 줍니다. 그 토큰이 Todae 자체 파일에 있으면, 회사 리졸버의 같은 세트나 모디파이어에서 오버라이드하라고 알려 줍니다. 한 번의 변경이 여러 쌍을 고칠 수 있으므로, 하나를 적용한 뒤 다시 빌드하세요.

```sh
contrast: 1 pair(s) fail APCA
  "color.on-accent" on "color.accent.active" in appearance "dark" is Lc 56.2, below 60
    fix: set the lightness of "color.accent.active" (modifier "appearance" context "dark") from 0.74 to 0.764, for Lc 60.1
```

CSS는 Todae 다음에 로드합니다.

```ts
import '@tounsoo/todae/todae.css';
import './todae-theme.css';
```

앱에 Tailwind처럼 자체 캐스케이드 레이어가 있다면 대신 CSS 진입 파일에서 레이어 문 다음에 두 파일을 import하세요. [CSS 레이어](/guides/css-layers)를 보세요.

## 한 페이지에 여러 테마

테마 CSS는 페이지 전체의 Todae 토큰을 바꿉니다. 하위 브랜드처럼 페이지 일부에 다른 테마를 주려면 그 테마를 `--scope`와 CSS 선택자로 빌드합니다.

```sh
npx --no todae-tokens build --resolver ./tokens/business.resolver.json --scope .business --css ./business-theme.css
```

그러면 CSS는 Todae와 회사의 모든 토큰을 `@scope (.business)` 안에 담으므로, 선택자에 맞는 요소와 그 안의 모든 것이 테마를 받고 바깥은 받지 않습니다. 위처럼 Todae의 CSS 다음에 로드하고, 페이지에 필요한 만큼 스코프 테마를 로드하세요. 스코프는 테마 전체를 담으므로, 다른 스코프 안의 스코프에는 바깥 테마의 토큰도, 바깥 `ThemeProvider`의 `overrides`도 보이지 않고, 어느 파일이 나중에 로드되든 더 가까운 스코프가 이깁니다. 그래서 스코프 파일은 Todae 자체의 토큰 CSS보다 큽니다. gzip으로 약 17 KB이고, Todae는 11 KB입니다.

선택자에 맞는 요소는 `ThemeProvider`처럼 `data-appearance`나 `data-density`를 지정한 가장 가까운 바깥 요소의 appearance와 density를 따르고, 그런 요소가 없으면 기본값을 씁니다. 스코프 안이나 스코프 요소 자체의 `ThemeProvider`는 다른 곳에서처럼 이를 바꿉니다.

```tsx
<ThemeProvider appearance="dark" className="business">
  …
</ThemeProvider>
```

스코프 테마는 다른 회사 테마가 아니라 Todae의 토큰 위에 빌드됩니다. 하위 브랜드라면 [`examples/fernway`](https://github.com/tounsoo/todae/tree/main/examples/fernway)의 `business.resolver.json`처럼, 하위 브랜드의 리졸버에 주 브랜드의 토큰 파일을 나열하고 그 뒤에 바뀌는 파일을 두세요.

## 오버라이드: CSS 또는 ThemeProvider

페이지 일부의 토큰을 바꾸는 방법은 두 가지입니다.

**CSS**는 빌드 시점에 알 수 있는 모든 것에 씁니다. 가능하면 회사 토큰 패키지에 넣어 빌드가 검사하게 하세요. 그렇지 않으면 `todae.theme` 레이어에 쓰거나, 모든 레이어를 이기는 레이어 밖에 씁니다.

```css
@layer todae.theme {
  [data-appearance='dark'] {
    --todae-color-accent-default: oklch(0.78 0.13 25);
  }
  @media (prefers-color-scheme: dark) {
    [data-appearance='system'] {
      --todae-color-accent-default: oklch(0.78 0.13 25);
    }
  }
}
```

`ThemeProvider appearance="system"`은 `data-appearance="system"`을 렌더링하고, 이 값은 CSS에서 사용자의 색 구성표를 따릅니다. 그래서 직접 쓴 `light`나 `dark` 오버라이드에는 맞는 `prefers-color-scheme` 쿼리 안의 `system` 규칙도 필요합니다. 회사 토큰 빌드는 이 규칙을 만들어 줍니다.

`data-appearance`나 `data-density`가 있는 요소에 설정하세요. contract 토큰은 그 요소에서 계산되므로, 하위 요소에 둔 오버라이드는 contract 토큰에 닿지 않습니다. 이런 요소마다 contract 토큰을 다시 계산하므로, CSS로 contract 토큰을 오버라이드할 때는 가장 바깥 요소만이 아니라 그 요소 모두에 맞게 설정하세요.

**`ThemeProvider`의 `overrides`**는 고객의 브랜드 색상처럼 런타임에 들어오는 값에 씁니다. 토큰 경로와 DTCG 값을 받아 자신의 요소에 커스텀 프로퍼티로 설정하고, 모르는 경로와 잘못된 값은 거부합니다. 개발 환경에서는 오류를 던지고 프로덕션에서는 건너뜁니다. 개발 환경에서는 렌더링된 위치에서 Todae resolver의 APCA 대비 쌍도 검사하고, 오버라이드 때문에 Todae의 최솟값에 못 미치게 된 쌍을 `console.warn`으로 알려 줍니다. 프로덕션에서는 대비 검사를 하지 않습니다.

```tsx
<ThemeProvider overrides={{ 'color.accent.default': { colorSpace: 'oklch', components: [0.5, 0.15, 150] } }}>
  …
</ThemeProvider>
```

`@tounsoo/todae`가 export하는 `THEME_OVERRIDE_KEYS`는 `overrides`가 받는 경로의 목록입니다. raw 키, semantic 키, component 키를 잇습니다. 도구가 `overrides`가 받는 경로를 알아야 할 때 이 목록을 읽으세요. [토큰](/tokens) 페이지가 `ThemeProvider` 옆에 같은 목록을 보여 줍니다. 프로바이더 없이 커스텀 프로퍼티가 필요하면 같은 값으로 [`themeOverrideStyle`](/utilities/theme-override-style)을 호출하세요.

`appearance`가 없는 `ThemeProvider`는 바깥 프로바이더의 appearance를 따르고, 가장 바깥 프로바이더의 기본값은 `system`입니다. 그래서 오버라이드만 설정하는 중첩 프로바이더는 페이지의 라이트나 다크를 그대로 유지합니다. 프로바이더마다 appearance 토큰을 다시 선언하므로, 바깥 프로바이더가 `color.accent.default` 같은 appearance 토큰을 오버라이드해도 중첩 프로바이더 안에는 닿지 않습니다. 그 프로바이더에서 다시 설정하세요. `card.shadow` 같은 컴포넌트 토큰의 오버라이드는 그대로 이어집니다. 오버라이드는 그것을 설정한 프로바이더의 모든 appearance에 적용됩니다. 라이트와 다크에 다른 값을 주려면, 프로바이더 안의 컴포넌트에서 `useAppearance()`로 고르세요. `system`에서는 페이지가 하이드레이션될 때까지 서버가 라이트 값을 렌더링하므로, 미리 알 수 있는 값은 라이트와 다크 컨텍스트를 둔 회사 토큰 패키지에 넣으세요.

```tsx
const PARTNER_ACCENT = {
  light: { colorSpace: 'oklch', components: [0.45, 0.12, 50] },
  dark: { colorSpace: 'oklch', components: [0.8, 0.1, 50] },
} as const;

function PartnerTheme({ children }: { children: React.ReactNode }) {
  return <ThemeProvider overrides={{ 'color.accent.default': PARTNER_ACCENT[useAppearance()] }}>{children}</ThemeProvider>;
}
```

회사 토큰은 Todae가 알지 못하므로, 생성된 타입을 넘겨 허용합니다.

```tsx
import { THEME_OVERRIDE_TYPES } from './todae-theme.types';

<ThemeProvider
  overrideTypes={THEME_OVERRIDE_TYPES}
  overrides={{ 'brand.ink': { colorSpace: 'oklch', components: [0.3, 0.05, 25] } }}
>
  …
</ThemeProvider>
```

그러면 TypeScript가 `brand.*` 키를 받아들이면서도 철자가 틀린 키는 여전히 거부합니다.

## 실제 예제

Todae 저장소의 [`examples/fernway`](https://github.com/tounsoo/todae/tree/main/examples/fernway)는 가상의 회사를 위해 토큰만으로 Todae의 테마를 만듭니다. Todae의 회색, 모서리 반경, 글꼴과 액센트를 바꾸고, 버튼 변형과 자체 토큰을 추가하고, 파트너의 색상을 런타임에 설정합니다.

## 변형이나 밀도 추가하기

버튼 변형과 밀도는 모디파이어 컨텍스트이므로, 회사는 리졸버에서 추가합니다.

버튼 변형은 Todae와 같은 토큰 구조를 가진 `buttonVariant` 컨텍스트입니다. `default`, `hover`, `active`, `focus`, `disabled` 각각의 `bg`, `fg`, `border`, 그리고 `ring.focus`와 `shadow`입니다. 빌드가 그 구조를 검사하도록 `button` 규칙을 켜세요.

```json
"buttonVariant": {
  "contexts": { "outline": [{ "$ref": "./button.outline.json" }] },
  "$extensions": {
    "dev.todae": { "layer": "contract", "rules": ["button"], "attribute": "data-button-variant", "alias": true }
  }
}
```

밀도는 간격 토큰만 설정하는 `density` 컨텍스트입니다.

```json
"density": {
  "contexts": { "roomy": [{ "$ref": "./density/roomy.json" }] },
  "$extensions": { "dev.todae": { "layer": "density", "rules": ["density-space"], "attribute": "data-density", "root": true } }
}
```

그다음 TypeScript에 새 이름을 알려 줍니다.

```ts
declare module '@tounsoo/todae' {
  interface ButtonVariants {
    outline: true;
  }
  interface Densities {
    roomy: true;
  }
}
```

이제 `<Button.Root variant="outline">`과 `<DensityProvider density="roomy">`가 타입 검사를 통과하고 새 토큰을 사용합니다.

## 컴포넌트 감싸기

회사 기본값을 고정하거나 회사용 prop을 더하려면 파트를 감싸세요. 모든 파트는 네이티브 속성과 ref를 전달하므로, 나머지 props를 펼치고 `ref`를 넘겨 주세요.

```tsx
import { Button, type ButtonRootProps } from '@tounsoo/todae';

export function AcmeButton({ variant = 'outline', ...props }: ButtonRootProps) {
  return <Button.Root {...props} variant={variant} />;
}
```

부모는 컴포넌트 타입으로 자식을 찾지 않으므로 감싼 자식도 동작합니다. `OptionList.Option`은 컨텍스트로 목록에 등록되므로 감싼 옵션도 선택과 탐색이 됩니다. `Button.Root`는 `Button.Icon`이 렌더링하는 data 속성으로 아이콘을 찾으므로, `Button.Icon`을 렌더링하는 래퍼도 버튼의 아이콘으로 인식됩니다.

```tsx
function AcmeOption({ className, ...props }: OptionListOptionProps) {
  return <OptionList.Option {...props} className={['acme-option', className].filter(Boolean).join(' ')} />;
}

<OptionList.Root aria-label="Size" value={size} onValueChange={setSize}>

```

먼저 토큰으로 스타일을 바꾸세요. 파트에 클래스를 붙이는 것은 레이아웃에는 괜찮지만, 토큰으로 설정한 색상과 간격은 appearance와 density를 따르고 클래스는 그렇지 않습니다.
