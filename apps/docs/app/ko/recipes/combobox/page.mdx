# Combobox

패키지 네임스페이스가 아니라 레시피입니다. [useCombobox](/utilities/use-combobox)가 열림 상태, 값, 입력, 하이라이트, id를 맡습니다. 외형은 컴포넌트가 맡습니다. `Combobox.*` export는 없습니다. 루트 하나에는 인터랙티브 역할 하나만 둡니다.

## 표시 방식

`useCombobox({ presentation: 'auto' })`는 [useSheetPresentation](/utilities/use-sheet-presentation)을 통해 거친 포인터나 좁은 뷰포트에서는 시트를, 그 밖에는 팝오버를 고릅니다. 서버와 첫 페인트에서는 항상 팝오버입니다. 문서 스크린샷이 고정되어야 할 때는 `popover`나 `sheet`를 강제하세요.

목록이 열린 동안 표시 방식이 바뀌면 훅은 `blur`로 닫습니다.

배지는 [useSheetPresentation](/utilities/use-sheet-presentation)이 여기서 고른 값을 보여 줍니다. `isSheet`는 `isTouch`가 아닙니다.

## Popover · 단일

형제 `Label.Root` + `Field.Root` id. 입력이 combobox입니다. 목록은 `Popover.Root` 안에 있습니다.

```tsx
import { ChevronDown } from 'lucide-react';

const cb = useCombobox({ options, presentation: 'popover' });

<Field.Group>
  <Label.Root htmlFor={cb.ids.input}>Framework</Label.Root>
  <Field.Root {...cb.getAnchorProps()}>
    <Field.TextInput {...cb.getInputProps()} />
    <Field.Icon>
      <ChevronDown />
    </Field.Icon>
  </Field.Root>
</Field.Group>
<Popover.Root {...cb.getPopoverProps()}>
  <OptionList.Root {...cb.getListboxProps()}>
    {cb.items.map((item) => (
      <OptionList.Option key={item.id} {...cb.getOptionProps(item)} />
    ))}
  </OptionList.Root>
</Popover.Root>
```

## 시트

닫힌 컨트롤은 `Button.Root`입니다. 검색 Field는 시트 안에 있습니다. `inputValue`와 목록은 팝오버와 같습니다.

```tsx
const cb = useCombobox({ options, presentation: 'sheet' });
const labelId = useId();
const selected = options.find((option) => option.value === cb.value)?.label ?? 'Choose';

<Field.Group>
  <Label.Root id={labelId} htmlFor={cb.ids.trigger}>
    City
  </Label.Root>
  <Button.Root {...cb.getTriggerProps()} aria-labelledby={`${labelId} ${cb.ids.trigger}`}>
    {selected}
  </Button.Root>
</Field.Group>
<BottomSheet.Root {...cb.getSheetProps()}>
  <Field.Root id={cb.ids.input} aria-label="Search">
    <Field.TextInput {...cb.getInputProps()} />
  </Field.Root>
  <OptionList.Root {...cb.getListboxProps()}>…</OptionList.Root>
</BottomSheet.Root>
```

## 자동

훅은 하나입니다. 트리는 표시 방식에 따라 바뀝니다. 고정된 화면이 필요하면 `presentation`을 강제하세요.

## 비동기

`loadOptions(query, signal)`이 옵션을 불러옵니다. 새 쿼리는 이전 컨트롤러를 중단하고 오래된 결과를 버립니다. 훅은 `loading`이 true인 동안 이전 목록을 유지합니다. 디바운스, 로딩, 다시 시도 외형은 레시피에 둡니다. 훅은 디바운스하지 않습니다.

`fail`을 입력하면 오류 행을 볼 수 있습니다.

```tsx
const cb = useCombobox({
  loadOptions: (query, signal) => fetchPackages(query, { signal }),
  presentation: 'popover',
});

<Popover.Root {...cb.getPopoverProps()}>
  <Text.Root role="status">{cb.loading ? 'Loading…' : cb.error ? 'Couldn’t load options.' : ''}</Text.Root>
  {cb.error && !cb.loading ? (
    <Button.Root variant="ghost" onClick={cb.retry}>
      Retry
    </Button.Root>
  ) : null}
  <OptionList.Root {...cb.getListboxProps()} hidden={cb.loading || cb.error != null}>
    …
  </OptionList.Root>
</Popover.Root>
```

## 빈 결과와 생성

일치하는 항목이 없으면 상태 행을 렌더링합니다. `allowCreate`는 쿼리와 대소문자 구분 없이 일치하는 레이블이 없을 때 같은 `OptionList`에 `Create "{query}"` 옵션 하나를 더합니다. 클릭하거나 Enter를 누르면 확정됩니다. 단일 선택은 선택하고 닫습니다. 다중 선택은 칩을 더하고 열린 채로 둡니다. `onCreate`는 정규화된 값을 반환할 수 있으며, 목록이 선택된 상태로 보여 줄 수 있도록 새 옵션을 `options`에 추가해야 합니다.

## 일치 항목 강조

[useHighlight](/utilities/use-highlight)는 옵션의 마크업을 바꾸지 않고 각 옵션에서 query를 표시합니다. 훅의 `query`(입력에 선택한 레이블이 보이는 동안은 비어 있음)를 넘기고, `ref`를 목록에 두고, `::highlight(search)`로 그 이름에 스타일을 주세요.

```tsx
const found = useHighlight({ name: 'search', query: cb.query });

<OptionList.Root ref={found.ref} {...cb.getListboxProps()}>…</OptionList.Root>
```

## 조합 규칙

- 형제 [Label](/label) + `Field.Root` id. `Field.Label`은 없습니다.
- `getAnchorProps` 옆에 [usePopover](/utilities/use-popover)의 `getTriggerProps`를 펼치지 마세요. 이중 연결은 QA 실패입니다.
- OptionList가 오버레이 목록입니다. 같은 값에 Radio나 Checkbox를 함께 렌더링하지 마세요.
- combobox를 Field에 내장하지 마세요. `Combobox.*` 외형을 export하지 마세요.
- 시트 트리거는 `aria-haspopup="dialog"`를 씁니다. 팝오버의 Field 외형에는 `aria-haspopup`이 없습니다.

## 접근성을 지키는 조합

**Todae가 맡는 것:** [useCombobox](/utilities/use-combobox)는 입력을 `role="combobox"`로 만들어 `aria-controls`로 listbox를, `aria-activedescendant`로 활성 옵션을 가리키게 하고, 화살표 키, Home, End, Enter, Escape, Tab을 처리합니다. `OptionList`는 `role="listbox"`와 `aria-selected`, `aria-disabled`가 있는 `role="option"` 행을 렌더링하며, 다중 모드에서는 `aria-multiselectable`을 줍니다. `Popover`와 `BottomSheet`는 Escape로 닫히고 포커스를 돌려줍니다. 다중 모드에서 `Field.ChipInput`은 각 칩의 제거 버튼에 이름을 붙입니다.

**직접 제공할 것:** 레이블을 주세요. `htmlFor={cb.ids.input}`인 [Label](/label)을 쓰거나, 시트 안의 `Field.Root`에 `aria-label`을 주세요. 시트 모드에서는 트리거의 이름이 필드와 현재 값을 말해야 합니다. 로딩, 오류, 빈 결과 텍스트는 `role="status"` 요소에 두세요. 방금 나타난 영역의 텍스트는 늘 읽히지는 않으므로, 그 요소는 마운트된 채로 두고 텍스트만 바꾸세요. Retry는 비동기 데모처럼 실제 버튼이어야 합니다.

**주의할 점:** 비어 있거나 로딩 중일 때 `OptionList.Root`를 마운트 해제하지 마세요. `aria-controls`가 계속 가리키도록 `hidden`을 지정하세요. getter 스프레드 뒤에 직접 `onKeyDown`, `onFocus`, `onBlur`를 주면 훅의 핸들러를 대체합니다. 일치 항목 강조만으로 알리지 마세요. 강조는 시각적일 뿐입니다.
