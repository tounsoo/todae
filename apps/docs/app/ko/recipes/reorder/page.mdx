# Reorder

패키지 네임스페이스가 아니라 레시피입니다. 순서 있는 목록의 각 행에 Move to top, Move up, Move down, Move to bottom이 든 [Menu](/menu)를 두고, 새 위치는 [`useAnnouncer`](/utilities/use-announcer)로 알립니다. 끌기가 필요 없으므로 키보드, 화면 낭독기 또는 두 번의 탭으로 행을 옮길 수 있습니다. 목록에 무엇이 들고 순서를 어디에 저장할지는 제품이 정합니다. `Reorder.*` export는 없습니다.

## 이동 메뉴

순서가 핵심이므로 행을 `ol`에 넣고, 각 행에 그 행의 이름을 붙인 `Menu.Trigger`를 둡니다. 첫 행의 Move up처럼 그 행이 할 수 없는 이동에는 `disabled`를 줍니다. 메뉴 항목은 이를 `aria-disabled`로 그리므로, 항목이 화살표 키 순서에 남고 사용할 수 없다고 읽혀 모든 행의 메뉴가 같은 네 항목을 유지합니다. 각 행의 key는 인덱스가 아니라 항목의 id로 주세요. 그래야 행의 메뉴가 행과 함께 옮겨지고, 포커스가 옮겨진 행으로 돌아옵니다. 예제는 네 이동을 목적지와 함께 나열하고, 목적지가 행의 원래 자리이거나 목록 밖이면 그 이동을 사용할 수 없게 합니다.

```tsx
import { Button, Menu, Stack, Text, useAnnouncer } from '@tounsoo/todae';
import { ArrowUpDown } from 'lucide-react';
import { useId } from 'react';

function moveItem<T>(list: readonly T[], from: number, to: number): T[] {
  const next = [...list];
  const [item] = next.splice(from, 1);
  next.splice(to, 0, item!);
  return next;
}

export function PinnedChannels({
  channels,
  onReorder,
}: {
  channels: readonly { id: string; name: string }[];
  onReorder: (channels: { id: string; name: string }[]) => void;
}) {
  const announce = useAnnouncer();
  const labelId = useId();
  const last = channels.length - 1;

  const move = (from: number, to: number) => {
    onReorder(moveItem(channels, from, to));
    announce(`${channels[from]!.name} moved to position ${to + 1} of ${channels.length}`);
  };

  return (
    <>
      <Text.Root id={labelId} size="label">
        Pinned channels
      </Text.Root>
      <Stack.Root as="ol" gap="none" aria-labelledby={labelId}>
        {channels.map((channel, index) => {
          const moves = [
            ['Move to top', 0],
            ['Move up', index - 1],
            ['Move down', index + 1],
            ['Move to bottom', last],
          ] as const;
          return (
            <li key={channel.id}>
              <Stack.Root direction="row" align="center" justify="between">
                <Text.Root>{channel.name}</Text.Root>
                <Menu.Root>
                  <Menu.Trigger variant="ghost" aria-label={`Move ${channel.name}`}>
                    <Button.Icon>
                      <ArrowUpDown />
                    </Button.Icon>
                  </Menu.Trigger>
                  <Menu.Content>
                    {moves.map(([label, to]) => (
                      <Menu.Item
                        key={label}
                        disabled={to === index || to < 0 || to > last}
                        onSelect={() => move(index, to)}
                      >
                        {label}
                      </Menu.Item>
                    ))}
                  </Menu.Content>
                </Menu.Root>
              </Stack.Root>
            </li>
          );
        })}
      </Stack.Root>
    </>
  );
}
```

메뉴가 닫히면 포커스는 행과 함께 옮겨진 트리거로 돌아가고, 트리거가 화면 밖에 있으면 브라우저가 화면 안으로 스크롤합니다. 알림은 행이 어디로 갔는지 말해 줍니다. 알림이 없으면 목록을 다시 읽어야 알 수 있습니다.

## 순서 저장

예제는 이동을 고르는 즉시 목록을 바꿉니다. 제품이 새 순서를 저장하다 실패하면, 목록을 되돌리고 [Toast](/toast)나 [Alert](/alert)로 알려 주세요. 알림은 이미 행이 옮겨졌다고 말했기 때문입니다. React는 한 번의 렌더에서 옮기는 포커스된 요소의 포커스를 유지하므로, 행을 되돌려도 트리거의 포커스가 남습니다.

## 끌기

이 레시피에는 끌기가 없습니다. 끌기를 더한다면 메뉴는 남겨 두세요. WCAG 2.2 SC 2.5.7은 끌지 않고 단일 포인터로 행을 옮기는 방법을, SC 2.1.1은 키보드로 옮기는 방법을 요구하는데, HTML drag and drop은 키보드 방법을 주지 않습니다.

## 접근성을 지키는 조합

**Todae가 맡는 것:** `Menu`는 트리거에 `aria-haspopup`과 `aria-expanded`를 주고, 포커스를 메뉴 안으로 옮겨 화살표 키로 이동하게 하며, `disabled` 항목을 `aria-disabled`로 읽히게 하고, 항목을 고르면 포커스를 트리거로 돌려줍니다. `useAnnouncer`는 메시지를 live region에 씁니다.

**직접 제공할 것:** 이름이 있는 `ol`. 어느 행을 옮기는지 말하는 각 행 트리거의 이름. 그 행이 할 수 없는 이동에 주는 `disabled`. 항목의 id로 만든 key. 행의 이름과 새 위치를 담아 제품의 언어로 쓴 알림.

**주의할 점:** 인덱스로 key를 주는 것. 옮겨진 행이 있던 자리에 새로 온 행의 트리거가 포커스를 받습니다. 그 행이 할 수 없는 이동을 사용할 수 없다고 표시하지 않고 빼는 것. 메뉴가 행마다 달라집니다. 알리지 않는 이동, 또는 위치만 말하고 행은 말하지 않는 알림. 끌기만으로 행을 옮기게 하는 것. 이동을 알린 뒤 저장이 실패하는 것. 행이 되돌아간 것도 알리세요.
