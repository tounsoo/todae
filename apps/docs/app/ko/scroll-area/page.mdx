# ScrollArea

`ScrollArea.Root`는 스크롤되면서 안에 든 요소의 포커스 링을 온전히 지키는 `div`입니다. 스크롤 컨테이너는 패딩 상자 밖으로 나간 것을 모두 잘라 내므로, 가장자리에 있는 컨트롤의 링이 잘립니다. `ScrollArea.Root`는 링의 너비와 오프셋만큼 자신에게 패딩을 주고 같은 크기의 음수 마진으로 되돌려, 그 여백이 없을 때와 같은 공간을 차지합니다. 같은 값을 스크롤 패딩으로도 설정하므로, 포커스가 컨트롤의 링 전체를 화면 안으로 스크롤합니다.

<Example>
  <ScrollAreaLinks />
</Example>

```tsx
<nav aria-label="Guide sections">
  <ScrollArea.Root style={{ blockSize: '9rem' }}>
    <ul>{/* links */}</ul>
  </ScrollArea.Root>
</nav>
```

`axis`는 스크롤할 방향을 고르며 기본값은 `block`이고, 다른 방향은 잘라 냅니다. 높이나 너비는 다른 `div`처럼 주면 되고, 콘텐츠 상자의 크기가 됩니다. 서버용 엔트리가 없으므로 Server Component에서는 클라이언트 컴포넌트 안에서 렌더링하세요.

## 컨트롤이 없는 콘텐츠의 Tab 정지점

콘텐츠가 넘치는데 안에 포커스를 받을 요소가 없으면 키보드로는 나머지에 닿을 수 없습니다. 그래서 이때는 `region` 역할로 Tab 정지점이 되고, 화살표 키로 스크롤됩니다. `aria-label`이나 `aria-labelledby`로 이름을 붙이세요. 이름 없이 정지점이 되면 개발 중에 경고합니다. 자신의 링은 `scroll.ring.focus`로 가장자리 안쪽에 그립니다.

<Example>
  <ScrollAreaText />
</Example>

```tsx
<ScrollArea.Root aria-label="Release notes" style={{ blockSize: '7rem' }}>
  <Text>…</Text>
</ScrollArea.Root>
```

`focusable`은 정지점을 어느 쪽으로든 정합니다. `true`는 안에 컨트롤이 있어도 넘치는 동안 정지점을 두고, `false`는 정지점을 두지 않습니다. 포커스가 이미 스크롤해 주는 링크 목록에 씁니다.

## 접근성을 지키는 조합

**Todae가 맡는 것:** 모든 가장자리에 포커스 링을 위한 여백을 두고, 포커스가 링 전체를 보이게 하도록 스크롤 패딩을 줍니다. 콘텐츠가 넘치고 포커스를 받을 요소가 없는 동안 `region` 역할의 Tab 정지점이 되며, 포커스가 있는 동안에는 크기가 바뀌어도 포커스를 잃지 않도록 유지하고, 콘텐츠가 들어맞으면 없앱니다. 자신의 포커스 링은 가장자리 안쪽에 그립니다.

**직접 제공할 것:** Tab 정지점이 될 수 있을 때는 `aria-label`이나 `aria-labelledby`로 이름을 주세요. 스크롤이 생기도록 높이나 너비를 주세요.

**주의할 점:** `ScrollArea.Root` 자체에 준 패딩은 링 여백을 대신해 버립니다. 패딩은 안쪽 요소에 주세요. 뷰포트나 `overflow: hidden`인 부모처럼 잘라 내는 가장자리에 붙은 영역에서는 음수 마진이 링 여백을 그 가장자리 밖으로 밀어냅니다. 그런 곳에서는 `margin: 0`을 주면 여백이 안에 남습니다.

## 언제 쓰나요

**언제:** 사이드바, 패널 안의 목록, 옆으로 스크롤되는 카드 줄처럼 따로 스크롤되는 영역.

**쓰지 않을 때:** 페이지 자체가 스크롤됨 → 스크롤 영역 없이 그대로 두세요. 스크롤 대신 줄을 접어야 하는 콘텐츠 → [ChipList](/chip-list)나 [Field](/field)의 `maxRows`. 시트의 본문 → 이미 스크롤되고 같은 여백을 두는 [BottomSheet](/bottomsheet)의 `BottomSheet.Body`.
