# Stack

`gap`은 네 단계 중 하나를 고릅니다. `condensed`, `normal`, `spacious`는 `stack.gap-condensed`, `stack.gap`, `stack.gap-spacious` 토큰에서 오므로 밀도를 따릅니다. `none`은 간격이 없습니다. 기본값은 `normal`입니다.

Server Components는 `@omsoo.design/todae/stack`에서 가져올 수 있습니다. 이 엔트리에는 `'use client'`도 훅도 없습니다. 메인 `@omsoo.design/todae` 엔트리는 클라이언트 모듈입니다.

## 정렬과 줄바꿈

`align`은 교차 축을, `justify`는 주 축을 정합니다. `between`은 첫 항목과 마지막 항목을 양 끝으로 밀어냅니다. `wrap`은 행이 가득 차면 항목이 다음 줄로 넘어가게 합니다.

## 접근성을 지키는 조합

**Todae가 맡는 것:** 레이아웃만 맡습니다. `Stack.Root`은 `as`로 다른 요소를 고르지 않으면 role이 없는 `div`를 렌더링합니다. `ul`이나 `ol`로 렌더링하면 글머리표와 들여쓰기를 없애고 `role="list"`를 설정합니다. 그렇지 않으면 Safari가 글머리표 없는 목록의 목록 의미를 버리기 때문입니다. `direction`은 `row`나 `column`이고 뒤집히지 않으며, `justify`와 `align`은 그 순서 안에서만 항목을 옮기므로, 항목은 DOM 순서대로 보이고 읽는 순서와 Tab 순서가 화면에 그려진 순서를 따릅니다. 나머지 prop은 `ref`, `role`, `aria-*`까지 모두 해당 요소에 전달되며, 직접 넘긴 `role`은 목록 role을 대체합니다.

**직접 제공할 것:** 의미를 정하세요. 한 대상에 작용하고 함께 쓸 이름이 필요한 버튼에는 `role="group"`과 `aria-label`을 줍니다. [Button.Group](/button)은 `role="group"`을 직접 설정합니다. 화살표 키로 오가는 하나의 Tab 정지점이어야 하는 도구 행은 `Stack.Root`이 아니라 [Toolbar](/toolbar)입니다. 목록인 항목은 `as="ul"`이나 `as="ol"` 안에 두고, 각 자식을 `li`로 만드세요. `nav`는 탐색 랜드마크이므로, 한 페이지에 여러 개가 있으면 각각 `aria-label`을 주세요. `section`은 이름이 있을 때만 영역 랜드마크가 됩니다.

**주의할 점:** `className`이나 `style`로 `row-reverse`, `column-reverse`, `order`를 설정하면 항목은 화면에서만 옮겨지고, 읽는 순서와 Tab 순서는 그대로입니다. 주 버튼을 마지막에 보이려면 DOM에서도 마지막에 두세요.

## 언제 쓰나요

**언제:** 간격 단계 중 하나로 간격을 둔 flex 행이나 열. 필드나 버튼 사이의 간격, 링크 목록, 양 끝에 항목이 있는 머리글 행.

**쓰지 않을 때:** 레이블과 컨트롤 사이 간격 → `Field.Group`(`field.label.gap`). 간격 단계에 없는 값 → 직접 작성한 CSS. 붙어 있는 버튼 행 → Button.Group.
