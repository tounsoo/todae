# MCP 서버

Todae는 `https://todae.omsoo.design/api/mcp`에서 Model Context Protocol(MCP) 서버를 운영합니다. 여기에 연결한 AI 에이전트는 Todae의 컴포넌트와 토큰을 찾아보고, 회사의 토큰 파일을 `todae-tokens build`와 같은 빌드로 검사하고, Todae 위에 만드는 디자인 시스템의 시작 파일을 작성할 수 있습니다. Streamable HTTP로 통신하며 로그인이나 설치가 필요 없습니다.

## 연결하기

### Claude Code

프로젝트 폴더에서 서버를 추가합니다.

```sh
claude mcp add --transport http todae https://todae.omsoo.design/api/mcp
```

`--scope project`를 붙이면 프로젝트의 `.mcp.json`에 저장되어, 저장소에서 작업하는 모든 사람이 함께 씁니다.

```json
{
  "mcpServers": {
    "todae": { "type": "http", "url": "https://todae.omsoo.design/api/mcp" }
  }
}
```

### Claude Desktop과 claude.ai

**Settings**에서 **Connectors**를 열고 **Add custom connector**를 고른 뒤, URL에 `https://todae.omsoo.design/api/mcp`를 입력합니다.

### Cursor

프로젝트의 `.cursor/mcp.json`에, 또는 모든 프로젝트에서 쓰려면 `~/.cursor/mcp.json`에 서버를 추가합니다.

```json
{
  "mcpServers": {
    "todae": { "url": "https://todae.omsoo.design/api/mcp" }
  }
}
```

### VS Code

프로젝트의 `.vscode/mcp.json`에 서버를 추가합니다.

```json
{
  "servers": {
    "todae": { "type": "http", "url": "https://todae.omsoo.design/api/mcp" }
  }
}
```

### 다른 클라이언트

Streamable HTTP를 지원하는 클라이언트에는 URL을 그대로 넣습니다. stdio로 로컬 서버만 실행하는 클라이언트는 `mcp-remote` 같은 브리지를 거쳐 연결할 수 있습니다.

```json
{
  "mcpServers": {
    "todae": { "command": "npx", "args": ["-y", "mcp-remote", "https://todae.omsoo.design/api/mcp"] }
  }
}
```

## 도구

컴포넌트:

- `list_components`: 모든 컴포넌트와 파트, 그리고 각각의 설명과 문서 페이지.
- `get_component`: 컴포넌트나 파트 하나와 그 props, 파트.
- `when_to_use`: 컴포넌트 문서 페이지의 "When to use" 섹션. 이 섹션이 없는 페이지는 `status: "missing"`을 돌려주며, 서버가 내용을 직접 지어내지 않습니다.

토큰:

- `list_tokens`: Todae 카탈로그의 토큰과 각각의 `$type`, 레이어, 컨텍스트, CSS 사용자 정의 속성, CSS 값. `color.accent` 같은 경로 접두사나 레이어로 거를 수 있습니다.
- `get_token`: 토큰 하나의 컨텍스트별 값(`light`, `dark` 등)과, 그 토큰을 값에서 읽는 토큰들.
- `get_contrast_pairs`: 테마가 맞춰야 하는 APCA 쌍. 쌍마다 최소 Lc와 Todae 기본 테마에서 잰 값을 함께 줍니다.

디자인 시스템 만들기:

- `build_tokens`: 회사 토큰 패키지에 `todae-tokens build`를 실행합니다. 리졸버 기준 상대 경로로 파일을 넘기며, 그중에 `resolver.json`이 있어야 합니다. 테마 CSS, `THEME_OVERRIDE_TYPES` 모듈, 모든 쌍의 대비를 돌려주거나, 빌드 오류를 돌려줍니다.
- `scaffold_design_system`: 회사 리졸버와 토큰 파일을 작성합니다. `name`을 받고, 선택적으로 바꿀 appearance 색(light와 dark의 OKLCH 채널), `secondary`를 복사해 시작하는 새 버튼 variant, `comfortable`을 복사해 시작하는 새 density를 받습니다. 새 variant와 density 이름을 선언하는 `src/todae.d.ts`도 작성하고, 토큰 파일을 빌드한 뒤 빌드 결과와 함께 돌려줍니다.
- `get_guide`: Todae 위에 만드는 방법을 다룬 문서 페이지의 소스: `build-on-todae`, `tokens`, `css-layers`, `composition`, `platform`, `mcp`.

## 에이전트와 디자인 시스템 만들기

원하는 디자인 시스템을 에이전트에게 요청합니다. 예를 들면 다음과 같습니다.

> Using the todae MCP, start a design system called acme on Todae. Make the accent a deep red in light and dark, add an outline button variant, and fix any contrast pairs the build reports. Save the files in this repository.

이 도구들을 가진 에이전트는 `get_guide`로 [Todae로 디자인 시스템 만들기](/guides/build-on-todae)를 읽고, `list_tokens`로 바꿀 토큰을 찾고, `scaffold_design_system`으로 파일을 작성한 다음, 파일을 고칠 때마다 빌드가 통과할 때까지 `build_tokens`로 검사할 수 있습니다. 파일은 에이전트가 저장합니다. 서버는 여러분의 컴퓨터에 아무것도 쓰지 않습니다.

그다음 프로젝트에서 `todae-tokens` CLI로 파일을 빌드하고, [Todae로 디자인 시스템 만들기](/guides/build-on-todae)에 나온 대로 Todae의 CSS 다음에 CSS를 불러옵니다.

## 제한

`build_tokens`와 `scaffold_design_system`은 토큰 파일을 서버의 임시 폴더에 쓰고, 호출이 끝나면 그 폴더를 지웁니다. `build_tokens`는 파일을 최대 64개, 모두 합쳐 512 KB까지 받습니다.

컴포넌트 도구와 가이드 도구는 영어 문서 페이지를 읽으므로, 그 내용은 영어입니다.
