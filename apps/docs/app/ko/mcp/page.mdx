# MCP 서버

Todae는 `https://todae.omsoo.design/api/mcp`에서 Model Context Protocol(MCP) 서버를 운영합니다. 여기에 연결한 AI 에이전트는 Todae의 컴포넌트, 레시피, 토큰을 찾아보고, 두 버전 사이에 무엇이 바뀌었는지 확인하고, 회사의 토큰 파일을 `todae-tokens build`와 같은 빌드로 검사하고, Todae 위에 만드는 디자인 시스템의 시작 파일을 작성할 수 있습니다. Streamable HTTP로 통신하며 로그인이나 설치가 필요 없습니다. 이 서버는 npm에 올라간 `@tounsoo/todae`의 최신 버전을 설명하고 그 버전을 자기 버전으로 알려 주므로, `main`의 변경은 다음 릴리스와 함께 반영됩니다.

## 연결하기

### Claude Code

프로젝트 폴더에서 서버를 추가합니다.

```sh
claude mcp add --transport http todae https://todae.omsoo.design/api/mcp
```

`--scope project`를 붙이면 프로젝트의 `.mcp.json`에 저장되어, 저장소에서 작업하는 모든 사람이 함께 씁니다.

```json
{
  "mcpServers": {
    "todae": { "type": "http", "url": "https://todae.omsoo.design/api/mcp" }
  }
}
```

### Claude Desktop과 claude.ai

**Settings**에서 **Connectors**를 열고 **Add custom connector**를 고른 뒤, URL에 `https://todae.omsoo.design/api/mcp`를 입력합니다.

### Cursor

프로젝트의 `.cursor/mcp.json`에, 또는 모든 프로젝트에서 쓰려면 `~/.cursor/mcp.json`에 서버를 추가합니다.

```json
{
  "mcpServers": {
    "todae": { "url": "https://todae.omsoo.design/api/mcp" }
  }
}
```

### VS Code

프로젝트의 `.vscode/mcp.json`에 서버를 추가합니다.

```json
{
  "servers": {
    "todae": { "type": "http", "url": "https://todae.omsoo.design/api/mcp" }
  }
}
```

### 다른 클라이언트

Streamable HTTP를 지원하는 클라이언트에는 URL을 그대로 넣습니다. stdio로 로컬 서버만 실행하는 클라이언트는 `mcp-remote` 같은 브리지를 거쳐 연결할 수 있습니다.

```json
{
  "mcpServers": {
    "todae": { "command": "npx", "args": ["-y", "mcp-remote", "https://todae.omsoo.design/api/mcp"] }
  }
}
```

## 순서대로 읽기

slug를 모르는 에이전트는 검색한 다음 한 섹션을 읽고, 그다음 예제를 엽니다.

1. `search_docs`에 할 일을 평범한 말로 넘깁니다. 영어와 한국어 모두 찾습니다. 각 결과에는 `recipes/scheduler#dragging` 같은 `ref`, 종류, 짧은 발췌, 그리고 다음 호출의 비용인 `tokens`가 있습니다. 비용은 그 호출이 돌려주는 JSON의 길이를 4로 나눈 값입니다. 실제 o200k 토크나이저는 영어에서 그 값의 약 1.00배에서 1.12배이고, 한국어에서 약 1.18배에서 1.76배이므로, 같은 글자 수의 한국어 페이지가 영어보다 더 듭니다.
2. 그 `ref`로 `get_docs_page`를 호출합니다. 결과가 prop, 컴포넌트, 훅이면 `get_component`를 호출합니다. 4,000토큰을 넘는 페이지는 본문 대신 개요와 도입부를 돌려주고, 섹션마다 토큰 수를 붙입니다. `section`을 넘기거나 `#anchor`를 그대로 두면 그 섹션만 읽습니다. `locale: "ko"`나 `ko/`로 시작하는 slug는 한국어 페이지를 읽습니다.
3. 예제 스텁에 적힌 페이지 slug와 파일 이름으로 `get_example`을 호출합니다. `startLine`과 `endLine`으로 범위를 고릅니다. 코드는 줄 번호와 함께 돌아옵니다. 긴 파일은 일부와 다음 호출에 쓸 `cursor.startLine`을 돌려줍니다.

페이지 도구에 `includeCode: true`를 넘기면 예제 소스가 본문에 들어갑니다. 응답은 40,000자를 넘지 않습니다. 넘치면 도구는 개요나 다음 조각을 가리키는 커서를 돌려주며, 잘렸다고 알리지 않은 채 결과를 자르지 않습니다.

## 도구

검색:

- `search_docs`: 페이지, 섹션, 컴포넌트, prop, 훅, 레시피, 예제, 토큰을 순위로 찾습니다. slug를 모를 때 가장 먼저 호출합니다.
- `get_example`: 스텁이 가리키는 예제 파일 하나를 줄 번호와 함께 돌려줍니다. `startLine`과 `endLine`은 선택입니다.

컴포넌트:

- `list_components`: 모든 컴포넌트, 파트, 훅, 헬퍼와 각각의 설명, 파트, 문서 페이지, 그리고 그 페이지에 해당 항목만의 "When to use" 내용이 있는지를 나타내는 `hasWhenToUse`. 페이지 전체의 내용만 있는 항목은 `scope: "page"`와 `hasWhenToUse: false`를 가지며, `when_to_use`는 그 항목에 페이지 전체의 내용을 돌려줍니다.
- `get_component`: 컴포넌트나 파트 하나와 그 props, 파트.
- `when_to_use`: 컴포넌트 문서 페이지의 "When to use"와 "When not to use" 섹션을 `whenToUse`와 `whenNotToUse`로 돌려줍니다. `scope: "page"`는 그 내용이 파트 자신의 것이 아니라 페이지 전체의 섹션임을 뜻합니다. 내용이 없는 페이지는 `note`와 함께 `status: "missing"`을, 문서 페이지가 없는 이름은 `status: "no-docs-page"`를 돌려주며, 서버가 내용을 직접 지어내지 않습니다.
- `get_docs_page`: 페이지 하나, 또는 이름에 `#anchor`가 있거나 `section`을 넘기면 그 섹션. 이름은 대소문자, 공백, 붙임표를 무시하고 찾고, 모르는 이름은 가까운 검색 결과와 함께 돌아옵니다. `locale: "ko"`는 한국어 페이지를 읽습니다. 4,000토큰을 넘는 페이지는 페이지 전체 대신 개요를 돌려줍니다. 예제마다 파일 이름, 보여주는 내용, 줄 수, 토큰 비용이 적힌 스텁이 붙습니다. `includeCode: true`는 결과가 한도 안에 들 때 소스를 본문에 넣습니다.

레시피:

- `list_recipes`: 모든 레시피와 그 요약, 코드가 쓰는 export. 레시피는 데이터 테이블이나 위저드 같은 제품 흐름에 맞춰 Todae의 export를 엮는 문서 속 코드입니다.
- `get_recipe`: `data-table` 같은 이름이나 제목으로 찾는 레시피 하나. `get_docs_page`와 같이 섹션, 로캘, 예제 스텁을 받고, 페이지가 길면 개요를 돌려줍니다.

토큰:

- `list_tokens`: Todae 카탈로그의 토큰과 각각의 타입, 레이어, 컨텍스트, 그 토큰을 선언한 세트나 모디파이어, CSS 사용자 정의 속성, CSS 값, 설명. `color.accent` 같은 경로 접두사나 레이어로 거를 수 있습니다.
- `get_token`: 토큰 하나의 용도, 그 토큰을 선언한 세트나 모디파이어, 컨텍스트별 값(`light`, `dark` 등)과, 그 토큰을 값에서 읽는 토큰들.
- `get_contrast_pairs`: Todae의 APCA 쌍. 쌍마다 최소 Lc와 Todae 기본 테마에서 잰 값을 함께 줍니다. 회사 토큰 패키지는 이 쌍을 물려받으며, 쌍의 최소값을 바꾸거나 쌍을 추가할 수 있습니다.

디자인 시스템 만들기:

- `build_tokens`: 회사 토큰 패키지에 `todae-tokens build`를 실행합니다. `.json` 파일마다 토큰 폴더 안의 경로로 넘기고, 리졸버가 `resolver.json`이 아니면 `resolver`로 그 경로를 알려 줍니다. CSS 선택자인 `scope`는 `--scope`처럼 페이지 일부에 쓸 테마를 빌드합니다. 테마 CSS와 `THEME_OVERRIDE_TYPES` 모듈을 돌려주거나, 기준에 못 미치는 대비 쌍을 나열한 빌드 오류를 돌려줍니다.
- `scaffold_design_system`: 회사 리졸버와 토큰 파일을 작성합니다. `name`을 받고, 선택적으로 바꿀 appearance 색(light와 dark의 OKLCH 채널), `secondary`를 복사해 시작하는 새 버튼 variant, `comfortable`을 복사해 시작하는 새 density를 받습니다. 토큰 파일은 `tokens` 폴더 안의 경로로, `build_tokens`가 받는 모양 그대로 돌려주고, 새 variant와 density 이름을 선언하는 `src/todae.d.ts`, 토큰 파일을 빌드한 결과도 함께 돌려줍니다. 응답이 40,000자를 넘으면 파일을 하나씩 돌려줍니다. 다음 파일은 `cursor.offset`을, 한 파일이 이어지면 `cursor.char`를 넘깁니다.
- `get_guide`: Todae 위에 만드는 방법을 다룬 페이지입니다. `get-started`, `build-on-todae`, `tokens`, `css-layers`, `composition`, `platform`, `mcp` 중 하나이며, `get_docs_page`와 같이 `section`과 `locale`을 받습니다.

업그레이드:

- `get_changes`: 설치된 버전(예: `0.2.0`)인 `from` 이후부터 `to`까지, `to`를 생략하면 최신 릴리스까지 각 릴리스의 변경 기록 항목. 릴리스는 오래된 것부터 나오고, 릴리스마다 호환성을 깨는 변경을 나머지와 따로 줍니다. 1.0 전에는 마이너 릴리스가 호환성을 깨는 릴리스입니다.

## 에이전트와 디자인 시스템 만들기

원하는 디자인 시스템을 에이전트에게 요청합니다. 예를 들면 다음과 같습니다.

> todae MCP로 Todae 위에 acme라는 디자인 시스템을 시작해 줘. light와 dark 모두 강조색을 짙은 빨강으로 하고, outline 버튼 variant를 추가하고, 빌드가 알려 주는 대비 쌍을 고쳐 줘. 파일은 이 저장소에 저장해 줘.

이 도구들을 가진 에이전트는 `get_guide`로 [Todae로 디자인 시스템 만들기](/guides/build-on-todae)를 읽고, `list_tokens`로 바꿀 토큰을 찾고, `scaffold_design_system`으로 파일을 작성한 다음, 파일을 고칠 때마다 빌드가 통과할 때까지 `build_tokens`로 검사할 수 있습니다. 파일은 에이전트가 저장합니다. 서버는 여러분의 컴퓨터에 아무것도 쓰지 않습니다.

그다음 프로젝트에서 `todae-tokens` CLI로 파일을 빌드하고, [Todae로 디자인 시스템 만들기](/guides/build-on-todae)에 나온 대로 Todae의 CSS 다음에 CSS를 불러옵니다.

## 에이전트와 업그레이드하기

에이전트에게 업그레이드를 요청하세요. 예를 들어:

> todae MCP로 이 저장소의 @tounsoo/todae를 최신 버전으로 올리고, 호환성을 깨는 변경에 맞게 코드를 고쳐 줘.

에이전트는 `node_modules/@tounsoo/todae/package.json`이나 lockfile에서 설치된 버전을 찾고(내 `package.json`의 `^0.2.0` 같은 범위가 아니라), 그 버전으로 `get_changes`를 호출한 뒤, 릴리스마다 호환성을 깨는 변경을 순서대로 처리할 수 있습니다.

## 제한

`build_tokens`와 `scaffold_design_system`은 토큰 파일을 서버의 임시 폴더에 쓰고, 호출이 끝나면 그 폴더를 지웁니다. `build_tokens`는 파일을 최대 64개, 모두 합쳐 512 KB까지 받으며, 한 요청 안의 `build_tokens` 호출은 이 한도를 함께 나눠 씁니다. 2 MB보다 큰 요청 본문은 거부됩니다. 이 한도는 보낸 본문 그대로를 세므로, 큰 파일은 들여쓰기 없이 압축된 JSON으로 보내세요. 한 요청은 도구를 최대 4번 호출할 수 있고, 256단계까지만 중첩할 수 있으며, `build_tokens` 파일 밖에는 배열 항목과 객체 멤버를 모두 합쳐 2,048개까지 담을 수 있고, 그곳의 객체 키는 128자를 넘을 수 없습니다. 다른 도구를 호출할 때 인수에는 항목과 멤버를 1,024개까지 담을 수 있습니다. 한 요청 안의 호출은 이 한도를 함께 나눠 쓰며, `build_tokens`와 다른 도구를 섞은 요청에는 1,024개 한도가 적용됩니다. 10초보다 오래 걸리는 빌드는 중단되며, 서버가 다른 빌드로 바쁠 때 온 호출에는 다시 시도하라고 알려 줍니다.

도구 응답은 40,000자 안에 있습니다. 더 긴 페이지는 개요로, 또는 다음 조각을 가리키는 커서와 함께 돌아오며, 결과가 그 사실을 알립니다. `list_components`, `get_changes`, `list_tokens`, `scaffold_design_system`도 같은 방식으로 나뉩니다. 다음 페이지나 다음 파일은 `cursor.offset`을 넘겨 읽습니다. `list_tokens`의 `limit`는 한 페이지의 최대 행 수입니다. `get_docs_page`, `get_recipe`, `get_guide`, `when_to_use`는 `locale`이 `ko`이거나 slug가 `ko/`로 시작하면 한국어를 읽습니다. 컴포넌트 이름, prop 이름, 토큰 경로는 영어로 둡니다. 글자 수를 4로 나눈 값이 토큰 추정입니다. 실제 o200k 토크나이저는 영어에서 그 값의 약 1.00배에서 1.12배이고, 한국어에서 약 1.18배에서 1.76배입니다.
