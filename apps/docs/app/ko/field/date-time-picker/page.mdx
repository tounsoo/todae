# Field.DateTimePicker

`Field.DateTimePicker`는 [Field](/field) 안에서 [Popover](/popover)에 [Calendar](/calendar)와 시각 목록을 나란히, 좁은 화면에서는 목록을 달력 아래에 여는 버튼입니다. `value`는 `Temporal.PlainDateTime`이나 `null`입니다. `onValueChange`는 고른 뒤에 달력이 내놓는 날짜와 그 날짜의 범위 안 시각이 있을 때마다 그 날짜와 시각을 받습니다. 달력이 내놓는 날짜가 골라져 있을 때 시각을 고르면 팝오버가 닫힙니다. [Field.DatePicker](/field/date-picker), [Field.TimePicker](/field/time-picker)와 같은 방식으로 동작하고, 뜻이 같은 props는 같은 이름으로 받습니다. `PlainDateTime`에는 시간대가 없습니다. 사용자의 시계에 보이는 날짜와 시각입니다. 시점을 저장하려면 `value.toZonedDateTime(zone)`처럼 직접 작성한 코드에서 시간대와 합치세요.

```tsx
const id = useId();
const [start, setStart] = useState<Temporal.PlainDateTime | null>(null);
const [text, setText] = useState('');
const [invalid, setInvalid] = useState(false);

<Field.Group>
  <Label.Root htmlFor={id}>Meeting starts</Label.Root>
  <Field.Root id={id} invalid={invalid}>
    <Field.TextInput
      value={text}
      onChange={(event) => {
        setText(event.target.value);
        setStart(parseDateTime(event.target.value));
        setInvalid(false);
      }}
      onBlur={() => {
        if (start) setText(formatDateTime(start));
        else setInvalid(text.trim() !== '');
      }}
    />
    <Field.DateTimePicker
      value={start}
      onValueChange={(next) => {
        setStart(next);
        setText(formatDateTime(next));
        setInvalid(false);
      }}
      step={15}
      showValue={false}
    />
  </Field.Root>
</Field.Group>
```

여기서는 같은 필드의 [Field.TextInput](/field/text-input)으로 날짜와 시각을 입력할 수도 있습니다. 고른 날짜와 시각은 `formatDateTime`으로 텍스트에 쓰입니다. `Field.TextInput` 옆에서는 그 입력이 필드의 컨트롤입니다. 입력이 필드의 `id`, `name`, 설명을 받고, 필드의 다른 곳을 누르면 입력에 포커스가 갑니다. `showValue={false}`이면 버튼은 달력 글리프만 보여 줍니다. 버튼은 자신의 `name`이 있으면 그 이름으로 폼에 날짜와 시각을 보냅니다. 없으면 필드의 `name`으로 보내는데, `Field.ColorPicker`, `Field.DatePicker`, `Field.TimePicker`, 다른 `Field.DateTimePicker`가 아닌 Field 파트나 [`useField`](/utilities/use-field)로 연결한 컨트롤이 그 `name`을 가지고 있으면 보내지 않습니다. 자신의 `name`이 없는 `Field.TextInput`이 그런 경우입니다. 입력한 텍스트 대신 `2026-10-13T09:30` 형식으로 보내려면 Root 대신 선택기에 `name`을 두세요.

## 입력한 날짜와 시각

`formatDateTime(value, { locale })`은 날짜를 `formatDate`처럼 숫자로, 시각을 시와 분으로, 초가 있으면 초까지 씁니다. 예: `en-US`에서는 `10/13/2026, 9:30 PM`, `de`에서는 `13.10.2026, 21:30`, `ko`에서는 `2026. 10. 13. 오후 9:30`. `parseDateTime(text, { locale })`은 입력한 텍스트를 `Temporal.PlainDateTime`으로 읽고, 날짜와 시각이 아니면 `null`을 돌려줍니다. 날짜는 [`parseDate`](/field/date-picker#typed-dates)처럼 읽되 연도는 전부 쓰거나, `en-US`의 `10/13/26`처럼 로캘이 두 자리 연도로 쓰는 날짜 모양일 때만 끝의 두 자리로 쓰고, 이어서 시각은 [`parseTime`](/field/time-picker#typed-times)처럼 로캘이 쓰는 순서로 읽고, 로캘이 둘 사이에 쓰는 단어는 있어도 없어도 됩니다. 예: `en-US`에서는 `Oct 13, 2026 at 9:30 PM`이나 `10/13/2026 9:30 pm`. 시각에는 `21:30`이나 `2130`처럼 분이 있거나 `pm` 같은 단어가 있어야 하므로, `13.10.2026 21`처럼 시만 있는 텍스트는 읽지 않고, 시각이 없는 날짜도 읽지 않습니다. `locale`이 없으면 둘 다 런타임의 로캘을 씁니다.

예시에서는 날짜와 시각이 아닌 텍스트가 값을 비우므로 폼은 값을 보내지 않고, 필드는 포커스를 잃을 때 유효하지 않음으로 표시됩니다. `parseDateTime`은 선택기의 `min`, `max`, `isDateDisabled`를 확인하지 않으므로, 입력한 값은 직접 확인하세요.

## 단독으로

단독으로 쓰면 `Field.DateTimePicker`가 필드의 컨트롤입니다. 날짜는 로캘의 medium 날짜 스타일로, 시각은 short 시각 스타일로, 초가 있으면 medium 스타일로 보여 주고, 값이 없으면 `placeholder`를 보여 주며, 필드의 다른 곳을 누르면 팝오버가 열립니다. Root에 `name`이 있으면 숨은 입력이 HTML이 쓰는 형식으로 값을 보냅니다. 예: `2026-10-13T09:30`.

팝오버는 `open`과 `onOpenChange`, 또는 `defaultOpen`으로 열고 닫습니다. `onOpenChange`는 닫힌 이유를 받습니다. 고른 시각이 값이 되면 `'select'`, 그 밖에는 `'escape'`, `'outside'`, `'trigger'`, 필드가 비활성화되면 `'disabled'`입니다. 열리면 달력이 그 날짜에, 없으면 오늘이나 범위 안의 가장 가까운 날짜에 포커스를 둡니다. 날짜를 고르면 포커스가 시각 목록으로 가고, 날짜보다 시각을 먼저 고르면 달력으로 갑니다. Escape를 누르면 팝오버가 닫히고, 포커스는 열리기 전에 있던 곳으로 돌아갑니다.

`min`과 `max`는 두 쪽을 다 제한합니다. 달력은 그 사이의 날짜만 내놓고, 그중 첫 날짜와 마지막 날짜에는 목록이 범위 안의 시각만 내놓습니다. 고른 날짜에 대해 시각이 범위 밖이면, 범위 안의 시각을 고를 때까지 값을 알리지 않습니다. 선택기 옆에 입력한 날짜처럼 달력이 내놓지 않는 날짜는 날짜가 없는 것으로 보므로, 그때 시각을 고르면 포커스가 달력으로 갑니다. `isDateDisabled`와 `firstDayOfWeek`는 [Field.DatePicker](/field/date-picker)에서처럼, `step`은 [Field.TimePicker](/field/time-picker)에서처럼 동작합니다.

## Temporal

Todae는 Temporal 폴리필을 포함하지 않습니다. 선택기의 값과 `formatDateTime`, `parseDateTime`은 `Temporal.PlainDateTime`이므로, 브라우저에 Temporal이 없는 곳에서는 앱이 폴리필을 불러옵니다([네이티브 플랫폼](/platform) 참고). Todae의 타입에는 `Temporal`을 선언하는 TypeScript 6 이상이 필요합니다.

## 접근성을 지키는 조합

**Todae가 맡는 것:** 단독으로 쓰면 버튼은 `Field.Root`에서 `id`, `aria-label`, `aria-labelledby`, `aria-describedby`를 받고, Root나 바깥 [Fieldset](/fieldset)에서 네이티브 `disabled`와 `aria-invalid`를 받습니다. 레이블이 버튼의 이름이 되므로, 버튼에 보이는 날짜와 시각은 `aria-describedby`에 더해집니다. 텍스트 입력처럼 `Field.ColorPicker`, `Field.DatePicker`, `Field.TimePicker`, 다른 `Field.DateTimePicker`가 아닌 Field 파트나 `useField`로 연결한 컨트롤이 필드에 함께 있으면 그 컨트롤이 대신 `id`와 `aria-describedby`를 받고, 버튼은 `disabled`와 `aria-invalid`를 유지하며, 자체 `aria-label`이 없으면 [StringsProvider](/utilities/strings-provider)의 `dateTimePicker` 문자열로 이름이 붙습니다. 버튼에는 `aria-haspopup="dialog"`와 `aria-expanded`가, 팝오버가 열려 있는 동안에는 `aria-controls`가 붙습니다. 팝오버는 `dateTimePicker` 문자열로 이름이 붙는 `role="dialog"`입니다. 안에는 키보드 조작이 해당 페이지에 설명된 Calendar와, `timePicker` 문자열로 이름이 붙는 시각의 [OptionList](/optionlist)가 있으며, 목록에서는 화살표 키, Home, End로 옮기고 Enter나 Space로 고릅니다. 글리프는 [GlyphsProvider](/utilities/glyphs-provider)의 `calendar`입니다.

**직접 제공할 것:** 이름. `htmlFor`가 Root `id`인 [Label](/label)이나, Root의 `aria-label` / `aria-labelledby`입니다. 텍스트 입력과 그 옆의 선택기에는 같은 값을 주고, `formatDateTime`으로 쓰고 `parseDateTime`으로 읽으세요.

**주의할 점:** 서버 렌더는 버튼 옆에 다른 컨트롤이 있는지 알 수 없으므로, 페이지가 하이드레이션될 때까지 버튼과 그 컨트롤 둘 다 필드의 `id`를 가지고 필드의 `name`으로 값을 보냅니다. `value`가 있으면 서버는 그 날짜와 시각을 서버의 로캘로 쓰므로, 서버에서 렌더링할 때는 `locale`을 넘기세요.

## 언제 쓰나요

### Field.DateTimePicker

**언제:** 회의 시작이나 항공편 출발처럼 날짜와 하루 중 시각을 하나의 값으로.

**쓰지 않을 때:** 날짜만 → [Field.DatePicker](/field/date-picker). 시각만 → [Field.TimePicker](/field/time-picker). 시간대가 있는 시점 → 이 선택기를 쓰고 시간대는 직접 작성한 코드에서 더하세요.
