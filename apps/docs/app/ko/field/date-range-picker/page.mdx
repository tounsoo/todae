# Field.DateRangePicker

`Field.DateRangePicker`는 [Field](/field) 안에서 범위 모드의 [Calendar](/calendar)를 [Popover](/popover)로 여는 버튼입니다. `value`는 시작일과 종료일을 모두 포함하는 `{ start, end }` 형태의 `DateRange`나 `null`입니다. 달력에서 처음 고른 날짜가 범위를 시작하고 두 번째로 고른 날짜가 끝내며, 순서는 상관없습니다. 그러면 `onValueChange`가 범위를 받고 달력이 닫힙니다. 달력의 `min`, `max`, `isDateDisabled`, `firstDayOfWeek`, `locale`을 받습니다.

```tsx
const id = useId();
const [range, setRange] = useState<DateRange | null>(null);
const [text, setText] = useState('');
const [invalid, setInvalid] = useState(false);

<Field.Group>
  <Label.Root htmlFor={id}>Stay</Label.Root>
  <Field.Root id={id} invalid={invalid}>
    <Field.TextInput
      value={text}
      onChange={(event) => {
        setText(event.target.value);
        setRange(parseDateRange(event.target.value));
        setInvalid(false);
      }}
      onBlur={() => {
        if (range) setText(formatDateRange(range));
        else setInvalid(text.trim() !== '');
      }}
    />
    <Field.DateRangePicker
      value={range}
      onValueChange={(next) => {
        setRange(next);
        setText(formatDateRange(next));
        setInvalid(false);
      }}
      showValue={false}
    />
  </Field.Root>
</Field.Group>
```

여기서는 같은 필드의 [Field.TextInput](/field/text-input)으로 범위를 입력할 수도 있습니다. 고른 범위는 `formatDateRange`로 텍스트에 쓰이고, `parseDateRange`가 범위로 읽은 입력은 달력을 그 시작일로 옮깁니다. `Field.TextInput` 옆에서는 그 입력이 필드의 컨트롤입니다. 입력이 필드의 `id`, `name`, 설명을 받고, 필드의 다른 곳을 누르면 입력에 포커스가 갑니다. `showValue={false}`이면 버튼은 달력 글리프만 보여 줍니다. 버튼은 자신의 `name`이 있으면 그 이름으로 폼에 범위를 보냅니다. 없으면 필드의 `name`으로 보내는데, `Field.ColorPicker`, `Field.DatePicker`, `Field.DateRangePicker`, `Field.TimePicker`, `Field.DateTimePicker`가 아닌 Field 파트나 [`useField`](/utilities/use-field)로 연결한 컨트롤이 그 `name`을 가지고 있으면 보내지 않습니다. 입력한 텍스트 대신 `2026-10-03/2026-10-10` 형식으로 범위를 보내려면 Root 대신 선택기에 `name`을 두세요.

## 입력한 범위

`formatDateRange(range, { locale })`는 두 날짜를 [`formatDate`](/field/date-picker)가 쓰는 대로 쓰고, 그 사이에 로캘의 범위 구분자를 넣습니다. 예: `en-US`에서는 `10/3/2026 – 10/10/2026`, `ko`에서는 `2026. 10. 3. ~ 2026. 10. 10.`. `parseDateRange(text, { locale })`는 입력한 텍스트를 `DateRange`로 읽고, 범위가 아니면 `null`을 돌려줍니다. 글자나 숫자가 아닌 문자가 이어진 곳마다, 그리고 로캘의 범위 구분자에서 텍스트를 나누고, 양쪽을 `parseDate`로 날짜로 읽습니다. 날짜 두 개로 읽히는 나눔이 정확히 하나일 때 범위를 돌려주므로, `10/3/2026 - 10/10/2026`, `Oct 3, 2026 – Oct 10, 2026`, 그리고 `2026-10-03/2026-10-10` 같은 ISO 8601 구간을 읽습니다. `formatDateRange`가 쓰는 대로 날짜마다 연도가 있어야 하므로, `Oct 3 – Oct 10, 2026`에는 `null`을 돌려줍니다. 종료일이 시작일보다 앞서도 `null`을 돌려줍니다. `locale`이 없으면 둘 다 런타임의 로캘을 씁니다.

예시에서는 범위가 아닌 텍스트가 범위를 비우므로 폼은 범위를 보내지 않고, 필드는 포커스를 잃을 때 유효하지 않음으로 표시됩니다. `parseDateRange`는 선택기의 `min`, `max`, `isDateDisabled`도, 두 날짜 사이의 날을 모두 고를 수 있는지도 확인하지 않으므로, 입력한 범위는 직접 확인하세요.

"최근 7일" 같은 프리셋은 선택기에 포함되지 않습니다. 선택기 옆에 버튼을 두고 그 `value`를 정하는 Date range with presets 레시피에서 다룹니다.

## 단독으로

단독으로 쓰면 `Field.DateRangePicker`가 필드의 컨트롤입니다. 범위를 `Intl.DateTimeFormat`의 `formatRange`로 `locale`의 medium 스타일에 맞춰 보여 줍니다. 예: `Oct 3 – 10, 2026`. 하루짜리 범위는 날짜 하나로, 범위가 없으면 `placeholder`를 보여 줍니다. 필드의 다른 곳을 누르면 달력이 열립니다. Root에 `name`이 있으면 숨은 입력이 범위를 ISO 8601 구간으로 보냅니다. 예: `2026-10-03/2026-10-10`.

달력은 `open`과 `onOpenChange`, 또는 `defaultOpen`으로 열고 닫습니다. `onOpenChange`는 닫힌 이유를 받습니다. 범위의 두 번째 날짜를 고르면 `'select'`, 그 밖에는 `'escape'`, `'outside'`, `'trigger'`, 필드가 비활성화되면 `'disabled'`입니다. 열리면 달력은 범위의 시작일에, 없으면 오늘이나 범위 안의 가장 가까운 날짜에 포커스를 둡니다. 첫 번째 날짜를 고른 뒤에 Escape를 누르면 그 선택이 취소되고 달력은 열린 채로 남습니다. 고른 날짜가 없을 때 Escape를 누르면 달력이 닫히고, 포커스는 열리기 전에 있던 곳으로 돌아갑니다. 달력이 닫히면 첫 번째로 고른 날짜는 사라집니다.

## 접근성을 지키는 조합

**Todae가 맡는 것:** 단독으로 쓰면 버튼은 `Field.Root`에서 `id`, `aria-label`, `aria-labelledby`, `aria-describedby`를 받고, Root나 바깥 [Fieldset](/fieldset)에서 네이티브 `disabled`와 `aria-invalid`를 받습니다. 레이블이 버튼의 이름이 되므로, 버튼에 보이는 범위는 `aria-describedby`에 더해집니다. 텍스트 입력처럼 `Field.ColorPicker`, `Field.DatePicker`, `Field.TimePicker`, `Field.DateTimePicker`, 다른 `Field.DateRangePicker`가 아닌 Field 파트나 `useField`로 연결한 컨트롤이 필드에 함께 있으면 그 컨트롤이 대신 `id`와 `aria-describedby`를 받고, 버튼은 `disabled`와 `aria-invalid`를 유지하며, 자체 `aria-label`이 없으면 [StringsProvider](/utilities/strings-provider)의 `dateRangePicker` 문자열로 이름이 붙습니다. 버튼에는 `aria-haspopup="dialog"`와 `aria-expanded`가, 달력이 열려 있는 동안에는 `aria-controls`가 붙습니다. 팝오버는 `dateRangePicker` 문자열로 이름이 붙은 `role="dialog"`이고, 안의 달력은 범위 모드의 [Calendar](/calendar)와 같은 키로 움직이고 같은 안내를 읽어 줍니다. 글리프는 [GlyphsProvider](/utilities/glyphs-provider)의 `calendar`입니다.

**직접 제공할 것:** 이름. `htmlFor`가 Root `id`인 [Label](/label)이나, Root의 `aria-label` / `aria-labelledby`입니다. 텍스트 입력과 그 옆의 선택기에는 같은 범위를 주고, `formatDateRange`로 쓰고 `parseDateRange`로 읽으세요.

**주의할 점:** 서버 렌더는 버튼 옆에 다른 컨트롤이 있는지 알 수 없으므로, 페이지가 하이드레이션될 때까지 버튼과 그 컨트롤 둘 다 필드의 `id`를 가지고 필드의 `name`으로 값을 보냅니다. `value`가 있으면 서버는 그 범위를 서버의 로캘로 쓰므로, 서버에서 렌더링할 때는 `locale`을 넘기세요.

## 언제 쓰나요

### Field.DateRangePicker

**언제:** 숙박, 여행, 보고서 기간처럼 폼에서 시작일과 종료일을 고를 때.

**쓰지 않을 때:** 날짜 하나 → [Field.DatePicker](/field/date-picker). 페이지에 펼쳐 둔 달력에서 고르는 범위 → `mode="range"`인 [Calendar](/calendar). 시작일과 별도의 마감일처럼 따로 정하는 두 날짜 → `Field.DatePicker` 두 개.

### formatDateRange

**언제:** 선택기 옆 텍스트 입력처럼, 범위를 로캘에 맞는 텍스트로 쓸 때.

**쓰지 않을 때:** `Oct 3 – 10, 2026`처럼 입력용이 아니라 읽기용인 범위 → `Intl.DateTimeFormat`의 `formatRange`.

### parseDateRange

**언제:** 사람이 입력한 범위를 읽을 때.

**쓰지 않을 때:** 폼이나 API에서 온 `2026-10-03/2026-10-10` 같은 ISO 8601 구간 → `/`에서 나눠 각각 `Temporal.PlainDate.from`으로 읽으세요.
