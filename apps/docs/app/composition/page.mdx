# Composition

The public ladder is Compounds, then Recipes. Recipes live in these docs. They are not `Combobox.*` exports.

## Compounds

Public siblings. `Field`, `Label`, `Button`, `Popover`, `Chip`, `OptionList`, `Dialog`, and `BottomSheet`. Compose them side by side. Never nest namespaces. One interactive role per compound root.

`Field.Icon`, `Field.Affix`, and `Button.Icon` are compound parts. They are not free-floating atoms. Shared Icon, Affix, and Shell live under the hood. They are not a public rung.

`Field.Root` is chrome only. `Label` is a sibling atom. Adornments follow DOM order. No `side` prop.

Field shell is not a button. This tree is never allowed.

```tsx
<Field.Root role="button" onClick={onOpen}>
  <Field.TextInput value={q} onChange={(event) => setQ(event.target.value)} />

```

## Recipes

Worked examples that compose compounds and hooks. Combobox is a recipe, not a package namespace. The blocks below are static. They do not run. The hook owns behavior. Compounds own chrome. There is no shipped Trigger sugar.

Desktop (`presentation="popover"`). The closed control is a real Field. Spread hook trigger props onto `Field.Root`. The list lives in `Popover`.

```tsx
const cb = useCombobox({ presentation: 'popover' })
const id = useId()

<Label htmlFor={id}>Tags</Label>
<Field.Root {...cb.getTriggerProps()} id={id}>
	<Field.Icon><Search /></Field.Icon>
	<Field.ChipInput chips={chips} inputValue={q} onInputValueChange={setQ} onCommit={onCommit} onChipRemove={onRemove} />
	<Field.Icon><ChevronDown /></Field.Icon>
</Field.Root>
<Popover {...cb.getPopoverProps()}>
	<OptionList {...cb.getListProps()}>...</OptionList>
</Popover>
```

Today only `Popover.Trigger` sets `anchor-name`. Anchoring Popover to a non-Trigger Field is part of the hook PRD.

Touch (`presentation="sheet"`). The closed control is `Button.Root`. Search Field lives inside the sheet.

```tsx
const cb = useCombobox({ presentation: 'sheet' })
const searchId = useId()

<Button.Root {...cb.getTriggerProps()}>Pick…</Button.Root>
<BottomSheet {...cb.getSheetProps()}>
	<Label htmlFor={searchId}>Search</Label>
	<Field.Root id={searchId}>
		<Field.Icon><Search /></Field.Icon>
		<Field.TextInput value={q} onChange={(event) => setQ(event.target.value)} />
	</Field.Root>
	<OptionList>...</OptionList>
</BottomSheet>
```

The touch trigger is `Button.Root`.

## Coming

`useCombobox` will ship headless. It owns open, value, aria, keyboard, and listbox ids. Exact `get*Props` names land in the hook PRD. The intent is:

- `useCombobox({ presentation: 'popover' | 'sheet' })`
- `getTriggerProps()` on `Field.Root` (desktop) or `Button.Root` (touch)
- `getPopoverProps()` on `Popover`
- `getSheetProps()` on `BottomSheet`
- `getListProps()` on `OptionList`

No Trigger sugar component. No `Combobox.*` chrome.
