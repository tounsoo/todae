# Tokens

Generated catalog from the DTCG pipeline. Components consume contract vars only.

## When to use

### ThemeProvider

**When:** Set appearance (system / light / dark) for a subtree via `data-appearance`; nested providers override. `overrides` for allowlisted token paths only.

**When not:** Spacing density → DensityProvider. Raw CSS or unknown token keys (rejected). Styling via classes on the provider (overlays don't inherit them).

### DensityProvider

**When:** Set spacing density (compact / comfortable / spacious) for a subtree via `data-density`. Spacing only.

**When not:** Color or light / dark → ThemeProvider. Type size → Text `size`.

## Contrast

The token build measures text pairs with APCA, not WCAG 2 ratios. Each pair names a text color, an opaque background and the lowest Lc allowed, for example `color.fg.muted` on `color.bg.elevated` at Lc 60. The build fails when a pair falls short in any appearance.

The pairs live in `$extensions["dev.todae"].contrast` on the appearance modifier in `tokens/resolver.json`. A company token package inherits them, so a rebranded accent is checked too. A company can list a pair with the same `fg` and `bg` to change its minimum, or add pairs for its own tokens.
