# App shell

A recipe, not a package namespace. An app shell is the frame around a product's pages: a header across the top, a [Nav](/nav) sidebar in a [Splitter](/splitter) beside the main content, and, below a width where both don't fit, the sidebar in a [Drawer](/drawer) that a button in the header opens. The pages, their links and the breakpoint are your product's. There is no `AppShell.*` export.

Drag the handle, or hide the navigation from the header's first button. On a narrow screen the same button opens the navigation in a drawer.

## Layout

A skip link comes first, then the `header`, then the splitter, with the sidebar's `Nav.Root` in the first panel and `main` in the second. Give `main` the skip link's target id and `tabIndex={-1}`, so the link moves focus into it. The shell is a grid of two rows: the header's, and one that takes the rest, which the splitter fills. Each panel scrolls its own content, so the header stays in view.

```tsx
<div className="shell">
  <VisuallyHidden.Root focusable>
    <Link.Root href="#main">Skip to content</Link.Root>
  </VisuallyHidden.Root>
  <Stack.Root as="header" direction="row" align="center" gap="condensed">
    <Button.Root ref={navButton} variant="ghost" aria-label="Navigation">
      …
    </Button.Root>
    <Text.Root as="span" weight="bold">
      Atlas
    </Text.Root>
    <Toolbar.Root aria-label="Account">…</Toolbar.Root>
  </Stack.Root>
  <Splitter.Root value={width} onValueChange={setWidth} min={180} max={360} collapsible>
    <Splitter.Panel id={sidebarId}>…</Splitter.Panel>
    <Splitter.Handle aria-label="Resize navigation" />
    <Splitter.Panel>
      <main id="main" tabIndex={-1}>
        …
      </main>
    </Splitter.Panel>
  </Splitter.Root>
</div>
```

```css
.shell {
  display: grid;
  grid-template-rows: auto minmax(0, 1fr);
  block-size: 100dvh;
}
```

## Sidebar

The sidebar's width is the splitter's `value`, in pixels, so it keeps its width while the window changes and the main content flexes. With `collapsible`, Enter on the handle hides it and shows it again. The header's button does the same for people who don't find the handle: it sets the width you hold and keeps its own last width, as on the [Splitter](/splitter) page, with `aria-expanded` and `aria-controls` pointing at the panel. Keep the width where your product keeps preferences and pass it back as `value`.

```tsx
const [width, setWidth] = useState(240);
const [lastWidth, setLastWidth] = useState(240);
const toggleSidebar = () => {
  if (width > 0) setLastWidth(width);
  setWidth(width === 0 ? lastWidth : 0);
};
```

## Narrow screens

Below the breakpoint, 48rem here, the sidebar moves into a `Drawer.Root` at the start edge, and the same header button opens it. The shell fills the window, so read the window's width with `matchMedia`. Then set `only="end"` on the splitter: it shows the main panel alone and takes the sidebar's panel and the handle out of the layout, with the main panel still mounted. Crossing the breakpoint, which zooming the page to 200% does on most screens, then keeps the page's focus, its scroll position and anything typed into it. Render the `Nav.Root` in one place at a time: the first panel while wide, the drawer while narrow.

The server has no window, so choose the layout it sends. Sending the narrow one, as here, never squeezes the main content on a phone, and a wide window switches as it hydrates, with nothing remounted.

```tsx
const WIDE = '(min-width: 48rem)';

function subscribe(onChange: () => void) {
  const query = window.matchMedia(WIDE);
  query.addEventListener('change', onChange);
  return () => query.removeEventListener('change', onChange);
}

function useWide() {
  return useSyncExternalStore(subscribe, () => window.matchMedia(WIDE).matches, () => false);
}

const wide = useWide();
const sidebarHandoff = useFocusHandoff({ to: navButton });
// A window that widens shows the sidebar, so the drawer closes, and Drawer puts focus back on the button.
if (wide && drawerOpen) setDrawerOpen(false);

<Button.Root
  ref={navButton}
  variant="ghost"
  aria-label="Navigation"
  {...(wide ? { 'aria-controls': sidebarId, 'aria-expanded': width > 0 } : { 'aria-haspopup': 'dialog' as const })}
  onClick={wide ? toggleSidebar : () => setDrawerOpen(true)}
>
  <Button.Icon>{wide ? <PanelLeft /> : <Menu />}</Button.Icon>
</Button.Root>

<Splitter.Root only={wide ? undefined : 'end'} value={width} onValueChange={setWidth} min={180} max={360} collapsible>
  <Splitter.Panel id={sidebarId}>{wide && <div ref={sidebarHandoff}>{nav}</div>}</Splitter.Panel>
  <Splitter.Handle aria-label="Resize navigation" />
  <Splitter.Panel>…</Splitter.Panel>
</Splitter.Root>
```

The button stays one element in both layouts, so it keeps focus when the layout switches under it. While wide it hides and shows the sidebar; while narrow it opens a dialog, which `aria-haspopup="dialog"` says. A sidebar that unmounts while it holds focus hands it to the button through `useFocusHandoff`, so focus doesn't fall to the page when the window narrows.

## Navigating

Mark the current page's link with `aria-current="page"`, which your router sets (see [Nav](/nav)). In the sidebar, focus stays on the link the person chose, so they can go on to the next one. Some routers announce the new page, as Next.js does; with one that doesn't, announce its title with [useAnnouncer](/utilities/use-announcer).

In the drawer, the chosen link goes away with the drawer, so close it and send focus to the new page's heading through `restoreFocusRef`. Set the ref when a link is chosen and clear it when the drawer opens, so Escape and the close button still put focus back on the header button. A click with a modifier key opens the link elsewhere, so it leaves the drawer open.

```tsx
const heading = useRef<HTMLElement>(null);
const returnTo = useRef<HTMLElement | null>(null);
const openDrawer = () => {
  returnTo.current = null;
  setDrawerOpen(true);
};

<Drawer.Root open={drawerOpen} onOpenChange={setDrawerOpen} side="start" restoreFocusRef={returnTo}>
  <Drawer.Header>
    <Drawer.Title>Atlas</Drawer.Title>
    <Drawer.Close />
  </Drawer.Header>
  <Drawer.Body
    onClick={(event) => {
      const elsewhere = event.metaKey || event.ctrlKey || event.shiftKey || event.altKey;
      if (elsewhere || !(event.target as Element).closest('a[href]')) return;
      returnTo.current = heading.current;
      setDrawerOpen(false);
    }}
  >
    {nav}
  </Drawer.Body>
</Drawer.Root>

<Text.Root as="h1" ref={heading} tabIndex={-1}>
  {page.title}
</Text.Root>
```

## Accessible composition

**Todae handles:** The `nav` landmark, its lists and the current link's look, in `Nav.Root`. The resizable sidebar: the handle's role, value, keys and pointer, Enter to collapse, and a collapsed panel hidden from the tab order and the accessibility tree, in `Splitter`. The main panel shown alone with both panels kept mounted, through `only`. A modal drawer that takes focus, closes on Escape, makes the page behind it inert and puts focus back on the button or on `restoreFocusRef`, in `Drawer.Root`. One Tab stop for the header's actions, in `Toolbar.Root`. A skip link shown while it has focus, in `VisuallyHidden.Root focusable`. Focus moving to the header button when the sidebar unmounts holding it, through `useFocusHandoff`.

**You supply:** The pages and their links, and which one is current. The `header` and `main` landmarks, the skip link and its target. Names for the nav, the handle, the header button and the toolbar. The breakpoint and the layout the server sends. The nav in one place at a time. Closing the drawer when the window widens or a link is chosen, and where focus goes then. Saving the sidebar's width.

**Watch for:** A different layout below the breakpoint in place of `only`, which remounts the page, so a person who zooms in loses their place and what they typed. A second copy of the nav hidden with CSS other than `display: none`, which leaves two `nav` landmarks of the same name. A drawer that stays open after the window widens. A drawer link that sends focus back to the header button, which leaves a screen reader at the top of the new page instead of its heading. A skip link target without `tabIndex={-1}`, which moves the page but not every screen reader's reading position. Focus on the handle when the layout narrows, which `only` takes out of the layout, so focus falls to the page.

## When to use

**When:** The frame of an app with several pages and navigation that stays in view, such as a dashboard, an admin or a workspace.

**When not:** A site with a few top-level pages → links in the header, as a `nav`. Views of one page → [Tabs](/tabs). Two panes the person resizes inside a page → [Splitter](/splitter) alone. A side panel for a task beside the content → [Drawer](/drawer).
