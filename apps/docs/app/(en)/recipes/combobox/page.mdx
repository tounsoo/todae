# Combobox

A recipe, not a package namespace. [useCombobox](/utilities/use-combobox) owns open, value, input, highlight, and ids. Components own chrome. There is no `Combobox.*` export. One interactive role per root.

## Presentation

`useCombobox({ presentation: 'auto' })` picks a sheet on a coarse pointer or a narrow viewport and a popover otherwise, always a popover on the server and the first paint, through [useSheetPresentation](/utilities/use-sheet-presentation). Force `popover` or `sheet` when a docs screenshot must stay still.

If presentation flips while the list is open, the hook closes with `blur`.

The badge shows what [useSheetPresentation](/utilities/use-sheet-presentation) picks here; `isSheet` is not `isTouch`.

## Async

`loadOptions(query, signal)` loads options for the trimmed text, and they show as it returns them, so the loader does the matching; `filterOptions` is ignored beside it, and `options` only lends labels, such as the starting value's. A newer query aborts the last controller and discards a stale resolve. The hook keeps the previous list while `loading` is true. Debounce, loading, and Retry chrome stay in the recipe. The hook does not debounce.

Type `fail` to see the error row.

## Empty and create

No matches render a status row. `allowCreate` adds one `Create "{query}"` option in the same `OptionList` when the query has no case-insensitive label match. Click or Enter commits. Single selects and closes. Multi adds a chip and stays open. `onCreate` may return a canonical value and should append the new option to `options` so the list can show it selected. It may return a promise: `creating` is true until it settles. What it throws or rejects with lands in `createError` while the text still asks for that label. Show both in a status element next to the create row, as the first create demo does; type `fail` there to see it.

## Highlight matches

Every demo on this page marks the typed text in its options with [useHighlight](/utilities/use-highlight), which paints it without changing the options' markup, so each option keeps its accessible name. Pass the hook's `query` (empty while the input shows the selected label, so nothing is marked then) and put the `ref` on the list:

```tsx
const found = useHighlight({ name: 'combobox-match', query: cb.query });

<OptionList.Root ref={found.ref} {...cb.getListboxProps()}>
```

Hooks that share a name paint together, so give every combobox the same name and style it once:

```css
::highlight(combobox-match) {
  background-color: var(--todae-color-status-warning-bg);
  color: var(--todae-color-fg-default);
}
```

With `loadOptions`, the loader does the matching, so a row it returns may not hold the typed text and shows no mark.

## Composition rules

- Sibling [Label](/label) + `Field.Root` id. No `Field.Label`.
- Do not spread [usePopover](/utilities/use-popover) `getTriggerProps` next to `getAnchorProps`. Dual-wire is a QA fail.
- OptionList is the overlay list. Do not also render Radio or Checkbox for the same value.
- Do not bake combobox into Field. Do not export `Combobox.*` chrome.
- Sheet trigger uses `aria-haspopup="dialog"`. Popover Field chrome has no `aria-haspopup`.

## Accessible composition

**Todae handles:** [useCombobox](/utilities/use-combobox) makes the input a `role="combobox"` that points at the listbox with `aria-controls` and at the active option with `aria-activedescendant`, and runs the arrow keys, Home, End, Enter, Escape and Tab. `OptionList` renders `role="listbox"` with `role="option"` rows carrying `aria-selected` and `aria-disabled`, and `aria-multiselectable` in multi mode. `Popover` and `BottomSheet` close on Escape and return focus. In multi mode, `Field.ChipInput` names each chip's remove button.

**You supply:** The label: a [Label](/label) with `{...cb.getLabelProps()}`, which points it at the input, or at the trigger in sheet mode, and gives it the id the listbox takes its name from. Inside a sheet, the search field's own name, such as `aria-label` on its `Field.Root`. With no visible label, pass `aria-label` to `getListboxProps()`. In sheet mode, trigger text that shows the value. Loading, error, create failure and empty text in a `role="status"` element; keep that element mounted and change its text, since text in a region that has just appeared is not always read. A Retry button that is a real button, as in the async demo.

**Watch for:** Unmounting `OptionList.Root` when it is empty or loading; set `hidden` so `aria-controls` still points at it. Your own `onKeyDown`, `onFocus` or `onBlur` after the getter's spread, which replaces the hook's handlers. The match highlight as the only cue: it is visual only.

## When to use

**When:** Picking one or more values from a list long enough that people type to find one, such as a country, an assignee or tags.

**When not:** A few options that fit on the page → [Radio](/radio) or [Checkbox](/checkbox). One value from a short list in a form → [Field.Select](/field/select). A short overlay list with no typing → [usePopover](/utilities/use-popover) and [OptionList](/optionlist). Running actions → [Menu](/menu), or the [Command palette](/recipes/command-palette) recipe to search them. Free text with no list → a [Field](/field) text input.
