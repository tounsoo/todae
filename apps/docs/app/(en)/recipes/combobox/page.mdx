# Combobox

A recipe, not a package namespace. [useCombobox](/utilities/use-combobox) owns open, value, input, highlight, and ids. Components own chrome. There is no `Combobox.*` export. One interactive role per root.

## Presentation

`useCombobox({ presentation: 'auto' })` picks a sheet on a coarse pointer or a narrow viewport and a popover otherwise, always a popover on the server and the first paint, through [useSheetPresentation](/utilities/use-sheet-presentation). Force `popover` or `sheet` when a docs screenshot must stay still.

If presentation flips while the list is open, the hook closes with `blur`.

The badge shows what [useSheetPresentation](/utilities/use-sheet-presentation) picks here; `isSheet` is not `isTouch`.

## Popover · single

Sibling `Label.Root` + `Field.Root` id. The input is the combobox. The list lives in `Popover.Root`.

```tsx
import { ChevronDown } from 'lucide-react';

const cb = useCombobox({ options, presentation: 'popover' });

<Field.Group>
  <Label.Root {...cb.getLabelProps()}>Framework</Label.Root>
  <Field.Root {...cb.getAnchorProps()}>
    <Field.TextInput {...cb.getInputProps()} />
    <Field.Icon>
      <ChevronDown />
    </Field.Icon>
  </Field.Root>
</Field.Group>
<Popover.Root {...cb.getPopoverProps()}>
  <OptionList.Root {...cb.getListboxProps()}>
    {cb.items.map((item) => (
      <OptionList.Option key={item.id} {...cb.getOptionProps(item)} />
    ))}
  </OptionList.Root>
</Popover.Root>
```

## Popover · multi

`Field.ChipInput` via `getChipInputProps`. Chips are labels. Values dedupe.

```tsx
const cb = useCombobox({ options, selectionMode: 'multiple', presentation: 'popover' });

<Field.Group>
  <Label.Root {...cb.getLabelProps()}>Type</Label.Root>
  <Field.Root {...cb.getAnchorProps()}>
    <Field.ChipInput {...cb.getChipInputProps()} />
```

## Sheet

The closed control is `Button.Root`. Search Field lives inside the sheet. Same `inputValue` and list as popover.

```tsx
const cb = useCombobox({ options, presentation: 'sheet' });
const selected = options.find((option) => option.value === cb.value)?.label ?? 'Choose';

<Field.Group>
  <Label.Root {...cb.getLabelProps()}>
    City
  </Label.Root>
  <Button.Root {...cb.getTriggerProps()} aria-labelledby={`${cb.ids.label} ${cb.ids.trigger}`}>
    {selected}
  </Button.Root>
</Field.Group>
<BottomSheet.Root {...cb.getSheetProps()}>
  <Field.Root id={cb.ids.input} aria-label="Search">
    <Field.TextInput {...cb.getInputProps()} />
  </Field.Root>
  <OptionList.Root {...cb.getListboxProps()}>…</OptionList.Root>
</BottomSheet.Root>
```

## Async

`loadOptions(query, signal)` loads options. A newer query aborts the last controller and discards a stale resolve. The hook keeps the previous list while `loading` is true. Debounce, loading, and Retry chrome stay in the recipe. The hook does not debounce.

Type `fail` to see the error row.

```tsx
const cb = useCombobox({
  loadOptions: (query, signal) => fetchPackages(query, { signal }),
  presentation: 'popover',
});

<Popover.Root {...cb.getPopoverProps()}>
  <Text.Root role="status">{cb.loading ? 'Loading…' : cb.error ? 'Couldn’t load options.' : ''}</Text.Root>
  {cb.error && !cb.loading ? (
    <Button.Root variant="ghost" onClick={cb.retry}>
      Retry
    </Button.Root>
  ) : null}
  <OptionList.Root {...cb.getListboxProps()} hidden={cb.loading || cb.error != null}>
    …
  </OptionList.Root>
</Popover.Root>
```

## Empty and create

No matches render a status row. `allowCreate` adds one `Create "{query}"` option in the same `OptionList` when the query has no case-insensitive label match. Click or Enter commits. Single selects and closes. Multi adds a chip and stays open. `onCreate` may return a canonical value and should append the new option to `options` so the list can show it selected. It may return a promise: `creating` is true until it settles, and a rejection lands in `createError`. Show both in a status element next to the create row, as the first create demo does; type `fail` there to see it.

## Highlight matches

[useHighlight](/utilities/use-highlight) marks the query in each option without changing the options' markup. Pass the hook's `query` (empty while the input shows the selected label), put the `ref` on the list, and style the name with `::highlight(search)`.

```tsx
const found = useHighlight({ name: 'search', query: cb.query });

<OptionList.Root ref={found.ref} {...cb.getListboxProps()}>…</OptionList.Root>
```

## Composition rules

- Sibling [Label](/label) + `Field.Root` id. No `Field.Label`.
- Do not spread [usePopover](/utilities/use-popover) `getTriggerProps` next to `getAnchorProps`. Dual-wire is a QA fail.
- OptionList is the overlay list. Do not also render Radio or Checkbox for the same value.
- Do not bake combobox into Field. Do not export `Combobox.*` chrome.
- Sheet trigger uses `aria-haspopup="dialog"`. Popover Field chrome has no `aria-haspopup`.

## Accessible composition

**Todae handles:** [useCombobox](/utilities/use-combobox) makes the input a `role="combobox"` that points at the listbox with `aria-controls` and at the active option with `aria-activedescendant`, and runs the arrow keys, Home, End, Enter, Escape and Tab. `OptionList` renders `role="listbox"` with `role="option"` rows carrying `aria-selected` and `aria-disabled`, and `aria-multiselectable` in multi mode. `Popover` and `BottomSheet` close on Escape and return focus. In multi mode, `Field.ChipInput` names each chip's remove button.

**You supply:** The label: a [Label](/label) with `{...cb.getLabelProps()}`, which points it at the input, or at the trigger in sheet mode, and gives it the id the listbox takes its name from. Inside a sheet, the search field's own name, such as `aria-label` on its `Field.Root`. With no visible label, pass `aria-label` to `getListboxProps()`. In sheet mode, a trigger whose name says the field and its current value. Loading, error, create failure and empty text in a `role="status"` element; keep that element mounted and change its text, since text in a region that has just appeared is not always read. A Retry button that is a real button, as in the async demo.

**Watch for:** Unmounting `OptionList.Root` when it is empty or loading; set `hidden` so `aria-controls` still points at it. Your own `onKeyDown`, `onFocus` or `onBlur` after the getter's spread, which replaces the hook's handlers. The match highlight as the only cue: it is visual only.
