# Avatar group

A recipe, not a package namespace. Todae has no `Avatar.Group` export. A stack of avatars is a `div` with `role="group"`, some `Avatar.Root`s, and a few lines of CSS that your product copies. The CSS reads public tokens, and `--avatar-group-ring` for the ring color, so the ring and the theme stay with your product. Nothing in `@tounsoo/todae` stacks avatars for you.

The stack below is the people on a task. Four of them show with a category tone each, and the rest shows as a "+1" avatar. The [Avatar](/avatar) page covers the avatar itself, its image and fallback, and its size.

## The stack

The stack is a flex row whose children overlap by a quarter of the avatar size. Each `Avatar.Root` takes the `avatar` class, which draws the ring that keeps overlapping edges apart. There is no `max` or count. Slice your own array and show the rest as a plain `Avatar.Root` with a label of its own.

The first example above shows its stylesheet after its code. Save it next to the component as `AvatarGroup.module.css`. Every example on this page uses the same rules, so the page shows the stylesheet once.

The overlap reads the stack's size, not each avatar's, so it holds for any direct child: an avatar, or one wrapped in a tooltip trigger or a link. An avatar given its own size is still pulled back by the stack's size. The margin is logical, so the stack mirrors in right-to-left text. The ring is a `box-shadow` in `--avatar-group-ring`, which falls back to the surface color. Set `--avatar-group-ring` on the stack. Set on an ancestor, a token in its value resolves there, so a theme between that ancestor and the stack does not change it. A focused child rises above its neighbors, so its focus ring shows whole. In forced colors the ring is dropped and each avatar gets a border in the system text color instead. An avatar inside a button or a link is a flex box, so it does not add a line box of its own. A button or a link that is a direct child has no padding, border or fill, so that child stays the avatar's size.

## Sizes

An avatar has no `size` prop, and Todae does not ship a size scale, so the stack has none either. The avatars draw at `--todae-avatar-size`, and the stack captures that same variable for its overlap. Set the variable to a length on the stack element, and every avatar inside and the overlap follow it. Do not put an element with `data-appearance` or `data-density`, or a scoped theme root, inside that element. A ThemeProvider or a DensityProvider carries one of those attributes. Such an element, or a scoped theme root, declares the size token again, so the avatars return to `avatar.size` while the overlap stays at the size the stack captured. The `.small` and `.large` rules at the end of the stylesheet set explicit lengths. Add one to the stack beside `avatarGroup`, as the example below does.

## Wrapped avatars

Put a tooltip trigger, a link or a button around an avatar when each person is something to act on. The overlap and the focus lift apply to the stack's direct children, so the wrapper takes the avatar's place. Tooltip and Popover content is a sibling of its trigger and carries `popover`, and a `dialog` places itself, so the rules leave both out of the stack. A hover list of everyone in the stack is a [Tooltip](/tooltip) or [Popover](/popover) around the stack, which you write.

```tsx
import { Avatar, Tooltip, useTooltip } from '@tounsoo/todae';
import styles from './AvatarGroup.module.css';

type Person = { id: string; name: string; initials: string };

function AssigneeTip({ person }: { person: Person }) {
  const tooltip = useTooltip();
  return (
    <>
      <button type="button" aria-label={person.name} {...tooltip.getTriggerProps()}>
        <Avatar.Root className={styles.avatar}>
          <Avatar.Fallback>{person.initials}</Avatar.Fallback>
        </Avatar.Root>
      </button>
      <Tooltip.Root {...tooltip.getTooltipProps()}>{person.name}</Tooltip.Root>
    </>
  );
}

function Assignees({ people }: { people: Person[] }) {
  return (
    <div role="group" aria-label="Assignees" className={styles.avatarGroup}>
      {people.map((person) => (
        <AssigneeTip key={person.id} person={person} />
      ))}
    </div>
  );
}
```

## Accessible composition

**Todae handles:** With `label`, `Avatar.Root` is `role="img"` named by `aria-label`, and `Avatar.Image` renders `alt=""`, so the image and the initials share one name.

**You supply:** The `role="group"` and an `aria-label` on the stack, such as "Assignees", so the avatars inside read as one named set. A `label` on each avatar, and on the "+1" avatar a label such as "1 more", so the count is read too. When the names are written next to the stack, leave the avatars unnamed. The copied CSS, which overlaps by the stack size, lifts a focused child, clears the browser box on a button or a link, and swaps the ring for a text-color border in forced colors.

**Watch for:** An avatar with no `label` as the only content of a button or a link: the avatar is hidden, so the control has no name. Give the control `aria-label`. A stack so tight that initials hide each other: show fewer avatars and put the rest in the count.

## When to use

**When:** A few people stacked in a row: assignees, participants, the members of a team.

**When not:** One person or team next to a name → [Avatar](/avatar). Everyone, with names → a list of avatars with the names written beside them. A status or a count with no people → [Badge](/badge).
