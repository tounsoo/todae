# Data table

A recipe, not a package namespace. A data table is a [Table](/table) with sortable columns, a checkbox on each row from [useSelection](/utilities/use-selection), bulk actions in a [Toolbar](/toolbar), [Pagination](/pagination) and an [EmptyState](/empty-state) for no results. Which rows load, how they filter and sort, and what the actions do are your product's. There is no `DataTable.*` export.

Search, sort by a column, page through, select rows on more than one page, then mark them paid or delete them.

## Rows

Work out the rows in one place: filter, then sort, then cut out the page. With data on a server, send the query, sort and page in a request and render the rows it returns. Go back to the first page when the search or sort changes, and keep the page in range when rows go away.

```ts
const needle = query.trim().toLowerCase();
const matches = rows
  .filter((row) => `${row.id} ${row.customer}`.toLowerCase().includes(needle))
  .sort((a, b) => (sorted.direction === 'ascending' ? 1 : -1) * compare(a, b, sorted.column));
const pageCount = Math.max(1, Math.ceil(matches.length / PAGE_SIZE));
const current = Math.min(page, pageCount);
const pageRows = matches.slice((current - 1) * PAGE_SIZE, current * PAGE_SIZE);
```

## Sorting

Keep one sorted column and its direction. Each sortable `Table.HeaderCell` takes `'ascending'` or `'descending'` when it is that column and `'none'` when it is not, and its `Table.SortButton` sets the column. The button announces the new order, as the [Table](/table) page says.

```tsx
const sortOf = (column: Column): TableSort => (sorted.column === column ? sorted.direction : 'none');

<Table.HeaderCell scope="col" sort={sortOf('customer')}>
  <Table.SortButton onClick={() => sortBy('customer')}>Customer</Table.SortButton>
</Table.HeaderCell>
```

## Selecting across pages

Pass the keys of the rows on the current page to `useSelection`. Selected keys on other pages stay selected, so the header checkbox selects or clears only this page, and `selection.value` holds every selected key. Show that count beside the actions, so people know an action reaches rows they can't see. Clear the selection when the search changes, so an action never reaches a row the search hides.

```tsx
const selection = useSelection({ keys: pageRows.map((row) => row.id) });

<Checkbox.Root ref={selectAll} {...selection.getSelectAllProps()}>
  <VisuallyHidden.Root>Select all invoices on this page</VisuallyHidden.Root>
</Checkbox.Root>
```

## Bulk actions

Put the actions in a `Toolbar.Root` named after what they act on, and keep it in place while nothing is selected, with its buttons disabled, so the table doesn't move as rows are checked. Announce what an action did through [useAnnouncer](/utilities/use-announcer). Confirm a delete with a `Dialog.Root role="alertdialog"`. Deleting clears the selection, which disables the Delete button the dialog would give focus back to, so `restoreFocusRef` names another place: the header checkbox while rows still match the search, else the search. Cancel leaves `restoreFocusRef` empty, and focus goes back to Delete.

```tsx
const selectAll = useRef<HTMLInputElement>(null);
const restoreFocus = useRef<HTMLElement>(null);

const remove = () => {
  const ids = new Set(selection.value);
  const shown = matches.filter((row) => !ids.has(row.id)).length;
  restoreFocus.current = shown > 0 ? selectAll.current : search.current;
  setRows(rows.filter((row) => !ids.has(row.id)));
  setPage(Math.min(current, Math.max(1, Math.ceil(shown / PAGE_SIZE))));
  selection.clear();
  setConfirming(false);
  announce(`${ids.size} deleted`);
};

<Toolbar.Root aria-label="Selected invoices">
  <Button.Root variant="secondary" disabled={selection.value.length === 0} onClick={markPaid}>
    Mark paid
  </Button.Root>
  <Button.Root
    variant="secondary"
    disabled={selection.value.length === 0}
    onClick={() => {
      restoreFocus.current = null;
      setConfirming(true);
    }}
  >
    Delete
  </Button.Root>
</Toolbar.Root>
<Dialog.Root role="alertdialog" open={confirming} onOpenChange={setConfirming} restoreFocusRef={restoreFocus}>
  <Dialog.Title>{`Delete ${selection.value.length} invoices?`}</Dialog.Title>
  <Dialog.Description>Deleted invoices can't be restored.</Dialog.Description>
  <Dialog.Footer>
    <Dialog.Close>Cancel</Dialog.Close>
    <Button.Root onClick={remove}>Delete</Button.Root>
  </Dialog.Footer>
</Dialog.Root>
```

## No results

When nothing matches, render one row whose cell spans every column and holds an `EmptyState.Root`, so the table keeps its caption and headers. The empty state has no role, so announce the number of matches once typing settles, as the [EmptyState](/empty-state) page does. Announce on a new search only, so a delete's own message isn't followed by a count. "Clear search" moves focus back to the search before its own button goes away.

```tsx
import { SearchX } from 'lucide-react';

const announce = useAnnouncer();
const searched = useRef(query);

useEffect(() => {
  const timer = setTimeout(() => {
    if (searched.current === query) return;
    searched.current = query;
    announce(matches.length === 0 ? 'No invoices found' : `${matches.length} found`);
  }, 500);
  return () => clearTimeout(timer);
}, [query, matches.length, announce]);

<Table.Row>
  <Table.Cell colSpan={5}>
    <EmptyState.Root>
      <EmptyState.Icon>
        <SearchX />
      </EmptyState.Icon>
      <EmptyState.Title as="h3">No invoices found</EmptyState.Title>
      <EmptyState.Description>Nothing matches “{query}”.</EmptyState.Description>
      <EmptyState.Actions>
        <Button.Root variant="secondary" onClick={clearSearch}>
          Clear search
        </Button.Root>
      </EmptyState.Actions>
    </EmptyState.Root>
  </Table.Cell>
</Table.Row>
```

## Pages and narrow screens

Page with `Pagination.Root` and buttons, and render it only when there is more than one page. Mark the current page with `aria-current="page"` and a step with nowhere to go with `aria-disabled="true"`, which keeps its focus at an end, as the [Pagination](/pagination) page says. The buttons swap the rows in place, so announce the new page. Wrap the table in a `ScrollArea.Root` with `axis="inline"`, `focusable` and an `aria-label`, so a table wider than the screen scrolls sideways and keyboard users can scroll it too.

```tsx
const goTo = (to: number) => {
  setPage(to);
  announce(`Page ${to} of ${pageCount}`);
};

const step = (to: number, label: string) => (
  <Pagination.Item>
    <button
      type="button"
      aria-disabled={to < 1 || to > pageCount ? true : undefined}
      onClick={() => to >= 1 && to <= pageCount && goTo(to)}
    >
      {label}
    </button>
  </Pagination.Item>
);

<ScrollArea.Root axis="inline" focusable aria-label="Invoices table">
  <Table.Root>…</Table.Root>
</ScrollArea.Root>
{pageCount > 1 && (
  <Pagination.Root aria-label="Invoice pages">
    {step(current - 1, 'Previous')}
    {paginationRange({ page: current, count: pageCount }).map((item) =>
      typeof item === 'number' ? (
        <Pagination.Item key={item}>
          <button type="button" aria-current={item === current ? 'page' : undefined} onClick={() => goTo(item)}>
            {item}
          </button>
        </Pagination.Item>
      ) : (
        <Pagination.Ellipsis key={item} />
      ),
    )}
    {step(current + 1, 'Next')}
  </Pagination.Root>
)}
```

## Accessible composition

**Todae handles:** The native table, its caption and its row and column headers. `aria-sort` on the sorted column, and an announcement after a `Table.SortButton` click. Each row checkbox's checked state, the header checkbox's mixed state, and Shift ranges, through `useSelection`. One tab stop and arrow keys for the bulk actions in `Toolbar.Root`. The confirmation's role, its first focus on Cancel, and focus sent to `restoreFocusRef` after it closes, in `Dialog.Root`. The `nav` landmark of `Pagination.Root`, and the look of a current page and of a step with nowhere to go. Sideways scrolling by keyboard in `ScrollArea.Root`.

**You supply:** The filtering, sorting, paging and actions. A name for the table, the toolbar, the pagination and the scroll area, and for each checkbox one that says which row it selects. `aria-current="page"` and `aria-disabled="true"` on the page buttons. Announcements for the number of matches, the new page and what an action did. A place for focus when an action disables the button that had it, and before "Clear search" goes away.

**Watch for:** Disabling a focused button by clearing the selection without moving focus first. A focus target that a search can empty, such as a header checkbox with no matching rows, which turns disabled too. A selection that reaches rows the person can't see, on another page or hidden by a search, without a count that says so. A destructive action with no confirmation or undo. A row made clickable with `onClick` on `Table.Row`, which takes no focus: put a link or button in a cell.

## When to use

**When:** Records people search, sort, page through and act on in bulk, such as invoices, orders or members.

**When not:** A short table people only read → a plain [Table](/table). One record's fields → [DataList](/data-list). Cell editing, column resizing, virtual scrolling or arrow keys between cells → a data grid, which is out of scope for Todae.
