# Event calendar

A recipe, not a package namespace. An event calendar shows events on a month, on a week of day columns, or on one day, in one time zone. In the week and the day, each day is a lane of its visible hours, and an event is a block on the lane its start and end fall in. There is no `EventCalendar.*` export.

The example is the week of 16 November 2026 in `America/Los_Angeles`, open from 8:00 to 18:00. Switch to Month to see that month, to Day to see one column, and use Previous and Next to move. Thursday is a busy day: overlapping events sit side by side.

## The time lanes

`daySegments()` builds one lane per visible day, open from `opens` to `closes` in `timeZone`. Units are elapsed minutes from that day's opening, so a day the clock changes is as long as it really is, and the night stays off the lane. `toUnits()` and `fromUnits()` turn a `Temporal.ZonedDateTime` into a point on that lane and back. A start at a shared midnight belongs to the later day, and an end belongs to the earlier day.

`weekOf()` returns the seven days that contain a day, starting on the locale's first day of the week, the same day Calendar starts on. English and Korean start on Sunday. The week view passes those seven days to `daySegments()`, and the day view passes the one day on screen. Every column is as tall as the longest lane, so a minute is the same height in each column. `hourMarks()` lists each hour from that lane's opening through the last hour that starts before the close. Each column draws those lines itself. The gutter names an hour only when every column has that same wall time at that offset. A column that differs names the hour inside the column.

## The event block

`visibleSpans()` keeps the part of each event that falls inside a lane and drops the rest. An event that starts before the opening is drawn from the opening, and one that runs past the close stops at the close. An event that meets two days becomes one block on each day. An all-day event is left out, and so is an event that only touches a lane at an endpoint. `spanFrame()` turns a span into a top and a height as fractions of the shared length, so nothing is measured.

`placeOverlaps()` packs one lane's spans into columns. Spans that overlap in time, including a chain where each one overlaps the next, share that cluster's column count. Each span takes the first column that is free when it starts. When two start together, the longer one takes the column on the left. A span may widen into columns on its right that nothing else uses while it runs. The left edge and the width are fractions of the lane, so nothing is measured. Spans that only touch at an endpoint each keep the full width, one after the other. A span with no length overlaps a span only when its instant is strictly inside that span, and two spans with no length at the same instant do not overlap. The grid does not draw a span with no length, because `visibleSpans()` drops it. Each day column is at least 5.5rem wide, and another 4rem for every column in that day's busiest cluster, so a busy week scrolls sideways.

The block is a [Menu](/menu) button. Its name is the title, then the event's own start and end, written with `formatTime`. When the start or the end falls on another day, the name includes that day in the same form as the column heading. A block the visible hours clip says "started earlier" or "continues", and the text shows "…" on that side. A block shorter than 45 minutes shows the title only. Drag the block to move the event. Drag the top or bottom edge to change that end. The edges are not keyboard controls. The menu is.

`findConflicts()` lists other occurrences that overlap an event in time. Touching at an endpoint is not an overlap. `placeOverlaps()` uses that same test on the lane's minutes.

## The month

Month sits beside Week and Day. The switch lists Month, then Week, then Day. It shows one month in `timeZone`. `eventsOnDay()` lists the events that overlap a calendar day, from that midnight up to the next midnight. An event that ends on the next midnight stays on the earlier day. An all-day event is included here. The time lanes still leave it out. All-day events come first, then earlier starts, then titles.

[Calendar](/calendar) draws the day buttons through `Calendar.Grid`, and `Calendar.Header` names the focused month and moves to the previous or next month. `renderDay` draws up to two titles in each day, in the same colors as an event block, and writes `+N more` as text when the day has more. Those titles and that count are the button's description. The button's name stays the full date. Nothing inside the day is a control. The day number sits at the top of every cell, and each title spans the cell. When the month is narrower than 30rem, a day shows a dot and the number of events instead of the titles, so `+N more` is never cut off. The titles stay in the description.

Press a day, or press Enter or Space while it is focused, and the view switches to that day. Focus moves to the day's first event. When the day has no event on the time lane, focus moves to the day heading. Arrow keys move a week. Page Up and Page Down move a month, and with Shift they move a year. The header's label and the grid's name follow the focused month. Switching to Week or Day keeps that day. The week is the one that contains it. Previous and Next keep focus on the button that was pressed.

An event that covers more than one day shows its title on each of those days. A bar that runs across the days is not part of this view.

`showOutsideDays` draws the days that lead and trail the month, so each week is a full row. The days that lead and trail the month stay pressable and show their events. A press opens that day.

## Dragging

In the week and the day, [`useLaneDrag`](/utilities/use-lane-drag) runs on `axis: "block"`. Each day column is a lane. Every lane covers one shared range, the longest day's open minutes, which is the height of the columns. A drag snaps to a 15 minute slot. A move keeps the event's length, including any part the lane clips, and can land on another day in the week. A resize stays on the day it started and writes the edge that was dragged. Escape cancels the drag and leaves the event where it was.

`useLaneDrag` reads that one shared range. When a clock change falls inside the visible hours, a day is shorter than the range. A place past that day's close is blocked, so the drop does not land. A resize cannot cross into the next day. The library keeps a resize on the lane where it started.

The menu on each event makes every move a drag can make. It moves the event one slot earlier or later, and, in the week, to the previous or next day. It lengthens or shortens the event by one slot, from the end. An item that would leave the day's open hours is unavailable. The day view has no previous or next day, because that board has one lane. After each item, focus returns to the event. A live region reads the new time, and the button's name reads it too.

## Editing

Edit… opens a [Dialog](/dialog). The fields are the title, the date, the start, the end date, the end, and an all-day switch, using [Field](/field) date and time inputs. Changing the date or the start keeps the length and moves the end with it. Save writes the event and returns focus to it, or to that day's heading when the event is off the time lanes. Cancel and Escape leave it as it was. The end has to be after the start. When it is not, the end field shows "End must be after the start." An all-day event covers that date, from midnight to the next midnight, and leaves the time lanes. The month still lists it.

`EventEditor` is that dialog. It takes the event to edit and calls `onSave` with the edited event. A later drag that creates an event can open the same dialog.

## Accessible composition

**Todae handles:** [ToggleGroup](/toggle-group) switches Month, Week and Day and keeps one selected. [Button](/button) moves to the previous or next week or day. [Calendar](/calendar) draws the month, names the focused month from `Calendar.Header`, keeps one tab stop, names each day with the full date, and reads that day's titles as the description. [ScrollArea](/scroll-area) scrolls the week and the day and keeps a focused block's ring in view. [Text](/text) clamps the title and the time. [`useLaneDrag`](/utilities/use-lane-drag) moves and resizes a block with the pointer, snaps it to the slot grid, and cancels on Escape. [Menu](/menu) is the keyboard path for those same changes. [Dialog](/dialog) and [Field](/field) edit the exact title and time. The event button takes its focus ring from Button. A live region reads the time after a change.

**You supply:** A title for each event. A time zone and the visible hours. Day headings that name each column and the list of events in it. An accessible name on each event that starts with the title and includes the event's real start and end, not only the hours on screen. The 15 minute slot, and a check that the end is after the start.

**Watch for:** An event named only by its color. Times written in the browser's zone when the calendar's zone is the one that matters. A week of columns with nowhere to scroll on a narrow screen. An all-day event drawn on the time grid. A day column fixed so narrow that side-by-side blocks are squeezed to a letter. A control inside a month day. The day button is the only interaction there. A drag with no keyboard path. A resize that tries to cross a day. An end that is not after the start, with nothing saying so.

## When to use

**When:** People look at events across a month, a week, or a day in one time zone, such as a team's calendar.

**When not:** Items on parallel resource lanes, with conflicts across lanes → the [Scheduler](/recipes/scheduler) recipe. Picking one date or time → the [Date and time picker](/recipes/date-time-picker) recipe.
