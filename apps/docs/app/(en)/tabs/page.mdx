# Tabs

Panels that share one place on the page, one shown at a time. `Tabs.Root` owns the selected value. `Tabs.List` is the `role="tablist"`; each `Tabs.Tab` is a native button with `role="tab"`, and each `Tabs.Panel` is a `role="tabpanel"` labelled by its tab. A tab and a panel pair by `value`.

The list holds one tab stop, on the selected tab. Arrow keys, Home and End move between tabs through [useRovingFocus](/utilities/use-roving-focus). Left and Right swap in a right-to-left page. A disabled tab is a native `disabled` button, so arrow keys skip it.

<Example of={TabsBasic} block />

The indicator slides from the old tab to the new one over `tabs.motion.duration`, in browsers with CSS anchor positioning. In other browsers, and when the user prefers reduced motion, it moves at once.

A horizontal list that holds more tabs than fit scrolls sideways, in one row. An arrow shows at each edge where tabs are cut off; resting a mouse or pen on it scrolls that way. The arrows are for the pointer only: touch, a wheel and the arrow keys scroll the list as before, a tab that takes focus scrolls clear of them, and assistive technology never meets them. Pass `arrows={false}` to leave them out. A selected tab past the edge, on the first render or chosen by your code, scrolls into view. A vertical list doesn't scroll.

`activation="automatic"` (default) selects a tab as soon as focus moves to it from another tab. Focus entering the list from outside selects nothing, even when it lands on a fallback tab because the selected one is disabled. Use `activation="manual"` when a panel is slow to render: arrow keys only move focus, and Enter, Space or a click selects. When focus leaves the list, its tab stop returns to the selected tab. `orientation="vertical"` puts the list beside the panels and moves with Up and Down.

The root takes `value` with `onValueChange`, or `defaultValue`. One tab is always selected, so there is no empty state. Only the selected panel renders its children; pass `keepMounted` to keep a hidden panel's state, such as a half-filled form. A panel is a Tab stop by default, so a screen reader user reaches its text; pass `tabIndex={-1}` when the panel starts with a control of its own.

There is no native tabs element. An exclusive `<details name>` group looks similar but has no tab semantics or arrow keys, so it is an accordion, not tabs.

## Accessible composition

**Todae handles:** `Tabs.List` is the `role="tablist"` with `aria-orientation`. Each `Tabs.Tab` is a button with `role="tab"`, `aria-selected` and `aria-controls`, and each `Tabs.Panel` is a `role="tabpanel"` whose `aria-labelledby` points at its tab. Todae makes the ids that pair them, so neither part takes an `id`. It keeps at most one tab stop in the list, makes each panel a Tab stop by default, and hides unselected panels with `hidden`, even against a `display` in your own class.

**You supply:** A name for the list: `aria-label`, or `aria-labelledby` pointing at a visible heading. The type does not require one. Tab text that names its panel, since the panel takes its name from the tab; an icon-only tab needs `aria-label`. One `Tabs.Panel` for each `Tabs.Tab`, with the same `value`.

**Watch for:** A panel whose `value` matches no tab: its `aria-labelledby` points at an id that does not exist. A disabled tab is skipped by the arrow keys, so a reason it is unavailable needs to show somewhere else. A selected tab marked by color alone after restyling.

## When to use

**When:** Switch between sibling views of the same object in one place, such as settings sections or report views, where one view shows at a time.

**When not:** Moving to another page → links. A list of actions → Menu. Several sections open at once, or long content read top to bottom → headings or `<details>`.
