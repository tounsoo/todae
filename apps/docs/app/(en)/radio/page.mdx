# Radio

Exclusive choice that stays on the page. `RadioGroup.Root` owns the value, the shared `name`, `disabled`, and `invalid`. `RadioGroup.Item` cannot take `checked` or `name`. An item outside a root throws.

The group type requires `aria-label` or `aria-labelledby`. A `role="radiogroup"` div is not a labelable control, so do not point `Label.Root htmlFor` at the group. Caption it with `Text.Root` and `aria-labelledby`, and put both in a `Field.Group` to space the caption from the group.

`value={null}` is controlled with nothing selected. Omit `value` for uncontrolled.

```tsx
const captionId = useId();

<Field.Group>
  <Text.Root as="span" id={captionId} weight="medium">Plan</Text.Root>
  <RadioGroup.Root aria-labelledby={captionId} value={plan} onValueChange={setPlan}>
    <RadioGroup.Item value="free">Free</RadioGroup.Item>
    <RadioGroup.Item value="pro">Pro</RadioGroup.Item>
  </RadioGroup.Root>
</Field.Group>
```

Same-name native radios move focus with arrow keys. The group does not add a keyboard handler.

Use Radio when the options stay visible. Use [OptionList](/optionlist) when the options live in a popover or sheet. Wiring both to the same value is a QA fail.

## Accessible composition

**Todae handles:** `RadioGroup.Root` renders a `div` with `role="radiogroup"`, `aria-orientation`, and `aria-disabled` and `aria-invalid` when they apply. Its type requires `aria-label` or `aria-labelledby`. Each `RadioGroup.Item` is a native radio inside a `<label>` with your children. The items share a `name`, generated when you pass none, so the browser gives the group one tab stop and the arrow keys described above. Items get native `disabled` and `aria-invalid` from the group, which also takes them from a surrounding [Fieldset](/fieldset).

**You supply:** The group's name: a visible caption with an id in `aria-labelledby`, or `aria-label`. Children on every item. For an error, `invalid` and the [ErrorMessage](/errormessage) id in the root's `aria-describedby`. When you wrap the root, keep its props type whole so the name stays required:

```tsx
type PlanPickerProps = RadioGroupRootProps & { plans: readonly string[] };

function PlanPicker({ plans, ...group }: PlanPickerProps) {
  return (
    <RadioGroup.Root {...group}>
      {plans.map((plan) => (
        <RadioGroup.Item key={plan} value={plan}>{plan}</RadioGroup.Item>
      ))}
    </RadioGroup.Root>
  );
}
```

**Watch for:** `Omit<RadioGroupRootProps, …>` turns the naming union into two optional props, so a wrapper built on it compiles without a name. `Label.Root htmlFor` does not name a `radiogroup` div. Two groups with the same `name` in one form are one set to the browser's arrow keys.

## When to use

**When:** Exclusive choice that stays visible on the page. Group owns value/name; caption via `aria-label` / `aria-labelledby`.

**When not:** Independent toggles → Checkbox. Overlay list → OptionList. Same value also wired to OptionList (dual-wire = fail).
