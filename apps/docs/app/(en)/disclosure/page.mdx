# Disclosure

`Disclosure.Root` is a native `<details>` and `Disclosure.Summary` a native `<summary>`, styled from the `disclosure` contract tokens. The browser handles the keyboard, the expanded state that a screen reader announces, find-in-page into closed content, and the open marker.

```tsx
<Disclosure.Root>
	<Disclosure.Summary>Shipping details</Disclosure.Summary>
	<Text>Orders ship within two business days.</Text>
</Disclosure.Root>
```

Server Components can import it from `@omsoo/todae/disclosure`.

## Accordion

Give disclosures the same `name` and the browser keeps at most one of them open: an exclusive accordion. Named disclosures get a divider from `disclosure.border`. Use `open` to start one open, and `onToggle` to follow changes.

```tsx
<Disclosure.Root name="faq" open>
	<Disclosure.Summary>What is Todae?</Disclosure.Summary>
	…
</Disclosure.Root>
<Disclosure.Root name="faq">
	<Disclosure.Summary>Does it ship icons?</Disclosure.Summary>
	…
</Disclosure.Root>
```

The marker is the browser's own and turns as the disclosure opens; to draw an icon instead, see Icons below. Content fades in over `disclosure.motion.duration`, and in browsers with `interpolate-size` it also grows to its height. Neither happens when the user prefers reduced motion.

## Icons

With a `chevron` glyph from a [GlyphsProvider](/utilities/glyphs-provider), the summary draws that icon in place of the browser's marker. Draw it pointing down: a closed disclosure turns it toward the text. `Disclosure` from the `@omsoo/todae/disclosure` server entry reads no provider and keeps the browser's marker.

```tsx
import { ChevronDown } from 'lucide-react';

<GlyphsProvider glyphs={{ chevron: <ChevronDown /> }}>
	<Disclosure.Root>
		<Disclosure.Summary>Shipping</Disclosure.Summary>
		…
	</Disclosure.Root>
</GlyphsProvider>
```

## Accessible composition

**Todae handles:** A focus ring on the summary, the marker's color, a chevron glyph hidden from screen readers, a divider between named disclosures, and no motion when the user prefers reduced motion. The rest is the browser's: the toggle on the summary, its expanded state, Enter and Space, closing the others in a named group, and find-in-page.

**You supply:** A `Disclosure.Summary` as the first child of each `Disclosure.Root`, with text that names what opens. If you put an icon of your own in the summary instead of a chevron glyph, give it `aria-hidden="true"`; the open state is already announced.

**Watch for:** A `role`, an `aria-expanded` or a click handler that toggles `open` on the summary: the browser already does each, and doing it again fights it. Buttons or links inside the summary, which is itself the control.

## When to use

**When:** Optional detail the reader can open in place: FAQs, advanced settings, long explanations. Several of them with one open at a time → an accordion with a shared `name`.

**When not:** Views of the same object, one shown at a time with arrow keys → Tabs. A choice or a form that blocks the task → Dialog. Content most readers need → show it.
