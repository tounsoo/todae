# Spinner and Skeleton

Two class utilities in the `todae.base` layer for content that is still loading. There is no component: a spinner is a native `<progress>`, and a skeleton is any element with a class.

## Spinner

Put `todae-spinner` on a `<progress>` with no `value`. It keeps the progressbar role, so screen readers announce it as a progress bar, and it needs a name like any progress: wrap it in a `<label>` with the text, or give it `aria-label`. The bar becomes a ring with one arc of fill that turns, and it holds still when the user asks for reduced motion. Give it a `value` and it stays a bar, so what shows matches what is announced.

<Example>
  <SpinnerLabelled />
</Example>

```tsx
<label>
  <progress className="todae-spinner" /> Loading invoices
</label>

<progress className="todae-spinner" aria-label="Saving" />
```

It draws in the text color, so it shows on any surface, a primary button included: set `color` to change it. Restyle it through `spinner.size`, `spinner.thickness`, `spinner.track-tint` (how much of the text color the track takes) and `spinner.motion.duration`.

## Skeleton

Put `todae-skeleton` on a block that stands in for content before it arrives. It is at least one line high, and elements inside it only give it a size: they are hidden. It pulses, and holds still under reduced motion.

<Example block>
  <SkeletonProfile />
</Example>

```tsx
<div>
  <span className="todae-visually-hidden">Loading profile</span>
  <Stack direction="row" aria-hidden="true">
    <div className="todae-skeleton" style={{ inlineSize: '2.5rem', blockSize: '2.5rem', borderRadius: '50%' }} />
    <Stack style={{ flex: 1 }}>
      <div className="todae-skeleton" style={{ inlineSize: '40%' }} />
      <div className="todae-skeleton" style={{ inlineSize: '70%' }} />
    </Stack>
  </Stack>
</div>
```

A skeleton means nothing to a screen reader, so hide it with `aria-hidden` and say what is loading in text. Restyle it through `skeleton.bg`, `skeleton.radius` and `skeleton.motion.duration`.

## Accessible composition

**Todae handles:** Style only. A `todae-spinner` stays a native `<progress>` with the `progressbar` role, and turns only while it has no `value`. It holds still under reduced motion. A `todae-skeleton` hides the elements inside it with `visibility: hidden`, which also hides them from assistive technology, but bare text directly inside it is only made transparent and is still read.

**You supply:** A name for each spinner, from a `<label>` or `aria-label`, that says what is loading. `aria-hidden` on each skeleton, with the loading text next to it, such as in `todae-visually-hidden` text, as above. When the content arrives, it replaces both.

**Watch for:** `todae-spinner` on a `div` or an `svg`: the rules match only `progress`, so it neither turns nor has a role. A spinner with `aria-hidden` and no other text, so nothing says the area is busy. A spinner in every row of a list, each read as a progress bar; one spinner for the whole area reads better.

## When to use

**When:** Spinner → a short wait for one action or a small area, such as a save or a search. Skeleton → the layout of a page or section is known before its content arrives.

**When not:** The wait has a known end → [Progress](/progress) with a `value`. The wait is long or can fail → say so in text, with a way to cancel or retry.
