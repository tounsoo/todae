# Field.ColorPicker

`Field.ColorPicker` is a button inside a [Field](/field), drawn as a swatch one field line tall and filled with its color. It opens a [ColorPicker](/color-picker) in a [Popover](/popover). Its value is a `#rrggbb` string, and `onValueChange` gets each new color as it is dragged or keyed.

```tsx
<Label.Root htmlFor={id}>Accent</Label.Root>
<Field.Root id={id}>
	<Field.ColorPicker
		value={color}
		onValueChange={(next) => {
			setColor(next);
			setText(next);
		}}
	/>
	<Field.TextInput
		value={text}
		onChange={() => undefined}
		onValueChange={(next) => {
			setText(next);
			const hex = normalizeHex(next);
			if (hex) setColor(hex);
		}}
		onBlur={() => setText(color)}
	/>
</Field.Root>
```

Here a `Field.TextInput` in the same field lets people type the color too. The two share state: a picked color sets the text, and [`normalizeHex`](/color-picker) turns typed text into a color when it is one. Beside a `Field.TextInput`, that input is the field's control. It takes the field's `id` and description, and a press elsewhere in the field focuses it. A `Field.Textarea`, `Field.ChipInput`, `Field.Select`, `Field.DateInput`, `Field.TimeInput` or `Field.DateTimeInput`, or a control joined with [`useField`](/utilities/use-field), takes the `id` and description in the same way. The swatch sends the color with a form under its own `name` if it has one, and otherwise under the field's `name`, unless one of these controls has that `name`, as a `Field.TextInput` does when it has no `name` of its own.

On its own, `Field.ColorPicker` is the field's control, a press elsewhere in the field opens the picker, and the field is as wide as the swatch. Put the value after it in a `Field.Affix` to show it as text.

The picker opens and closes through `open` with `onOpenChange`, or `defaultOpen`. `onOpenChange` gets the reason it closed: `'escape'`, `'outside'`, `'trigger'`, or `'disabled'` when the field becomes disabled. Open, the picker takes focus, and Escape there closes it and returns focus to the swatch.

## Accessible composition

**Todae handles:** On its own, the button takes `id`, `aria-label`, `aria-labelledby` and `aria-describedby` from `Field.Root`, and native `disabled` and `aria-invalid` from the Root or a surrounding [Fieldset](/fieldset). Beside one of the controls above, that control takes the `id` and `aria-describedby` in its place, and the button keeps `disabled` and `aria-invalid` and is named from the `colorPicker` string in [StringsProvider](/utilities/strings-provider) unless it has its own `aria-label`. It gets `aria-haspopup="dialog"` and `aria-expanded`, and `aria-controls` while the picker is open. The popover is a `role="dialog"` named from the `colorPicker` string in [StringsProvider](/utilities/strings-provider), and its inputs are named and keyed as on [ColorPicker](/color-picker).

**You supply:** A name, through a [Label](/label) whose `htmlFor` is the Root `id` or `aria-label` / `aria-labelledby` on the Root.

**Watch for:** The swatch's name is never the color, so a screen reader does not hear the value from the button. Show the value as text, in a `Field.TextInput` or a `Field.Affix`, when people need to read it.

## When to use

### Field.ColorPicker

**When:** Pick one color in a form, such as a brand or accent color.

**When not:** A color in another form, such as `oklch()` → `Field.TextInput`. A picker shown inline, without a field → [ColorPicker](/color-picker). A fixed set of colors → RadioGroup.
