# Field

Shared chrome. `Field.Root` is the compound scope. The bordered shell is Root. Value lives on `Field.TextInput`, `Field.Textarea`, `Field.ChipInput`, `Field.Select` or `Field.ColorInput`. Adornments are order-only: put `Icon` / `Affix` before the input to lead, after to trail. No `side` prop. `Label.Root` is a sibling, not a compound part. Every part inside the field (input, Icon, Affix, chips) is one field line tall, and the shell's padding is the inset.

## Label

`Label.Root` is a sibling, not a compound part. It takes the same `id` you pass to `Field.Root`. Wrap the pair in one `Field.Group`, which puts the label `field.label.gap` above the shell. See [Label](/label) for the API.

```tsx
const id = useId()

<Field.Group>
	<Label.Root htmlFor={id}>Email</Label.Root>
	<Field.Root id={id}>
		<Field.TextInput value={v} onChange={(event) => setV(event.target.value)} />
	</Field.Root>
</Field.Group>
```

## Messages

[Description](/description) and [ErrorMessage](/errormessage) sit under the shell as siblings. They are not Field parts. Put `aria-describedby` on `Field.Root`. Root copies it onto the input.

```tsx
const describedBy = invalid ? `${hintId} ${errorId}` : hintId

<Field.Group>
	<Label.Root htmlFor={id}>Email</Label.Root>
	<Field.Root id={id} invalid={invalid} aria-describedby={describedBy}>
		<Field.TextInput value={email} onChange={(event) => setEmail(event.target.value)} />
	</Field.Root>
	<Description.Root id={hintId}>Use your work address.</Description.Root>
	{invalid ? <ErrorMessage.Root id={errorId}>{error}</ErrorMessage.Root> : null}
</Field.Group>
```

## Textarea

Multi-line text. Height is CSS only: `rows` sets the height and the drag floor, and `maxRows` sets the cap. `autoGrow` uses `field-sizing: content` where the browser has it, and grows with no cap when `maxRows` is omitted. Browsers without `field-sizing` stay at `rows` and scroll inside. Do not set an inline `height` when `autoGrow` is on; it overrides the growth. Padding sits on the textarea, inside the shell.

## Counter

`Field.Counter` shows a live count for `Field.TextInput` or `Field.Textarea`. It takes its own row. Write it after the input so the server HTML includes the count. One counter per `Field.Root`. The input stays controlled; `defaultValue` is not read.

## Chip input

Controlled chips plus input. The field never appends chips. Parent `onCommit` decides. Adornments stay on `Field.Root`, outside the chip flow. Chips inside a ChipInput are one field line tall, the same as the input, at every density. `chipLayout="row"` puts them on a full-width line above the input, inside the ChipInput. Icon and Affix sit on the first line. With no chips it is a one-line field the same height as `Field.TextInput`. In a row, `maxRows` counts chip lines only and clips like the inline flow. Label it with `Label.Root htmlFor` or Root's `aria-label`.

When `maxRows` is set, the flow clamps to that many token-derived rows from the first paint and hides chips until the first layout measure, so SSR does not unfold before `+N` fold. The visible window is the leading prefix; newest chips fold into `+N` and unmount from the live flow. A later chip that does not fit at its full width moves into `+N`. The first chip truncates with an ellipsis when it, `+N`, and the input cannot share the row; its accessible name stays the full label.

Chip remove buttons show the `close` glyph unless you pass `chipRemoveIcon`, as on [Chip](/chip).

Deferred this slice: built-in clear, paste-split, clickable `+N`, chip arrow-key roving.

## Row

A `Field.Row` is a full-width line. Write it before the input to sit above, or after to sit below. Put `Field.Counter` inside the Row when the field has a bottom row. Use `autoGrow` for a composer. Don't put bare text in a Row; wrap it in `Field.Affix`. Push trailing items to the end with `style={{ marginInlineStart: 'auto' }}` on the first of them. For chips, set `chipLayout="row"`; ChipInput draws its own chip line. Don't hand-roll chips in a `Field.Row`.

## Number, date and time

`Field.TextInput` takes `type="number"`, `"date"`, `"time"` and `"datetime-local"`. They stay native inputs, with the browser's own spinner, date picker and locale format, styled from the field tokens with figures lined up. `value` is the input's string: `"2"`, `"2026-10-07"`, `"14:30"`, or an empty string while the input is incomplete. Constrain them with the native `min`, `max` and `step`. `Field.TextInput` never turns the string into a `Date`, so no time zone is applied. When your app needs a date value, parse it with `Temporal.PlainDate.from(value)` (or `PlainTime`, `PlainDateTime` for the other types) rather than `new Date(value)`, which reads `"2026-10-07"` as midnight UTC and shows the previous day in time zones west of UTC.

<Example block>
  <FieldDateTime />
</Example>

Stepper buttons and a calendar grid are app compositions; build them around these inputs when the native ones are not enough.

## Select

`Field.Select` is a native `<select>`. In browsers with `appearance: base-select` the button and its picker are drawn from field and option tokens; elsewhere the browser's own picker shows, with the same value and keyboard. There is no JavaScript listbox. Children are native `<option>` and `<optgroup>` elements, and a `Label.Root htmlFor` names it like any other field.

```tsx
<Label.Root htmlFor={id}>Size</Label.Root>
<Field.Root id={id}>
	<Field.Select value={size} onChange={(event) => setSize(event.target.value)}>
		<option value="s">Small</option>
		<option value="m">Medium</option>
	</Field.Select>
</Field.Root>
```

## Color

`Field.ColorInput` is a native `<input type="color">`, drawn as a swatch one field line tall. Its value is a `#rrggbb` string. A press elsewhere in the field opens the browser's picker. To show the value as text, put a `Field.Affix` after it. On its own, the field is as wide as the swatch.

```tsx
<Label.Root htmlFor={id}>Accent</Label.Root>
<Field.Root id={id}>
	<Field.ColorInput value={color} onValueChange={setColor} />
	<Field.Affix>{color}</Field.Affix>
</Field.Root>
```

## Icons

`Field.Icon` takes an icon from any library; an `svg` or `img` directly inside it takes the `field.icon.size` token. `Field.Select` draws the `chevron` glyph from a [GlyphsProvider](/utilities/glyphs-provider) over the browser's picker icon when the browser supports `::picker-icon` and the select is the field's last part; otherwise, and without a provider, the browser's icon shows. The check mark beside a selected `<option>` is the browser's own. Chip remove buttons in `Field.ChipInput` show the `close` glyph unless you pass `chipRemoveIcon`.

```tsx
import { ChevronDown, Search } from 'lucide-react';

<Field.Root aria-label="Search">
	<Field.Icon>
		<Search />
	</Field.Icon>
	<Field.TextInput />
</Field.Root>

<GlyphsProvider glyphs={{ chevron: <ChevronDown /> }}>
	<Field.Root aria-label="Plan">
		<Field.Select value={plan} onValueChange={setPlan}>
			…
		</Field.Select>
	</Field.Root>
</GlyphsProvider>
```

## Accessible composition

**Todae handles:** `Field.Root` hands its `id`, `name`, `aria-label`, `aria-labelledby` and `aria-describedby` to the input. Other ARIA props stay on the shell `div`. The input gets native `disabled` and `aria-invalid` from the Root, or from a surrounding [Fieldset](/fieldset). A press on the shell focuses the input, and the shell draws the focus ring while the input is focus-visible. A decorative `Field.Icon` is `aria-hidden`. With `maxLength`, `Field.Counter` adds the limit to the input's description and, from 20 characters left, announces what remains. In `Field.ChipInput`, each remove button is named after its chip, and focus returns to the input after a remove.

**You supply:** A name: a [Label](/label) whose `htmlFor` is the Root `id`, or `aria-label` / `aria-labelledby` on the Root. The ids of any [Description](/description) or [ErrorMessage](/errormessage) in the Root's `aria-describedby`, and `invalid` while the error shows. A name for every button inside an interactive `Field.Icon`. Chip and counter strings in the product's language, through [StringsProvider](/utilities/strings-provider).

**Watch for:** An `id` on `Field.TextInput` is replaced by the Root's; put it on the Root. A `role` or `onClick` on `Field.Root` lands on the shell, which is not a control; open overlays from a real button. `invalid` marks the input invalid but does not say why, so show an ErrorMessage with it. Adding `'Tab'` to `commitKeys` makes Tab commit typed text instead of moving focus.

## When to use

### Field.Root

**When:** Shared field chrome for one text, textarea, or chip input — focus ring, disabled/invalid, density. Value lives on the input part.

**When not:** Selection controls (Checkbox / Radio / Switch). Overlay triggers that are buttons. Nesting another compound root inside.

### Field.TextInput

**When:** Single-line typed value inside `Field.Root` (text / search / email / url / tel / password), or a native number, date or time.

**When not:** Multi-value tokens → `Field.ChipInput`. Multi-line → `Field.Textarea`. Standalone without Root.

### Field.Textarea

**When:** Multi-line free text such as notes, messages or descriptions. `rows` sets the starting height, and `autoGrow` grows it up to `maxRows` with CSS only.
**When not:** Single-line values, use `Field.TextInput`. Separate tags or tokens, use `Field.ChipInput`. Rich text or formatting, not shipped.

### Field.ChipInput

**When:** Controlled chips + one input inside `Field.Root`. Parent owns commit/append via `onCommit`, or spreads `getChipInputProps()` from [useChipField](/utilities/use-chip-field) to hold that state.

**When not:** Free-form single string → TextInput. Options from a list → [Combobox recipe](/recipes/combobox) + OptionList.

### Field.Select

**When:** Pick one value from a short, fixed list inside a form, with the native picker and keyboard.

**When not:** Filtering or searching a long list → Combobox recipe. Several values → Checkbox or `Field.ChipInput`. Commands rather than values → Menu.

### Field.ColorInput

**When:** Pick one color with the browser's picker, such as a brand or accent color.

**When not:** A color in another form, such as `oklch()` → `Field.TextInput`, with a `Field.ColorInput` in its own field beside it for picking. A fixed set of colors → RadioGroup.

### Field.Icon

**When:** Leading/trailing icon or icon control inside Root. Position = DOM order. Decorative → `interactive={false}` (aria-hidden).

**When not:** Text adornments → Affix. Clickable clear/reveal as a dedicated Action (not shipped).

### Field.Row

**When:** Group parts on their own full-width line inside the field, such as chips above a `Field.ChipInput` or attach, `Field.Counter` and send below a `Field.Textarea`.

**When not:** For a single Icon or Affix beside the input, compose it inline without a Row, and don't use a Row to lay out separate fields.

### Field.Group

**When:** Stack a label or caption `field.label.gap` above its control, with any Description or ErrorMessage below. It sits outside `Field.Root` and works for any control, such as a RadioGroup under a `Text.Root` caption.

**When not:** To space separate fields from each other, use `Stack.Root`. To group related controls under one legend, use [Fieldset](/fieldset).

### Field.Affix

**When:** Static text adornment (currency, unit) inside Root. Order = position.

**When not:** Icons → Icon. Interactive controls — Affix is not clickable.

### Field.Counter

**When:** Show a live character count for a `Field.TextInput` or `Field.Textarea`, as `n / max` when `maxLength` is set and `n` otherwise.
**When not:** For a hard limit with no visible count, set `maxLength` alone, and skip it on short fixed-length values like codes or PINs.
