# Field.TimeInput

`Field.TimeInput` is a native `<input type="time">` inside a [Field](/field), with the browser's own time picker and locale format. Its `value`, `min` and `max` are a `Temporal.PlainTime`, and `onValueChange` gets a `Temporal.PlainTime`, or `null` while the input is empty or incomplete. A `PlainTime` has no date or time zone. `step` is the native one, in seconds. Put `id` on `Field.Root`.

```tsx
const id = useId();
const [time, setTime] = useState<Temporal.PlainTime | null>(null);

<Field.Group>
  <Label.Root htmlFor={id}>Start time</Label.Root>
  <Field.Root id={id}>
    <Field.TimeInput value={time} onValueChange={setTime} />
  </Field.Root>
</Field.Group>
```

## A date and time

A date and time on the user's clock, such as when a meeting starts, is a [Field.DatePicker](/field/date-picker) and a `Field.TimeInput`, each in its own field, grouped by a [Fieldset](/fieldset). Once both are set, `date.toPlainDateTime(time)` joins them into a `Temporal.PlainDateTime`, which has no time zone. To store an instant, combine it with a time zone in your own code, such as `dateTime.toZonedDateTime(zone)`.

```tsx
const dateId = useId();
const timeId = useId();
const [date, setDate] = useState<Temporal.PlainDate | null>(null);
const [time, setTime] = useState<Temporal.PlainTime | null>(null);
const start = date && time ? date.toPlainDateTime(time) : null;

<Fieldset.Root>
  <Fieldset.Legend>Meeting starts</Fieldset.Legend>
  <Stack.Root direction="row">
    <Field.Group>
      <Label.Root htmlFor={dateId}>Date</Label.Root>
      <Field.Root id={dateId}>
        <Field.DatePicker value={date} onValueChange={setDate} placeholder="Pick a date" />
      </Field.Root>
    </Field.Group>
    <Field.Group>
      <Label.Root htmlFor={timeId}>Time</Label.Root>
      <Field.Root id={timeId}>
        <Field.TimeInput step={900} value={time} onValueChange={setTime} />
      </Field.Root>
    </Field.Group>
  </Stack.Root>
</Fieldset.Root>
```

## Temporal

Todae ships no Temporal polyfill. `onValueChange` reads the input with `Temporal`, so where the browser has no Temporal, the app loads a polyfill (see [Native platform](/platform)). Todae's types need TypeScript 6 or later, which declares `Temporal`.

## Accessible composition

**Todae handles:** The input takes `id`, `name`, `aria-label`, `aria-labelledby` and `aria-describedby` from `Field.Root`, and native `disabled` and `aria-invalid` from the Root or a surrounding [Fieldset](/fieldset). The browser handles the keyboard and the picker.

**You supply:** A name, through a [Label](/label) whose `htmlFor` is the Root `id` or `aria-label` / `aria-labelledby` on the Root. `onChange` or `onValueChange`; without either, the input is read-only.

**Watch for:** While the user is still filling in the input, `onValueChange` gets `null`, so don't treat `null` as a cleared field until they leave it.

## When to use

### Field.TimeInput

**When:** A time of day with no date, such as opening hours or a daily reminder.

**When not:** A time on a given day → this input beside a `Field.DatePicker`, as above. A duration → `Field.TextInput` with `type="number"` and an `Affix` for the unit.
