# Field.DateTimeInput

`Field.DateTimeInput` is a text input inside a [Field](/field) that people type a date and a time into, in the locale's own way. Its `value` is a `Temporal.PlainDateTime` or `null`. It reads the text when it is committed, on blur, on Enter or when its form is submitted, rewrites it as `formatDateTime` writes the value and calls `onValueChange` with it. Typing alone calls nothing. Without `onValueChange`, the input is read-only. It works like [Field.DateInput](/field/date-input) and [Field.TimeInput](/field/time-input), and takes the same props where they mean the same thing. A `PlainDateTime` has no time zone: it is the date and time on the user's clock. To store an instant, combine it with a time zone in your own code, such as `value.toZonedDateTime(zone)`.

On its own, `Field.DateTimeInput` is the field's control, with no button. To pick the value too, put a [Field.Picker](/field/picker) beside it with a [Calendar](/calendar) and an [OptionList](/optionlist) of times. There is no date-and-time panel: the [Date and time picker](/recipes/date-time-picker) recipe composes one, keeping the time when a day is picked and the day when a time is picked, and closing the picker once both are set.

## Typed dates and times

`formatDateTime` writes the date in numbers and the time in hours and minutes, such as `10/13/2026, 9:30 PM` in `en-US`, and `parseDateTime` reads a date and a time typed in the order the locale writes them, such as `Oct 13, 2026 at 9:30 PM`. [formatDateTime and parseDateTime](/utilities/format-date-time) says what each writes and reads.

`Field.DateTimeInput` reads its text with `parseDateTime` and writes it with `formatDateTime`, in its `locale`. Empty text commits `null`. Text that is not a date and time stays as it was typed, `onValueChange` is not called, and the field is marked invalid once a commit has tried to read it; until the text is a date and time or empty, the form can't be submitted.

## In a form

The value goes with a form in a native `<input type="datetime-local">` beside the text input, under the field's `name`, or the input's own `name`, the way HTML writes one, such as `2026-10-13T09:30`. The text input sends nothing, and the native input is hidden from sight and from assistive technology and is not a tab stop. `required` makes a form with no value invalid, and `min` and `max` make a form with an earlier or later one invalid. The browser checks all three on the native input, and text that is not a date and time blocks the submit too. Inside a [Form.Root](/form), a problem shows in the field's `ErrorMessage.Root` in the page's language, with `min` or `max` written as `formatDateTime` writes them, and focus goes to the text input. Outside a `Form.Root` the browser blocks the submit and focus lands on the text input too. A native date input holds only the years 1 to 275760, so a value or bound outside them reads as no value: it is sent empty, `required`, `min` and `max` ignore it, and development builds warn once.

## Temporal

Todae ships no Temporal polyfill. The input's value, `formatDateTime` and `parseDateTime` are `Temporal.PlainDateTime`, so where the browser has no Temporal, the app loads a polyfill (see [Native platform](/platform)). Todae's types need TypeScript 6 or later, which declares `Temporal`.

## Accessible composition

**Todae handles:** The text input takes `id`, `aria-label`, `aria-labelledby` and `aria-describedby` from `Field.Root`, and native `disabled` and `aria-invalid` from the Root or a surrounding [Fieldset](/fieldset). It gets `aria-invalid` once a commit can't read its text, and `aria-required` with `required`. Beside a [Field.Picker](/field/picker), the input stays the field's control, and the picker's button is named from the `dateTimePicker` string in [StringsProvider](/utilities/strings-provider) and shows the `calendar` glyph from [GlyphsProvider](/utilities/glyphs-provider).

**You supply:** A name, through a [Label](/label) whose `htmlFor` is the Root `id` or `aria-label` / `aria-labelledby` on the Root. With a picker, the panel and its names, as the recipe shows.

**Watch for:** With a `value`, the server writes the date and time in its own locale, so pass `locale` when the input renders on a server. A value stored as if it were an instant: a `PlainDateTime` moves with the reader's clock, so add the time zone before you store a moment.

## When to use

### Field.DateTimeInput

**When:** A date and a time of day in one value, such as when a meeting starts or a flight departs.

**When not:** A date alone → [Field.DateInput](/field/date-input). A time alone → [Field.TimeInput](/field/time-input). An instant in a time zone → this input, with the zone added in your own code.
