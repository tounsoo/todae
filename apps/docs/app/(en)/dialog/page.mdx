# Dialog

Centered native `<dialog>` via `showModal()`. `open` is controlled, or `defaultOpen` leaves it uncontrolled. Escape and backdrop dismiss are opt-out. No sheet morph.

Enter is an opacity fade over 280ms while the panel rises into place from `dialog.motion.offset` (`0.5rem`) below; exit fades it and lets it sink back. The panel moves by layout, not a transform, so a tooltip inside stays by its trigger. `@starting-style` where supported; `data-entered` is the fallback so unsupported engines still tween. Exit stays mounted until `transitionend` (200ms fallback). Under reduced motion the panel and scrim only fade.

Overlays inherit tokens from `ThemeProvider` / `DensityProvider`. They do not inherit extra classes on the provider node.

iOS may still rubber-band the page behind an open overlay. Chrome may ignore `cancel.preventDefault()` without user activation. State still resyncs from the native `close` event.

## Alert dialog

`role="alertdialog"` marks a dialog that interrupts to ask for a response, such as confirming a destructive action. A backdrop click no longer closes it; Escape still does. On open, focus goes to its first close part, so a `Dialog.Close` that says Cancel takes it without an `initialFocusRef`. It needs a message: render `Dialog.Description` or pass `aria-describedby`, or it logs an error in development. Leave out the header close: Cancel is the way out.

Deleting removes the button that opened the dialog, so `restoreFocusRef` names where focus goes after the exit. Cancel leaves the opener in place, and focus goes back to it. What counts as destructive, and the wording, are the product's.

## Icons

`Dialog.Close` with no content shows the `close` glyph, a cross unless a [GlyphsProvider](/utilities/glyphs-provider) sets one, and is named by the `close` string. To use a different icon for one close, put it in a `Button.Icon`.

```tsx
import { X } from 'lucide-react';

<Dialog.Close>
  <Button.Icon>
    <X />
  </Button.Icon>
</Dialog.Close>
```

## Accessible composition

**Todae handles:** `Dialog.Root` opens a native `<dialog>` with `showModal()`, so the browser gives it the dialog role, puts it in the top layer and makes the page behind it inert. `Dialog.Title` sets the dialog's `aria-labelledby` and `Dialog.Description` its `aria-describedby`; an `aria-labelledby` or `aria-describedby` you pass to the root wins. On open, focus goes to `initialFocusRef`, else, with `role="alertdialog"`, the first tabbable `Dialog.Close`, else the first tabbable element, else the dialog itself. After the exit, focus goes to `restoreFocusRef`, else back to what had focus before it opened. `Dialog.Close` falls back to the `close` string ("Close") when neither its own text nor an `aria-label` names it, such as an icon.

**You supply:** A name: render `Dialog.Title`, or pass `aria-label` or `aria-labelledby` to `Dialog.Root`. A button that closes it, such as `Dialog.Close`, above all when `dismissOnEscape` is false. A `restoreFocusRef` when the opener is gone by the time it closes, such as a menu item or a `Toast.Action`. An `initialFocusRef` when the task does not start at the first control, or when an alert dialog's safe button is not a `Dialog.Close`. A description for an alert dialog.

```tsx
import type { ReactNode } from 'react';
import { Dialog, type DialogRootProps } from '@tounsoo/todae';

type ConfirmDialogProps = Omit<DialogRootProps, 'children'> & {
  title: string;
  children: ReactNode;
};

export function ConfirmDialog({ title, children, ...rest }: ConfirmDialogProps) {
  return (
    <Dialog.Root {...rest}>
      <Dialog.Title>{title}</Dialog.Title>
      <Dialog.Body>{children}</Dialog.Body>
      <Dialog.Footer>
        <Dialog.Close>Cancel</Dialog.Close>
      </Dialog.Footer>
    </Dialog.Root>
  );
}
```

**Watch for:** A wrapper that renders its own heading instead of `Dialog.Title` leaves the dialog unnamed unless it passes `aria-labelledby`. A wrapper that drops the rest props loses `aria-*`, `ref` and the focus refs. `Dialog.Title` always renders an `h2`, so start headings inside the dialog at `h3`. Do not render the dialog inside a hidden container such as a closed popover or tab panel: the page goes inert and nothing shows. In an alert dialog, every `Dialog.Close` counts as a safe choice, so keep the destructive action a plain `Button.Root`; a disabled Cancel leaves focus to the first tabbable element, so pass `initialFocusRef` then.

## When to use

**When:** Centered modal task or confirm (native `<dialog>`, controlled `open` or uncontrolled `defaultOpen`). Name via `Dialog.Title` or `aria-label`. Escape + backdrop dismiss by default. `role="alertdialog"` for a confirm that interrupts to ask for a response, such as before a destructive action.

**When not:** Mobile picker from the bottom → BottomSheet. Full-height side panel → Drawer. Non-modal anchored panel → Popover. Short hint → Tooltip. Needs to become a sheet on mobile (Dialog never morphs).
