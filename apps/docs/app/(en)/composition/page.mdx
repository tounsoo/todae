# Composition

What Todae offers for building UI comes in three kinds. Use the questions below to place something new. Providers and their hooks, helper functions and constants, such as `ThemeProvider`, `useDensity` and `composeRefs`, sit outside this split.

- **Component.** One UI concept whose markup, props and behavior Todae can fix without knowing anything about the product. A component owns behavior and accessibility. That is keyboard handling, focus, ARIA wiring, state, positioning, and tokens. It may own behavior, like [Menu](/menu) and [Tabs](/tabs), or only styles from tokens, like [Stack](/stack) and [Text](/text). A native element that Todae styles is a component too, like [Link](/link) on an `<a>` and [Disclosure](/disclosure) on a `<details>`: the browser runs it, and the component carries its tokens. Todae does not style a plain `<a>` or `<table>`, so every Todae look comes from an export. Components ship as a compound: a namespace with a `Root` and any named parts, like `Menu.Root` and `Menu.Item`.
- **Hook.** Behavior with no markup. Todae exports one when a recipe needs it or products need it under markup of their own. [useRovingFocus](/utilities/use-roving-focus) and [useCombobox](/utilities/use-combobox) are hooks. The sidebar lists them under Utilities.
- **Recipe.** A starting point for a company's own design system. It shows how to put Todae exports together where the result depends on the product: its data, its flow (what to search, how results load, what happens on pick) or how its screens are laid out. A recipe must be thin glue. Hard behavior (keyboard handling, focus management, ARIA wiring, measurement and positioning) must live in a component or hook, so a company can copy the recipe and restyle it without breaking accessibility. A recipe is never a package export, so there is no `Combobox.*`. A recipe owns layout, opinionated composition, and feature bundles, built from components and hooks.

## Placing something new

Ask these in order.

1. Can Todae fix its markup, every prop and its behavior without knowing the product's data, fetching, routing, business rules or screen layout? Then it is a component. `Stack.Root` passes: it fixes spacing from tokens, not where things go on a screen. [Link](/link) passes too, though the browser does all of its behavior: it fixes the `<a>` and its tokens. If a recipe, or a product's own markup, needs that behavior, it is a hook too, like [useRovingFocus](/utilities/use-roving-focus).
2. Otherwise it belongs to the product. When it puts Todae exports together, Todae documents it as a recipe. Any hard behavior it needs moves into a component or hook so the recipe stays thin glue, such as [useCombobox](/utilities/use-combobox) for [Combobox](/recipes/combobox). If the copied code would still carry hard behavior of its own, that behavior belongs in Todae.

A component can contain other components, as `Menu.Trigger` is a `Button`, and can share state with the children it holds, as [Fieldset](/fieldset) shares `disabled` and `invalid`. It is still a component because Todae can fix how those pieces fit together. A wrapper that adds nothing of its own, no behavior, styles or tokens, and only arranges other exports is never a Todae component. If the arrangement is worth showing, it is a recipe.

## Composer

Composer is the worked example of this split.

Ben's reason, in his words: "Composer had too many features baked in for the concept of this DS."

The mention pieces stay components. They are `defineMentionSource`, `useMention`, the suggestion list, the peek on the stock [Popover](/popover), `Mention.Root`, `MentionText`, and the `mention.*` tokens.

The frame, the toolbar, the attachments, and submit become a recipe. You build that recipe from `Field.Textarea`, `Button`, and the mention pieces.

This reverses option 2. Option 2 made Composer a component made of parts. The decision removes the published `Composer` export, which stays in the package until that removal. The package does not export `defineMentionSource`, `useMention`, `Mention.Root`, or `MentionText` yet.

## Components

Public siblings, for example `Field`, [Label](/label), [Description](/description), [ErrorMessage](/errormessage), [Checkbox](/checkbox), [Radio](/radio), [Switch](/switch), `Button`, `Popover`, `Tooltip`, `Chip`, `OptionList`, `Dialog`, and `BottomSheet`. Compose them side by side. Never nest namespaces, as in `Field.Button.Root`. One interactive role per component root.

`Field.Icon`, `Field.Affix`, and `Button.Icon` are compound parts. They are not free-floating atoms. Shared Icon, Affix, and Shell live under the hood. They are not public exports.

`Field.Root` is chrome only. [Label](/label) is a sibling component. Adornments follow DOM order. No `side` prop.

## Recipes

Worked examples that compose components and hooks. Combobox is a recipe, not a package namespace. The blocks below are static. They do not run. The hook owns behavior. Components own chrome. There is no shipped Trigger sugar.

Desktop (`presentation="popover"`). The closed control is a real Field. Spread `getAnchorProps` onto `Field.Root`. The list lives in `Popover.Root`. Worked recipes live on [Combobox](/recipes/combobox).

```tsx
const cb = useCombobox({ presentation: 'popover' })

<Field.Group>
	<Label.Root {...cb.getLabelProps()}>Tags</Label.Root>
	<Field.Root {...cb.getAnchorProps()}>
		<Field.Icon><Search /></Field.Icon>
		<Field.ChipInput {...cb.getChipInputProps()} />
		<Field.Icon><ChevronDown /></Field.Icon>
	</Field.Root>
</Field.Group>
<Popover.Root {...cb.getPopoverProps()}>
	<OptionList.Root {...cb.getListboxProps()}>...</OptionList.Root>
</Popover.Root>
```

`anchorRef` is the CSS anchor when the trigger is not the element `getTriggerProps` marks. Combobox uses `getAnchorProps` on `Field.Root`. Do not also spread [usePopover](/utilities/use-popover) `getTriggerProps`.

Touch (`presentation="sheet"`). The closed control is `Button.Root`. Search Field lives inside the sheet.

```tsx
const cb = useCombobox({ presentation: 'sheet' })

<Field.Group>
	<Label.Root {...cb.getLabelProps()}>Tags</Label.Root>
	<Button.Root {...cb.getTriggerProps()}>Pick…</Button.Root>
</Field.Group>
<BottomSheet.Root {...cb.getSheetProps()}>
	<Field.Group>
		<Label.Root htmlFor={cb.ids.input}>Search</Label.Root>
		<Field.Root id={cb.ids.input}>
			<Field.Icon><Search /></Field.Icon>
			<Field.TextInput {...cb.getInputProps()} />
		</Field.Root>
	</Field.Group>
	<OptionList.Root {...cb.getListboxProps()}>...</OptionList.Root>
</BottomSheet.Root>
```

The touch trigger is `Button.Root`. In both, `getLabelProps()` goes on the field's Label: it names the listbox, and points at the input in a popover and at the trigger in a sheet.

## Hook

[useCombobox](/utilities/use-combobox) is headless. It owns open, value, aria, keyboard, and listbox ids.

- `useCombobox({ presentation: 'popover' | 'sheet' | 'dialog' | 'auto' })`
- `getAnchorProps()` on `Field.Root` (desktop)
- `getTriggerProps()` on `Button.Root` (sheet)
- `getInputProps()` / `getChipInputProps()` on the field input
- `getPopoverProps()` on `Popover.Root`
- `getSheetProps()` on `BottomSheet.Root`
- `getDialogProps()` on `Dialog.Root`
- `getLabelProps()` on the field's `Label.Root`
- `getListboxProps()` on `OptionList.Root`

No Trigger sugar component. No `Combobox.*` chrome. See [Combobox](/recipes/combobox).

## Never

```
Field.Root
  └─ Field.Button.Root          nested compound namespaces

Field.Root as a button that also hosts TextInput
  two roles on one root

Combobox.Root, Combobox.Trigger, or Combobox.Icon
  recipe chrome in the package

Dual-wiring aria or open outside useCombobox while also using the hook

OptionList and Radio or Checkbox bound to the same value
  overlay listbox and permanent choice on one selection

Combobox behavior baked into Field

Touch closed control = Field pretending to be a button

Product trees importing raw Icon or Affix instead of Field.Icon or Field.Affix

Docs that treat Field.Icon or Button.Icon as free-floating atoms
```

See [Combobox](/recipes/combobox) for the live recipe.

## Audit

These are the 61 component namespaces exported from the package, in export order. Fits means the namespace owns behavior, accessibility, or tokens in the way the rule above describes. A misfit is an open question, except Composer, which is already decided.

- **Alert.** Fits.
  Root sets `role="alert"` or `role="status"` from the tone, and Close is a named button.
- **Avatar.** Fits.
  The image's load and failure are state, and the fallback stays when the image fails.
- **Link.** Fits.
  `Link.Root` is the styled native `<a>`, and the link tokens live on it.
- **Disclosure.** Fits.
  It is a native `<details>` and `<summary>`. The browser runs the keyboard and the expanded state, and the disclosure tokens live on it.
- **Separator.** Fits.
  It is a native `<hr>` with its separator role, and the separator tokens live on it.
- **Prose.** Fits.
  Root is one div. The sheet applies the `prose` tokens, including `prose.gap` and the heading spaces, to the markdown elements inside. It does not wire other exports into a product flow.
- **ScrollArea.** Fits.
  When focus lands on a control whose ring would be cut, it scrolls the ring into view.
- **Table.** Fits.
  It is a native `<table>` styled from the table tokens, and a header cell can sort.
- **Progress.** Fits.
  It is a native `<progress>`, and the progress tokens draw the track and fill.
- **Meter.** Fits.
  It is a native `<meter>`, and the meter tokens draw the track and fill.
- **Loader.** Fits.
  It is a native `<progress>` with no value, styled from the loader tokens.
- **Skeleton.** Fits.
  Root is one div. Children only give it a size and are hidden. It pulses from the skeleton motion tokens and the pulse stops under `prefers-reduced-motion`.
- **Slider.** Fits.
  It is a native `<input type="range">`. The browser runs the arrow keys, and the slider tokens tint the control.
- **Code.** Fits.
  It is a native `<code>`, styled from the code tokens.
- **CodeBlock.** Fits.
  It is a native `<pre>` styled from the code tokens, and it scrolls sideways when a line is wider than the block.
- **Kbd.** Fits.
  It is a native `<kbd>`, styled from the kbd tokens.
- **VisuallyHidden.** Fits.
  It hides its content on screen and keeps it for assistive technology. With `focusable`, the content shows again while focus is inside.
- **Badge.** Fits.
  Tones read the badge contract tokens. It is a static label, with no product flow.
- **Breadcrumbs.** Fits.
  Root is a `nav` landmark, and the current item sets `aria-current="page"`.
- **EmptyState.** Misfit, open question.
  The parts are className wrappers for an icon, a title, a description, and actions. They add no keyboard handling, focus, state, or positioning. Root also reads the `emptystate` tokens.
- **Card.** Misfit, open question.
  `Card.Header`, `Card.Body`, and `Card.Footer` are divs. `Card.Body` adds no class. None of them set a role, handle a key, move focus, or keep state. Root reads the `card` tokens.
- **DataList.** Fits.
  It is a native `dl`. Term and details keep that meaning, and the datalist tokens set color, weight, and column width.
- **Message.** Fits.
  Root is an `<article>` with `aria-busy` while `streaming` is set, and `Message.Time` formats a `Temporal.ZonedDateTime`. Copy and rating stay the message-actions recipe.
- **Attachment.** Fits.
  Removing a focused attachment moves focus to a neighbor's remove button, and `status` is state.
- **Steps.** Fits.
  A current step sets `aria-current="step"`, and each status draws its marker.
- **Composer.** Misfit, decided.
  The quote above is the decision. The frame, the toolbar, the attachments, and submit become a recipe. The package still exports `Composer`.
- **Conversation.** Fits.
  It follows the end until the reader scrolls up, announces a message that sets `aria-busy`, and the viewport is a named region.
- **BottomSheet.** Fits.
  It is a modal `<dialog>` with snap points, drag, and the browser's focus trap.
- **Button.** Fits.
  `Button.Root` is the control. An icon-only root needs an accessible name, and the button tokens live on it.
- **Splitter.** Fits.
  The handle is a separator with one tab stop. Drag and the arrow keys resize the primary panel.
- **Toolbar.** Fits.
  Root has `role="toolbar"`. Arrow keys move focus, and the controls share one tab stop.
- **ToggleGroup.** Fits.
  Items are buttons with `aria-pressed`. The group takes one tab stop, and the arrow keys move focus.
- **Dialog.** Fits.
  It is a modal `<dialog>`. Escape and the backdrop dismiss, and focus stays inside.
- **Drawer.** Fits.
  It is a modal `<dialog>` pinned to an edge, with the same focus model as Dialog.
- **Drilldown.** Fits.
  Escape goes back one view before it closes the surface, and focus returns to the trigger that pushed the view.
- **OptionList.** Fits.
  It is a listbox with `aria-activedescendant`. Arrow, Home, End, Enter, and Space are its keys.
- **Pagination.** Fits.
  Root is a `nav` landmark named by the pagination string, around the list of pages.
- **Menu.** Fits.
  The trigger sets `aria-haspopup="menu"` and `aria-expanded`. Content is a menu in a positioned popover, and the arrow keys move in it.
- **Popover.** Fits.
  Root is the positioned surface. `usePopover` owns open, focus, and dismissal.
- **Tooltip.** Fits.
  Root is the tip chrome. `useTooltip` owns hover, focus, and the delays.
- **Toast.** Fits.
  Toasts live in a store, appear in a region, and leave on their own. The region handles its own Escape.
- **Checkbox.** Fits.
  It is a native checkbox. Children are the visible label, and invalid state is shared with a fieldset.
- **Chip.** Fits.
  Text is the label. The optional remove control is a named button.
- **ChipList.** Fits.
  It measures how many chips fit in `maxRows` and positions the rest in a popover.
- **Description.** Fits.
  The required `id` is what a control names in `aria-describedby`.
- **ErrorMessage.** Fits.
  Inside a form, the scope puts this id on `aria-describedby` while a problem is shown.
- **Field.** Fits.
  It wires the label, description, and error to the control. The pickers render their own popover, because a native popup cannot take the tokens.
- **Fieldset.** Fits.
  It shares `disabled` and `invalid` with the controls it holds.
- **Form.** Fits.
  It reads the browser's validity, sets `aria-invalid` and `aria-describedby`, and moves focus to the first problem. It holds no schema.
- **Label.** Fits.
  `htmlFor` names the control.
- **RadioGroup.** Fits.
  Root owns the value, the shared `name`, `disabled`, and `invalid`. The items are native radios.
- **Switch.** Fits.
  It is a native checkbox with the switch presentation. The browser runs the keyboard.
- **Tabs.** Fits.
  The list is a tablist, tabs and panels pair by `value`, and the arrow keys move between tabs.
- **ColorPicker.** Fits.
  Drag and the arrow keys change the color, and the root holds that color as state.
- **Calendar.** Fits.
  The grid's keyboard picks a day, and a range keeps an anchor until the second pick.
- **Contents.** Fits.
  While the page scrolls, the link to the section in view sets `aria-current="location"`.
- **Nav.** Fits.
  Root is a `nav` landmark. A group with a label is named for assistive technology, and a branch is a native `<details>`.
- **Tree.** Fits.
  Root is a tree and owns which items are open and which one is selected. Arrow keys move in it.
- **Stack.** Fits.
  Gap, direction, and alignment come from props and the stack tokens. It does not set tracks. This page uses `Stack.Root` as the case that passes.
- **Grid.** Misfit, open question.
  Root is a div that sets `grid-template-columns` from `columns` or `minItemSize`. It has no keyboard handling, focus, ARIA, or state. `grid.gap` is a token. Unlike Stack, the tracks decide where items sit.
- **Text.** Fits.
  Body and heading sizes come from the text tokens. With `lines`, the main entry shows the full text in a tooltip on hover and on keyboard focus.

Open questions are EmptyState, Card, and Grid.

- **EmptyState.** An icon, a title, a sentence, and the next step, with no keyboard handling, focus, state, or positioning, and with `emptystate` tokens.
- **Card.** Header, body, and footer divs. `Card.Body` adds no class. Root reads the `card` tokens.
- **Grid.** Column tracks from `columns` or `minItemSize`, with no keyboard handling, focus, ARIA, or state, and with a `grid.gap` token.

Composer is the decided misfit. The quote above is the decision. The frame, the toolbar, the attachments, and submit become a recipe. The package still exports `Composer`.
