# Composition

Todae splits UI into four kinds. Every component and pattern in these docs is one of them. Providers and helpers, such as `ThemeProvider` and `composeRefs`, are foundations and sit outside this split.

- **Native + CSS.** HTML already has the element and all of its behavior. Todae adds only styles from tokens. [Link](/link) and [Disclosure](/disclosure) are native. A native element can also be a thin part of a component, such as `Field.Select`, so it joins that component's label and error wiring.
- **Component.** One UI concept whose whole API and behavior Todae can fix without knowing anything about the product. It owns something of its own: behavior, like [Menu](/menu) and [Tabs](/tabs), or styles from tokens, like [Stack](/stack) and [Alert](/alert). When consumers compose its parts, it ships as a compound: a namespace with a `Root` and named parts, like `Menu.Root` and `Menu.Item`. Otherwise it is one export, like `Stack` or `Checkbox`.
- **Hook.** The behavior of a component or recipe with no markup, for products that need their own markup. [useRovingFocus](/utilities/use-roving-focus) and [useField](/utilities/use-field) are hooks.
- **Recipe.** Two or more exports wired to each other around product data or a product flow: what to search, how results load, what happens on pick. The wiring is the point, and it differs per product. A recipe is code in these docs to copy. It is never a package export, so there is no `Combobox.*`.

## Component or recipe

Ask these in order. The first answer that decides wins.

1. Does a native element already do all of it, so Todae would add only styles? Then it is native, styled with CSS.
2. Can every prop be written without naming product data, fetching, routing or business rules? If not, it is a recipe.
3. Does it wire parts of other components to each other, such as a Field's input to an OptionList's active option? Then it is a recipe. The behavior that wiring needs in every product becomes a hook, as with [Combobox](/recipes/combobox) and [Chip list](/recipes/chip-list).
4. Otherwise it is a component.

A component may hold whatever children it receives and give them context or keyboard handling, as long as it does not wire them to each other. [Fieldset](/fieldset) does this: beyond what the native `<fieldset>` does, it hands `disabled` and `invalid` to any Todae control inside it.

A wrapper that adds nothing of its own, no behavior, styles or tokens, and only arranges other exports is neither. Todae does not ship it.

## Components

Components compose as siblings, for example `Field`, [Label](/label), [Description](/description), [ErrorMessage](/errormessage), [Checkbox](/checkbox), [RadioGroup](/radio), [Switch](/switch), `Button`, `Popover`, `Tooltip`, `Chip`, `OptionList`, `Dialog`, and `BottomSheet`. Compose them side by side. Never nest namespaces. One interactive role per compound root.

`Field.Icon`, `Field.Affix`, and `Button.Icon` are compound parts. They are not free-floating atoms. Shared Icon, Affix, and Shell live under the hood. They are not public exports.

`Field.Root` is chrome only. [Label](/label) is a sibling component. Adornments follow DOM order. No `side` prop.

## Recipes

Worked examples that compose components and hooks. Combobox is a recipe, not a package namespace. The blocks below are static. They do not run. The hook owns behavior. Components own chrome. There is no shipped Trigger sugar.

Desktop (`presentation="popover"`). The closed control is a real Field. Spread `getAnchorProps` onto `Field.Root`. The list lives in `Popover.Root`. Worked recipes live on [Combobox](/recipes/combobox).

```tsx
const cb = useCombobox({ presentation: 'popover' })

<div className="labelled-field">
	<Label htmlFor={cb.ids.input}>Tags</Label>
	<Field.Root {...cb.getAnchorProps()}>
		<Field.Icon><Search /></Field.Icon>
		<Field.ChipInput {...cb.getChipInputProps()} />
		<Field.Icon><ChevronDown /></Field.Icon>
	</Field.Root>
</div>
<Popover.Root {...cb.getPopoverProps()}>
	<OptionList.Root {...cb.getListboxProps()}>...</OptionList.Root>
</Popover.Root>
```

`anchorRef` is the CSS anchor when the trigger is not the element `getTriggerProps` marks. Combobox uses `getAnchorProps` on `Field.Root`. Do not also spread [usePopover](/utilities/use-popover) `getTriggerProps`.

Touch (`presentation="sheet"`). The closed control is `Button.Root`. Search Field lives inside the sheet.

```tsx
const cb = useCombobox({ presentation: 'sheet' })

<Button.Root {...cb.getTriggerProps()}>Pick…</Button.Root>
<BottomSheet.Root {...cb.getSheetProps()}>
	<div className="labelled-field">
		<Label htmlFor={cb.ids.input}>Search</Label>
		<Field.Root id={cb.ids.input}>
			<Field.Icon><Search /></Field.Icon>
			<Field.TextInput {...cb.getInputProps()} />
		</Field.Root>
	</div>
	<OptionList.Root {...cb.getListboxProps()}>...</OptionList.Root>
</BottomSheet.Root>
```

The touch trigger is `Button.Root`.

## Hook

[useCombobox](/utilities/use-combobox) is headless. It owns open, value, aria, keyboard, and listbox ids.

- `useCombobox({ presentation: 'popover' | 'sheet' | 'auto' })`
- `getAnchorProps()` on `Field.Root` (desktop)
- `getTriggerProps()` on `Button.Root` (sheet)
- `getInputProps()` / `getChipInputProps()` on the field input
- `getPopoverProps()` on `Popover.Root`
- `getSheetProps()` on `BottomSheet.Root`
- `getListboxProps()` on `OptionList.Root`

No Trigger sugar component. No `Combobox.*` chrome. See [Combobox](/recipes/combobox).

## Never

```
Field.Root
  └─ Field.Button.Root          nested compound namespaces

Field.Root as a button that also hosts TextInput
  two roles on one root

Combobox.Root, Combobox.Trigger, or Combobox.Icon
  recipe chrome in the package

Dual-wiring aria or open outside useCombobox while also using the hook

OptionList and Radio or Checkbox bound to the same value
  overlay listbox and permanent choice on one selection

Combobox behavior baked into Field

Touch closed control = Field pretending to be a button

Product trees importing raw Icon or Affix instead of Field.Icon or Field.Affix

Docs that treat Field.Icon or Button.Icon as free-floating atoms
```

See [Combobox](/recipes/combobox) for the live recipe.
