# useField

`useField()` joins your own control to the nearest `Field.Root`, the way the built-in parts join it. Spread `getControlProps()` on the control: it carries the Root's `id`, `name`, `disabled`, `aria-invalid`, the merged `aria-describedby`, the Root's name unless the control names itself, and a ref so a press on the shell focuses the control. The shell draws its focus ring for it too. For a control that is not a native form element, call `getControlProps(props, { native: false })`: it sets `aria-disabled` instead of `disabled` and leaves out `name`, which only form elements submit. Read `disabled` from `useField()`, the Root's, to skip the tab stop and ignore keys; a `disabled` or `aria-invalid` you pass in adds to the Root's and never clears it, so combine your own with it in the same checks. `Label.Root htmlFor` only names labelable elements, so name a custom element through `aria-labelledby` on the Root.

```tsx
function Stars({ value, onChange }: { value: number; onChange: (value: number) => void }) {
  const field = useField();
  const step = (delta: number) => onChange(Math.min(5, Math.max(0, value + delta)));
  return (
    <span
      {...field.getControlProps({}, { native: false })}
      role="slider"
      tabIndex={field.disabled ? -1 : 0}
      aria-valuemin={0}
      aria-valuemax={5}
      aria-valuenow={value}
      aria-valuetext={`${value} of 5 stars`}
      onKeyDown={(event) => {
        if (field.disabled) return;
        if (event.key === 'ArrowRight' || event.key === 'ArrowUp') step(1);
        else if (event.key === 'ArrowLeft' || event.key === 'ArrowDown') step(-1);
        else return;
        event.preventDefault();
      }}
    >
      {'★'.repeat(value)}
      {'☆'.repeat(5 - value)}
    </span>
  );
}
```

## Value inputs

A control that is not a native form element sends nothing with a form and is not validated. `getValueInputProps` gives the props for a native `<input>` that carries its value, so the browser checks `required`, `min` and `max`, and `Form.Root` shows the problem and moves focus to the control.

```tsx
function Stars({ value, onChange, required }: StarsProps) {
  const field = useField();
  return (
    <>
      <span {...field.getControlProps({}, { native: false })} role="slider" tabIndex={0} aria-valuenow={value} />
      <input
        {...field.getValueInputProps({ type: 'number', value: value ? String(value) : '', required, min: '1', max: '5' })}
      />
    </>
  );
}
```

`type` is `text`, `number`, `date`, `time`, `datetime-local` or `color`, and `value` is in that type's format, such as `2026-10-07` for `date`, or `''` for none. `step` is the type's own. `bound` writes a `min` or `max` in the field's own format for the message that names it, such as "Oct 7, 2026", and without it the message names the raw value. The input sends its value under the field's `name`, unless another control in the field took it, and is disabled with the field. It is not read-only or `type="hidden"`, which the browser leaves out of validation. It is hidden from sight and from assistive technology, is not a tab stop, and a press on the field's shell never focuses it. Render it beside the control, inside the same `Field.Root`. A problem on it moves focus to the control `getControlProps` wired, from `Form.Root` and from a `Form.Summary` link.

## Accessible composition

**Todae handles:** `getControlProps()` gives your control the Root's `id`, its `aria-describedby` merged with yours, `aria-invalid` while the Root is invalid, the Root's `aria-label` or `aria-labelledby` unless the control names itself, and `disabled`, or `aria-disabled` with `{ native: false }`. Its ref lets a press on the shell focus the control, and the shell draws its focus ring while the control or anything inside it is focus-visible. The Root's `disabled` and `invalid` include a surrounding [Fieldset](/fieldset)'s.

**You supply:** What the control is and does: a `role`, since the hook sets none, a `tabIndex`, keyboard handling, and the role's state, such as `aria-valuenow`, `aria-valuemin` and `aria-valuemax` for a `slider`. A name through `aria-labelledby` or `aria-label` on `Field.Root`. While `field.disabled` is true, skip the tab stop and ignore keys.

**Watch for:** An `aria-describedby`, `name` or `ref` spread after `getControlProps()` replaces the wired one without the field knowing; pass yours in as `getControlProps(props)` instead. The `aria-disabled` from `{ native: false }` does not stop focus or keys. Every control that calls `getControlProps()` gets the same `id`, so use one per `Field.Root`.

## When to use

**When:** Your own control, such as a rating, sits inside `Field.Root` and needs its id, name, description and invalid state.

**When not:** A built-in part already fits → use it. A control outside any `Field.Root` → wire its own ids.
