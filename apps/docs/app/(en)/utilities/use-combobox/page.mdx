# useCombobox

`useCombobox` owns a combobox's open state, value, input, highlight and ids. Components own the chrome: `Field` for the input, `Popover`, `BottomSheet` or `Dialog` for the surface, `OptionList` for the list. There is no `Combobox.*` export. The [Combobox recipe](/recipes/combobox) shows single, multi, sheet, async and create.

`presentation` defaults to `'auto'`, which picks a sheet on a coarse pointer or a narrow viewport through [useSheetPresentation](/utilities/use-sheet-presentation). Force `popover` or `sheet` to keep it fixed, as the demo below forces `popover`. `dialog` puts the input and list in a `Dialog`, as the [Command palette](/recipes/command-palette) does. [Composition](/composition) lists which getter goes on which part.

```tsx
const cb = useCombobox({ options, presentation: 'popover' });

<Field.Group>
  <Label.Root {...cb.getLabelProps()}>Framework</Label.Root>
  <Field.Root {...cb.getAnchorProps()}>
    <Field.TextInput {...cb.getInputProps()} />
  </Field.Root>
</Field.Group>
<Popover.Root {...cb.getPopoverProps()}>
  <OptionList.Root {...cb.getListboxProps()}>
    {cb.items.map((item) => (
      <OptionList.Option key={item.id} {...cb.getOptionProps(item)} />
    ))}
  </OptionList.Root>
</Popover.Root>
```

## Accessible composition

**Todae handles:** `getInputProps()` and `getChipInputProps()` make the input a `role="combobox"` with `aria-expanded`, `aria-controls` (the listbox id), `aria-autocomplete="list"`, `autoComplete="off"`, and `aria-activedescendant` on the active option while open, so focus stays in the input. ArrowDown, ArrowUp, Home and End open the list and move the active option, skipping disabled ones. Enter selects or creates while the list is open, and waits while the current query's list is still loading or its create is pending. While the list is closed, or open with no row to pick and no create row, Enter is left to the form and creates nothing. Any other `commitKeys` you give `Field.ChipInput` commit the same way while the list is open, and are kept from typing their character while it is closed. Escape closes, and Tab closes. Keys that belong to an IME composition, such as the Enter that ends a Korean word, are left to the input. While an async `onCreate` is pending, `creating` is true and that label's create row stays the active row with `aria-disabled`, so another Enter or click waits instead of running it again or picking another row; a create for another label runs beside it. Labels match without regard to case. What `onCreate` throws or rejects with lands in `createError`, not in `error`, which is only for loads, and only while the text still asks for that label; the next text change, pick, removal, `clear()`, create or opening of the list clears it. A throw from `onValueChange`, `onInputValueChange` or `onOpenChange` is yours, not a create failure: the other callbacks still run, then the throw goes on, out of the event handler, or after an async create as an unhandled rejection. In single mode, a create applies only while the input still reads its label and the value is the one it started from. Once either changes, the create is dropped for good, so a pick, a clear, other text or `reset()` wins, and creating the same label again starts a new one. In multiple mode the created chip is still added, and only `clear()` or `reset()` drops it. `getLabelProps()` gives the field's Label the id the listbox takes its name from, and a `htmlFor` that points at the input, or at the trigger in a sheet or dialog. `getListboxProps()` gives `OptionList.Root` the listbox id, `tabIndex={-1}` and `aria-labelledby` set to `ids.label`, or the `aria-label` or `aria-labelledby` you pass it instead. In development, the hook warns when the open list has no name. `getTriggerProps(props)` sets `aria-haspopup="dialog"`, `aria-expanded` and `aria-controls`, which win over yours, as its `id` does. Unless you pass `aria-label` or `aria-labelledby`, it names the trigger by the field's Label and its own text, so it reads "City San Francisco". With no Label rendered, its own text names it. It merges your other props and ref, and runs your `onClick` first: calling `preventDefault()` there skips the toggle. `reset()` puts back the default value, text and open state through the change callbacks, with the `reset` reason, and skips those that do not change. Escape in a popover returns focus to the input; a sheet returns it to the trigger when it closes.

**You supply:** The input's name: a [Label](/label) whose `htmlFor` is `ids.input`, or `aria-label` on `Field.Root` inside a sheet or dialog. The listbox's name: spread `getLabelProps()` on the field's Label, or with no visible label, pass `aria-label` to `getListboxProps()`. Text for a failed create, from `createError`, next to the create row. Trigger text that shows the value. A more specific name for the sheet or dialog when needed: `getSheetProps()` and `getDialogProps()` use the `options` string ("Options" by default), and an `aria-label` after the spread replaces it. Status text: the hook reports `loading`, `error`, `creating`, `createError` and `isEmpty` but renders and announces none of them.

**Watch for:** Unmounting `OptionList.Root` while it is empty or loading: `aria-controls` then points at nothing, so set `hidden` instead. Your own `onKeyDown`, `onFocus` or `onBlur` after the spread, which replaces the hook's handlers. A trigger's handlers go into `getTriggerProps({ … })` instead. An inline callback `ref` passed to `getTriggerProps`, which attaches again on every render. Buttons or links inside an option.

## When to use

**When:** Searchable select — typeahead + list. Hook owns open/value/input; Field + Popover/BottomSheet + OptionList own chrome, as the [recipe](/recipes/combobox) shows. Auto sheet on coarse/narrow.

**When not:** Static on-page exclusive → Radio. Non-search list → [usePopover](/utilities/use-popover) + OptionList only. Action menu → [Menu](/menu). Exporting `Combobox.*` chrome (forbidden).
