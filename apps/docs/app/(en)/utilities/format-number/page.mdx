# formatNumber and parseNumber

`formatNumber(value, { locale, formatOptions })` writes a number as [Field.NumberInput](/field/number-input) does, such as `1,234.5` in `en` and `1.234,5` in `de`, and `parseNumber(text, { locale, formatOptions })` reads text back into a number, or returns `null` when the text is not one. `formatOptions` takes what `Intl.NumberFormat` takes, so a percent, a currency or a unit is a style away. Without `locale`, both use the runtime's own. Use them to show or read the same number outside the input.

<Example of={NumberRoundTrip} />

```tsx
formatNumber(0.125, { locale: 'de', formatOptions: { style: 'percent', maximumFractionDigits: 1 } }); // "12,5 %"
parseNumber('12,5 %', { locale: 'de', formatOptions: { style: 'percent' } }); // 0.125
```

## What parseNumber reads {/*#reading-numbers*/}

`parseNumber` learns the locale's separators, minus sign and digits from `Intl.NumberFormat`, so `1.234,5` in `de`, `1 234,5` with a narrow no-break space in `fr` and `١٬٢٣٤٫٥` in `ar-EG` all read as 1234.5, and full-width digits fold to ASCII. It accepts the text with or without grouping, but a group separator only where the locale puts one, so `1.234` in `de` is 1234, and `1,5` in `en` is no number. A period is a decimal point in a locale that doesn't group with one, such as `fr`.

It reads the percent sign, the currency sign or the unit that `formatOptions` writes, or its absence. It doesn't read compact or scientific notation, so `formatOptions` leaves `notation` and `compactDisplay` out, and TypeScript rejects them. A percent style takes the number as a fraction: `formatNumber` writes 0.125 as `12.5%`, and `parseNumber` reads `13%` as 0.13.

## Accessible composition

**Todae handles:** Text in the `locale` you pass, or the runtime's own when you pass none.

**You supply:** A `locale` that matches the page's, and the same `locale` and `formatOptions` for writing and reading. A message near the input when `parseNumber` returns `null`.

**Watch for:** On a server with no `locale`, the text uses the server's locale, so a mismatch can make hydration warn.

## When to use

### formatNumber

**When:** Writing a number as text for a locale, such as in a table cell next to a number input.

**When not:** A number in a style `formatOptions` can't write, such as compact notation → `Intl.NumberFormat`.

### parseNumber

**When:** Reading a number someone typed, in the locale and format the input uses.

**When not:** Text in a fixed format such as `1234.5` → `Number`.
