# useReorder

`useReorder({ onMove })` lets a person reorder a list by dragging: with the browser's drag and drop for a mouse, and with pointer events for a finger or a pen. Spread `getItemProps(index)` on each item and `getHandleProps(index)` on the element inside it that a drag starts from, such as a grip. `onMove(from, to)` gets the dragged item's index and the index it ends at.

```tsx
import { useReorder } from '@tounsoo/todae';
import { GripVertical } from 'lucide-react';

const reorder = useReorder({ onMove: move });

<ol>
  {items.map((item, index) => (
    <li key={item.id} {...reorder.getItemProps(index)}>
      <span {...reorder.getHandleProps(index)} aria-hidden style={{ cursor: 'grab', touchAction: 'none' }}>
        <GripVertical />
      </span>
      {item.name}
    </li>
  ))}
</ol>
```

Drag a row by its grip. The [Reorder](/recipes/reorder) recipe pairs the hook with a menu, for the keyboard and for anyone who can't drag.

A press on a handle makes its item draggable, so an item drags only by its handle and text in the items stays selectable. While an item is dragged, `dragging` is its index and `drop` says which item it would land beside and on which side, `before` or `after`, or is `null` where a drop would not move it. The items carry the same state as `data-dragging` and `data-drop`, for styles. A drop calls `onMove` only when the order changes, and a drop outside the items calls nothing, unless it lands on the element that takes `getListProps`, as Between lists says. `from` is where the dragged item is when it is dropped, so a list that changes during a drag still moves that item, and a drag whose item is removed ends. Drags that didn't start from this list's handles, such as files, selected text or another list's items, are ignored, so they can't be dropped there, unless the lists share a group, as Between lists says. The getters take your own props as a second argument and run your handlers before their own; a handler of yours that calls `preventDefault()` skips the hook's, as in every Todae part.

With `orientation="horizontal"`, `before` is the side the text starts from, so it is the right side in a right-to-left page.

Escape cancels a drag and leaves the order as it was. During a mouse drag the browser takes Escape itself and ends the drag with no drop; during a touch drag the hook takes it before a [Dialog](/dialog) around the list, which stays open until the next Escape.

## Long lists

As long as you give a getter no handler of your own, the handlers in its props keep their identity from render to render, and `getHandleProps(index)` with no props of yours returns the same object every time, shared by every render, so don't change it. In a long list, then, draw each item as a memoized component that takes `getItemProps(index)` spread and the handle's props as one prop: a drag step then renders only the items whose own state changed, such as the one the line leaves and the one it reaches, instead of every item.

```tsx
import { type UseReorderHandleProps, type UseReorderItemProps } from '@tounsoo/todae';
import { GripVertical } from 'lucide-react';
import { memo } from 'react';

const Row = memo(function Row({ name, grip, ...item }: UseReorderItemProps & { name: string; grip: UseReorderHandleProps }) {
  return (
    <li {...item} style={{ opacity: item['data-dragging'] === undefined ? 1 : 0.5 }}>
      <span {...grip} aria-hidden style={{ cursor: 'grab', touchAction: 'none' }}>
        <GripVertical />
      </span>
      {name}
    </li>
  );
});

<ol>
  {items.map((item, index) => (
    <Row key={item.id} {...reorder.getItemProps(index)} name={item.name} grip={reorder.getHandleProps(index)} />
  ))}
</ol>
```

Call `getItemProps(index)` in the list's render and pass the item what it returns, not the getter. An item reads its own state from its `draggable`, `data-dragging` and `data-drop` props, not from `dragging` and `drop`, which would render every item whenever the drag or its landing place changes. Keep its other props the same from step to step too, such as a move function from `useCallback`. A handler of your own given to a getter is wrapped again on each call, so an item that takes one renders on every step. The [Reorder](/recipes/reorder) and [Kanban](/recipes/kanban) recipes draw their rows this way.

## Touch

Browsers on touch screens differ: some start the browser's drag after a long press and some never do. So a finger or a pen on a handle drags with pointer events instead, the same way everywhere: the item drags once the finger or pen moves, `drop` follows the item under it, and lifting it drops the item. A tap drags nothing, and a pen drag selects no text. The handle needs `touch-action: none`: without it the browser takes a finger or a pen to scroll the page, which cancels the drag. The page doesn't scroll during a touch drag, so in a list taller than the screen the menu is the way to move an item far.

## Between lists

`useReorderGroup({ onMove })` lets lists take each other's items, such as the columns of a board. Pass its group to each list's `useReorder`, with a `list` key of your own for that list, such as the column's index or id. A drop in another list of the group calls the group's `onMove(from, to)`, where each is `{ list, index }`: the list and index the item leaves, and the list and index it ends at. A drop inside one list still calls that list's own `onMove(from, to)`.

```tsx
import { useReorder, useReorderGroup } from '@tounsoo/todae';

const group = useReorderGroup({ onMove: (from, to) => moveCard(from.list, from.index, to.list, to.index) });

// In each column:
const reorder = useReorder({ group, list: columnIndex, onMove: (from, to) => moveCard(columnIndex, from, columnIndex, to) });

<section {...reorder.getListProps()}>
  <h3>{column.name}</h3>
  <ol>{/* items, as above */}</ol>
</section>
```

Spread `getListProps()` on the element around the items. A drop on it but not on an item, such as in a gap, below the last item or in a list with no items, lands among the items by the pointer: before the first item the pointer is before, or after the last one, so a list with no items takes the item at index 0. `data-drop-target` marks that element while the dragged item would land in its list, which is the only mark an empty list gets. Each list's `drop` says where the item would land in that list, so only the list under the pointer shows a line, and `dragging` stays on the list the item left. A list with `disabled` takes no item from another, and a list nested in an item leaves a drop it can't take, or a drop of the item it sits in, to the list around it. Touch drags move between the lists of a group the same way.

## Accessible composition

**Todae handles:** Dragging an item only by its handle, with a mouse, a finger or a pen. Working out the item and side a drop lands on, and the index the dragged item ends at, in its own list or another of its group. Ignoring drags from elsewhere. Cancelling a drag on Escape.

**You supply:** Another way to move an item that needs no dragging and works from the keyboard, such as the Reorder recipe's menu: the browser's drag and drop has no keyboard path. A handle hidden from screen readers with `aria-hidden`, since that other way is the one they use. Keys from each item's id. For a move to another list, a place for the focus the moved item's old element held. The announcement of a move, and how the drop line and the dragged item look.

**Watch for:** Drag as the only way to reorder (WCAG 2.2 SC 2.1.1 and SC 2.5.7). A handle that is a button or a tab stop: it does nothing from the keyboard. A handle smaller than 24 by 24 CSS pixels, such as a bare icon (SC 2.5.8). A handle without `touch-action: none`, which a press on a touch screen scrolls instead of dragging. Touch dragging is tested with Chromium's touch input, was checked with pointer events in Firefox and WebKit, and hasn't been checked on a phone.

## When to use

**When:** Letting a person drag the items of a list they order themselves, beside a way to move them without dragging.

**When not:** Dropping files → [`useDropzone`](/utilities/use-dropzone). Moving items between lists → `useReorderGroup`, with a way to move them without dragging too.
