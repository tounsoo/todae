# useReorder

`useReorder({ onMove })` lets a person reorder a list by dragging, with the browser's drag and drop. Spread `getItemProps(index)` on each item and `getHandleProps(index)` on the element inside it that a drag starts from, such as a grip. `onMove(from, to)` gets the dragged item's index and the index it ends at.

```tsx
import { useReorder } from '@tounsoo/todae';
import { GripVertical } from 'lucide-react';

const reorder = useReorder({ onMove: move });

<ol>
  {items.map((item, index) => (
    <li key={item.id} {...reorder.getItemProps(index)}>
      <span {...reorder.getHandleProps(index)} aria-hidden style={{ cursor: 'grab', touchAction: 'none' }}>
        <GripVertical />
      </span>
      {item.name}
    </li>
  ))}
</ol>
```

Drag a row by its grip. The [Reorder](/recipes/reorder) recipe pairs the hook with a menu, for the keyboard and for anyone who can't drag.

A press on a handle makes its item draggable, so an item drags only by its handle and text in the items stays selectable. While an item is dragged, `dragging` is its index and `drop` says which item it would land beside and on which side, `before` or `after`, or is `null` where a drop would not move it. The items carry the same state as `data-dragging` and `data-drop`, for styles. A drop calls `onMove` only when the order changes, and a drop outside the items, or Escape during a drag, calls nothing. A drag the browser sends no `dragend` for, as a touch drag in Chromium can, ends at the next release. `from` is where the dragged item is when it is dropped, so a list that changes during a drag still moves that item, and a drag whose item is removed ends. Drags that didn't start from this list's handles, such as files, selected text or another list's items, are ignored, so they can't be dropped there. Both getters take your own props as a second argument and run your handlers before their own; a handler of yours that calls `preventDefault()` skips the hook's, as in every Todae part.

With `orientation="horizontal"`, `before` is the side the text starts from, so it is the right side in a right-to-left page.

## Accessible composition

**Todae handles:** Dragging an item only by its handle. Working out the item and side a drop lands on, and the index the dragged item ends at. Ignoring drags from elsewhere.

**You supply:** Another way to move an item that needs no dragging and works from the keyboard, such as the Reorder recipe's menu: the browser's drag and drop has no keyboard path. A handle hidden from screen readers with `aria-hidden`, since that other way is the one they use. Keys from each item's id. The announcement of a move, and how the drop line and the dragged item look.

**Watch for:** Drag as the only way to reorder (WCAG 2.2 SC 2.1.1 and SC 2.5.7). A handle that is a button or a tab stop: it does nothing from the keyboard. A handle smaller than 24 by 24 CSS pixels, such as a bare icon (SC 2.5.8). A handle without `touch-action: none`, which a press on a touch screen scrolls. A long press on a handle starts a drag in Chromium's touch drag and drop, but a whole touch drag hasn't been checked on a phone or tablet.

## When to use

**When:** Letting a person drag the items of a list they order themselves, beside a way to move them without dragging.

**When not:** Dropping files → [`useDropzone`](/utilities/use-dropzone). Moving items between lists → your product's own drag and drop.
