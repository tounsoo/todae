# Badge

A short static label or count, such as a status on a row or the number of unread messages. It comes in five tones: `neutral`, the default, and the four status tones `info`, `success`, `warning` and `critical`, which take their colors from `color.status.<tone>` through the `badge.<tone>` contract tokens.

```tsx
<Badge.Root tone="success">Paid</Badge.Root>
```

</Example>

Server Components can import it from `@tounsoo/todae/badge`. That entry has no `'use client'` and no hooks; the main `@tounsoo/todae` entry is a client module.

`Badge.Root` is a `span` with no role, so a screen reader reads it as part of the text around it. A bare number has no meaning on its own: add the rest in visually hidden text.

```tsx
<Badge.Root>
  3<VisuallyHidden.Root> unread</VisuallyHidden.Root>
</Badge.Root>
```

## Accessible composition

**Todae handles:** Color only. `Badge.Root` is a `span` with no role and no ARIA, and `tone` sets `data-tone`, which nothing announces. A screen reader reads the badge in line with the text around it.

**You supply:** Text that makes sense when read in that line. For a count, add the noun in a [VisuallyHidden](/visually-hidden), as above. When the tone carries meaning, such as overdue against paid, put that meaning in the words too.

**Watch for:** A badge made clickable with `onClick`: a `span` takes no focus and has no role, so use a [Button](/button) or a link. A count that changes while the user waits, such as new messages: the badge does not announce it, so use [useAnnouncer](/utilities/use-announcer) or another live region. A badge inside a button or link becomes part of its name, so the whole name has to read well.

## When to use

**When:** A status or count that labels something next to it: a paid invoice, a beta feature, unread messages.

**When not:** A label the user can remove → Chip. A message about the page or a task → Alert. Something the user clicks → Button.Root. A change you need announced → a live region, which a badge is not.
