# Slider

`Slider.Root` is a native `<input type="range">`. The browser handles arrow keys, Page Up and Down, Home and End, and announces the value. Todae sets `accent-color` from the `slider` contract tokens, and the browser uses it to tint the thumb and filled track. How much of the control that color reaches differs by browser.

```tsx
const id = useId();

<Field.Group>
  <Label.Root htmlFor={id}>Volume</Label.Root>
  <Slider.Root
    id={id}
    min={0}
    max={100}
    step={5}
    value={value}
    onChange={(event) => setValue(Number(event.target.value))}
  />
</Field.Group>
<Text.Root>{value}%</Text.Root>
```

Server Components can import it from `@tounsoo/todae/slider`. Name it with [Label](/label) and show the current value as text nearby when the exact number matters. Restyle through `slider.fill` and `slider.ring.focus`. A slider with two thumbs for a range is not native and is not part of Todae yet.

## Accessible composition

**Todae handles:** Only styles. The native `<input type="range">` already has the `slider` role, exposes its value, minimum and maximum, and takes the keys above. Todae tints it with `accent-color` and draws a focus outline from `slider.ring.focus` while it is focus-visible.

**You supply:** A name, from a [Label](/label) with `htmlFor` or from `aria-label`. `aria-valuetext` when the number alone does not mean much, such as `"40%"` or `"Medium"`. The current value as visible text when the exact number matters, and `aria-describedby` for any hint.

**Watch for:** A `div` slider built by hand needs its role, value attributes and keys added one by one; inside a Field, see [useField](/utilities/use-field). An `outline: none` of yours removes the focus ring.

## When to use

**When:** Picking a value in a range where the rough position matters more than the exact number, such as volume or zoom.

**When not:** An exact number → [Field.NumberInput](/field/number-input). A few named choices → [Radio](/radio). Showing progress the user does not control → [Progress](/progress).
