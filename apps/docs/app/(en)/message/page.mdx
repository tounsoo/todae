# Message

`Message.Root` is one turn of a conversation, as an `<article>`. `from` says who wrote it: a user's message sits at the end side in a bubble, an assistant's runs the full width, and a system message is a quiet line in the middle. It knows nothing about any agent SDK's message shape: map your own data onto its parts.

```tsx
<Message.Root from="user" aria-label="You">
  <Message.Content>How do I name an icon-only button?</Message.Content>
</Message.Root>

<Message.Root aria-label="Assistant">
  <Message.Avatar>
    <Avatar.Root tone="category-3">
      <Avatar.Fallback>A</Avatar.Fallback>
    </Avatar.Root>
  </Message.Avatar>
  <Message.Header>
    <strong>Assistant</strong>
    <time dateTime="2026-10-14T09:41">9:41</time>
  </Message.Header>
  <Message.Content>
    <Prose.Root>
      <p>Give it aria-label, or put a visually hidden label inside it.</p>
    </Prose.Root>
  </Message.Content>
</Message.Root>
```

## Parts

Every part is a `div`, and all of them are optional.

- `Message.Avatar` holds an `Avatar.Root`. With one, the other parts sit in a column beside it: after it for an assistant or system message, before it for a user's.
- `Message.Header` is a row for the author's name and a time. Pass your own `<time>` element: Todae formats no dates here. A heading or paragraph directly inside it has no margin.
- `Message.Content` is the text. For a user's message it is the bubble. Put rendered markdown in a [Prose](/prose) root inside it.
- `Message.Actions` is a row for the message's actions, such as copy and retry. Put a [Toolbar](/toolbar) in it when there are several, so they take one tab stop.

`from` sets `data-from` and changes only layout and tokens: it does not change the role or what screen readers hear.

## Streaming

Set `streaming` while the message is still arriving, and set it back to `false` when it finishes or fails. It sets `aria-busy="true"` on the article and `data-streaming`, and the last `Message.Content` draws a caret after the text: after the last paragraph, list item, heading or table cell when the content ends with one, or right after the text when `Message.Content` holds only text, with no elements in it. Content that ends with anything else, such as a code block or a rule, shows no caret. The caret blinks, and holds still under reduced motion.

```tsx
<Message.Root streaming={status === 'streaming'} aria-label="Assistant">
  <Message.Content>
    <Prose.Root>{rendered}</Prose.Root>
  </Message.Content>
</Message.Root>
```

Restyle it through the `message` tokens: `message.fg` sets the text color, `message.gap` and `message.row-gap` space the parts, `message.header.*` sets the header's color and size, `message.user.*` the bubble's background, text color, radius, padding, `max-width` and the `border-width` of its forced-colors outline, `message.system.*` the system line, and `message.caret.width` and `message.caret.motion.duration` the caret. A `Prose.Root` inside keeps the `prose` tokens' text color and size.

## Accessible composition

**Todae handles:** An `<article>` for each message, so screen reader users can move between them. `aria-busy` while it streams. The caret is drawn from CSS, so it is never read. In forced colors the user bubble keeps an outline, since its background is replaced.

**You supply:** A name for each message that says who wrote it, such as `aria-label="You"` or `aria-labelledby` pointing at the author in `Message.Header`. Names for icon-only action buttons. One announcement when a message finishes, rather than the streamed text.

**Watch for:** Putting the message that is streaming in a live region: every token is read as it arrives. A timestamp with no `<time dateTime>`, which machines can't read. Telling user and assistant apart by color or side alone; the name says it too.

## When to use

**When:** The turns of a chat with a person or an assistant, comments in a thread, a support conversation.

**When not:** A one-off status message about the page → [Alert](/alert). A notice that comes and goes → [Toast](/toast). A bordered group of content → [Card](/card).
