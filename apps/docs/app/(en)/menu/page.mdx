# Menu

A button that opens a list of actions. `Menu.Trigger` is a `Button.Root` with `aria-haspopup="menu"` and `aria-expanded`. `Menu.Content` is a `role="menu"` in a non-modal popover anchored to the trigger with CSS anchor positioning, the same surface as [Popover](/popover). The menu is named by its trigger unless it gets `aria-label` or `aria-labelledby`.

## Keyboard

Enter, Space, a click or ArrowDown on the trigger opens the menu on its first item; ArrowUp opens it on the last. In a vertical toolbar, Up and Down move between the toolbar's controls instead. In the menu, Up and Down move and loop, Home and End jump, and typing a letter moves to the next item that starts with it. Enter, Space or a click chooses an item. Choosing one that closes the menu returns focus to the trigger, unless the choice moved focus elsewhere, also when the choice moves the trigger in the page, as reordering a list does. Escape closes and returns focus to the trigger; Tab closes and moves focus past the trigger (in a toolbar, past the trigger's run of controls); Shift+Tab closes and stops on the trigger. Focus that moves anywhere else outside the menu, by a script, a screen reader or a press into an iframe, closes it too. Pointer movement focuses the item under it, so the pointer and the keyboard share one highlight. Disabled items carry `aria-disabled` and stay in the arrow-key order, as menus conventionally do, so a screen reader announces them as unavailable; they cannot be chosen. Hovering one focuses it, as the arrow keys do, so the highlight never stays on another item.

## Checkbox and radio items

An item's children are presentational to assistive technology, as ARIA defines for `menuitem`, so keep links, inputs and buttons out of items (an item can be a link itself, as Links shows); keys pressed in one are left alone, but a click on it also chooses the item. `Menu.CheckboxItem` toggles `aria-checked`. `Menu.RadioGroup` owns one value for its `Menu.RadioItem` children. Both stay open after a choice so several settings can change in one visit; set `closeOnSelect` to close. `Menu.Group` and `Menu.RadioGroup` need `aria-label` or `aria-labelledby`.

`onOpenChange(open, reason)` reports `trigger`, `context` (a `Menu.ContextTrigger`), `escape`, `outside` (a press or focus outside), `select` or `tab`. A controlled `open` that is not updated vetoes the change; a vetoed `tab` still lets focus move on, the way a vetoed `outside` still lets the press land.

## Submenus

`Menu.Submenu` puts a list inside a list. `Menu.SubmenuTrigger` is an item with `aria-haspopup="menu"` and a chevron at the end of its line, and `Menu.SubmenuContent` is the `role="menu"` it opens, named by the trigger. The submenu opens past the trigger's end with its first item level with the trigger, and flips to the other side, or up, where there is no room. A submenu can hold any item, a group or another submenu.

<Example of={MenuSubmenu} />

Right arrow, Enter or Space on the trigger opens the submenu on its first item; in a right-to-left page, Left arrow does. Left arrow (Right arrow in right-to-left) or Escape closes only that submenu and puts focus back on its trigger. Up, Down, Home, End and typeahead move within the submenu's own items. Choosing an item in it, or Tab, closes the whole menu, as in the menu itself. The pointer resting on the trigger for `menu.submenu.delay.show` opens the submenu and leaves focus on the trigger; a click or tap opens it at once. Focus moving to another item of the menu it sits in closes it.

On its way from the trigger to the submenu, the pointer may cross other items. For `menu.submenu.delay.hide`, while the pointer stays inside the triangle between where it left the trigger and the submenu's near edge, those items leave focus where it is, so the submenu stays open. A pointer that stops, turns back or runs out of time focuses the item under it as usual.

`Menu.Submenu` takes `open`, `defaultOpen` and `onOpenChange(open, reason)`, where reason is `trigger` (a click or key on the trigger), `pointer` (the pointer resting on it), `escape`, `arrow` (the arrow key toward the line's start) or `parent` (focus moved to another item, or the menu it sits in closed).

## Links

An item that goes somewhere, such as Help or Settings, is a link. Pass `render` and return the link with the props it is handed; the element keeps `role="menuitem"` and the menu's keyboard. Enter, Space or a click follows the link, runs `onSelect` and closes the menu. A disabled item can't be chosen; leave out its `href` too, so a middle click or the browser's Open in new tab can't follow it.

```tsx
import NextLink from 'next/link';

<Menu.Item render={(props) => <NextLink {...props} href="/settings" />}>Settings</Menu.Item>
```

## Context menus

`Menu.ContextTrigger` is a region, such as a row, a file or a message, that opens the menu on a right click, a long press on Android, Shift+F10 or the ContextMenu key. A pointer opens the menu at the pointer; a key opens it below the focused element. The menu flips to stay in the viewport, as from `Menu.Trigger`, and opens on its first item. Escape gives focus back to whatever had it when the menu opened, or to the `Menu.Trigger` when that is gone or could not take focus, as after a right click on text. The region renders a `div`; pass `render` to make it a table row or a list item, and spread the props it is handed. While its menu is open, the region carries `data-open`, so a product can highlight the row that was clicked.

Give each region a visible `Menu.Trigger` in the same `Menu.Root` as well. A context menu can't be seen, few people know Shift+F10, Mac keyboards have no ContextMenu key, and iOS Safari fires no `contextmenu` on a long press, so the button is how many people reach the same menu.

A right click or Shift+F10 in a text field inside the region leaves the browser's own menu, which holds the field's editing commands. A region inside another region takes the request first. A right click inside an open menu doesn't open the browser's menu over it.

## Icons

`Menu.CheckboxItem` shows the `check` glyph while checked: Todae's check mark, unless a [GlyphsProvider](/utilities/glyphs-provider) sets one. `Menu.SubmenuTrigger` shows the `chevron` glyph, turned toward the end of the line. An icon-only trigger takes an icon from any library in `Button.Icon`, and needs a name.

```tsx
import { Check, Ellipsis } from 'lucide-react';

<GlyphsProvider glyphs={{ check: <Check /> }}>
  <Menu.Root>
    <Menu.Trigger variant="ghost" aria-label="View options">
      <Button.Icon>
        <Ellipsis />
      </Button.Icon>
    </Menu.Trigger>
    <Menu.Content>
      <Menu.CheckboxItem checked={grid} onCheckedChange={setGrid}>
        Show grid
      </Menu.CheckboxItem>
    </Menu.Content>
  </Menu.Root>
</GlyphsProvider>
```

## Accessible composition

**Todae handles:** `Menu.Trigger` sets `aria-haspopup="menu"`, `aria-expanded` and `aria-controls`, and its id names the `role="menu"` content through `aria-labelledby`. Items get `role="menuitem"`, `menuitemcheckbox` or `menuitemradio`, with `aria-checked` and `aria-disabled` kept in step. `Menu.SubmenuTrigger` sets `aria-haspopup="menu"`, `aria-expanded` and `aria-controls`, and names its submenu. `Menu.Group` and `Menu.RadioGroup` are `role="group"`, and `Menu.Separator` is `role="separator"`. Focus moves into the menu when it opens and follows the keyboard model above. `Menu.ContextTrigger` handles the `contextmenu` event and Shift+F10 and the ContextMenu key, places the menu at the pointer or the focused element, and returns focus when it closes.

**You supply:** A name for the trigger, which also names the menu. Text children are enough. An icon-only trigger needs `aria-label` or `aria-labelledby`; without one, `Button.Root` logs an error in development. A menu opened from code or from a `Menu.ContextTrigger` with no `Menu.Trigger` needs its own `aria-label` or `aria-labelledby` (without one, `Menu.Content` logs an error in development when it opens), a context menu needs a visible `Menu.Trigger` too, and every `Menu.Group` and `Menu.RadioGroup` needs one, as its type requires. Pass `textValue` when an item's children are not plain text, so typeahead can match it.

```tsx
import type { ReactNode } from 'react';
import { Button, Menu } from '@tounsoo/todae';
import { Ellipsis } from 'lucide-react';

export function RowActions({ label, children }: { label: string; children: ReactNode }) {
  return (
    <Menu.Root>
      <Menu.Trigger variant="ghost" aria-label={label}>
        <Button.Icon>
          <Ellipsis />
        </Button.Icon>
      </Menu.Trigger>
      <Menu.Content>{children}</Menu.Content>
    </Menu.Root>
  );
}
```

**Watch for:** A wrapper that takes a `label` prop but drops it before `Menu.Trigger`, leaving both the trigger and the menu unnamed. Links, inputs or buttons inside an item: its content is presentational, so they are not announced as controls. Hiding the check or radio indicator and showing the state with color alone. A `Menu.Trigger` `onClick` that calls `preventDefault()`, which stops the trigger from opening or closing the menu. A context menu that is the only way to reach its actions: a long press on iOS doesn't open it, and few people know Shift+F10. A context menu over content whose browser menu people need, such as links and images, since it replaces Open in new tab and Save image. Submenus nested more than two deep, which are hard to follow and to reach with a pointer.

## When to use

**When:** A short list of commands or view settings behind one button, such as row actions or a toolbar overflow. The same commands on a right click or Shift+F10 over a row, file or message, with `Menu.ContextTrigger` beside the button.

**When not:** Picking a value for a form → `Field.Select` or the Combobox recipe. Navigation between pages → links. Content with its own controls or text → Popover with `role="dialog"`.
