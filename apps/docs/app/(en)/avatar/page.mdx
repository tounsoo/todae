# Avatar

A picture of a person or a team, with a fallback such as initials. `Avatar.Fallback` shows while `Avatar.Image` loads, and stays when the image fails or there is none. The image draws over the fallback, which is removed once the image has loaded.

```tsx
<Avatar.Root label="Ada Lovelace">
  <Avatar.Image src={user.photoUrl} />
  <Avatar.Fallback>AL</Avatar.Fallback>
</Avatar.Root>
```

## Naming

With `label`, the avatar is one image named by `label`, whichever of the image and the fallback shows, so a screen reader reads "Ada Lovelace" rather than "AL". `Avatar.Image` takes no `alt` for that reason.

When the name is written next to the avatar, leave out `label`. The avatar is then decorative and hidden from assistive technology, so the name is not read twice.

```tsx
<Avatar.Root>
  <Avatar.Image src={user.photoUrl} />
  <Avatar.Fallback>AL</Avatar.Fallback>
</Avatar.Root>
<Text.Root>Ada Lovelace</Text.Root>
```

## Sizes

Avatar has no `size` prop. Your design system owns the sizes. An avatar draws at `avatar.size.md`, 2rem. To change one, set `--todae-avatar-size-md` on the avatar, or on an ancestor with no `[data-appearance]` or `[data-density]` element between them. A ThemeProvider or DensityProvider in between declares the token again and drops the ancestor's value. `avatar.size.sm` (1.5rem) and `avatar.size.lg` (2.5rem) are two more steps for a theme to change, and for your CSS to pick from. The fallback text scales with the box through `avatar.font.scale`.

```tsx
<Avatar.Root className={styles.small} label="Ada Lovelace">
  <Avatar.Fallback>AL</Avatar.Fallback>
</Avatar.Root>
```

```css
.small {
  --todae-avatar-size-md: var(--todae-avatar-size-sm);
}
```

To change every avatar in a product, set `avatar.size.md` in your theme or in `ThemeProvider` overrides.

Initials are yours to choose: how to shorten a name depends on the language and the person. Restyle the shape through `avatar.radius`.

## Colors

`tone` sets the avatar's colors, which show behind the fallback. `neutral`, the default, reads `avatar.bg` and `avatar.fg`. `category-1` to `category-8` read the `avatar.category-<n>` contract tokens, from `color.category.<n>`. To give each person a color that stays the same, pass a stable key such as a user id to `categoryTone`:

```tsx
<Avatar.Root label={user.name} tone={categoryTone(user.id)}>
  <Avatar.Fallback>{user.initials}</Avatar.Fallback>
</Avatar.Root>
```

## Stacked avatars

A few avatars stacked, such as assignees, are the [Avatar group](/recipes/avatar-group) recipe: a `div` with `role="group"`, some `Avatar.Root`s, and CSS you copy.

## Accessible composition

**Todae handles:** With `label`, `Avatar.Root` is `role="img"` named by `aria-label`, and `Avatar.Image` renders `alt=""`, so the image and the initials share one name. Without `label`, the root is `aria-hidden`. The types leave out `role`, `aria-label` and `aria-labelledby` on the root and `alt` on the image, so a wrapper cannot add a second name by mistake.

**You supply:** The choice between the two. A wrapper that shows a person should pass `label` when the avatar stands alone, such as in a row of participants, and leave it out when the name is written next to it. The name comes from your data; Todae does not read it from the fallback.

**Watch for:** An avatar with no `label` as the only content of a button, a link or a [Menu](/menu) trigger: the avatar is hidden, so the control has no name. Give the control `aria-label`, or the avatar `label`. A presence dot or ring the wrapper adds shows status by color alone; put the status in text as well.

## When to use

**When:** A person, team or workspace shown in a list, a header or next to a message.

**When not:** A picture with content of its own → `<img>` with real `alt` text. A status or count → [Badge](/badge). A control that opens a profile menu → put the avatar inside a [Menu](/menu) trigger, which carries the name.
