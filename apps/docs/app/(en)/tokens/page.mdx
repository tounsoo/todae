# Tokens

Generated catalog from the DTCG pipeline. Components consume contract vars only. The JSON catalog, `@tounsoo/todae/tokens.json`, also names the set or modifier that declares each token in `entry`, which is where a company token package overrides it.

To read the providers from code, `useAppearance()` returns the nearest ThemeProvider's resolved appearance (`light` or `dark`) and `useDensity()` the nearest DensityProvider's density. With no provider above, they return `light` and `comfortable`.

```tsx
function Panel() {
  const appearance = useAppearance(); // 'dark'
  const density = useDensity(); // 'compact'
  return <Text.Root>{appearance}, {density}</Text.Root>;
}

<ThemeProvider appearance="dark">
  <DensityProvider density="compact">
    <Panel />
  </DensityProvider>
</ThemeProvider>
```

## When to use

### ThemeProvider

**When:** Set appearance (system / light / dark) for a subtree via `data-appearance`; a nested provider overrides it, or keeps the enclosing one's when it sets none. `overrides` for allowlisted token paths only.

**When not:** Spacing density → DensityProvider. Raw CSS or unknown token keys (rejected).

`THEME_OVERRIDE_KEYS` is the list of token paths `overrides` accepts. Import it from `@tounsoo/todae`. The list joins the raw keys, the semantic keys, and the component keys. A path outside that list is rejected unless you pass `overrideTypes` from a company token build. [Build on Todae](/guides/build-on-todae) shows that build. [`themeOverrideStyle`](/utilities/theme-override-style) writes the same overrides as `--todae-*` custom properties without rendering `ThemeProvider`.

```ts
import { THEME_OVERRIDE_KEYS, type ThemeOverrideKey } from '@tounsoo/todae';

function listed(key: ThemeOverrideKey) {
  return THEME_OVERRIDE_KEYS.includes(key);
}
```

### DensityProvider

**When:** Set spacing density (compact / comfortable / spacious) for a subtree via `data-density`; a nested provider with none keeps the enclosing one's. Spacing only.

**When not:** Color or light / dark → ThemeProvider. Type size → the `font.size.*` tokens.

### useAppearance

**When:** A component of your own that must know whether it renders light or dark, such as one that picks an image.

**When not:** Colors → tokens, which follow the appearance in CSS.

### useDensity

**When:** A component of your own that must know the density in JavaScript.

**When not:** Spacing → tokens, which follow the density in CSS.

## Contrast

The token build measures text pairs with APCA, not WCAG 2 ratios. Each pair names a text color, a background and the lowest Lc allowed, for example `color.fg.muted` on `color.bg.elevated` at Lc 60. A pair with a translucent background, such as a selected row's, lists in `over` the opaque surfaces it can sit on, and is measured over each one. The build fails when a pair falls short in any appearance, and names the nearest lightness of the text or background color that would pass.

The pairs live in `$extensions["dev.todae"].contrast` in `tokens/resolver.json`: pairs of semantic colors on the appearance modifier, and pairs of Field, Nav, OptionList and Tree text on their own backgrounds, such as `field.fg.placeholder` on `field.bg.default`, and of `text.label.fg` on the four `color.bg` surfaces and `popover.bg`, on the contract set. A company token package inherits them, so a rebranded accent is checked, and so are those component colors. A company can list a pair with the same `fg` and `bg` in any of its sets or modifiers to change its minimum; it keeps Todae's `over` surfaces unless it lists its own. A company can also add pairs for its own tokens.

A brand accent is four tokens per appearance: `color.accent.default`, `color.accent.hover`, `color.accent.active` and `color.on-accent`. Set them together, since Todae's dark `on-accent` is near-black to sit on its near-white ink. Put the brand accent in a company token package so the build checks it. `ThemeProvider` overrides apply at runtime; only development checks them, with a console warning.

## References and opacity

Token files follow DTCG 2025.10: an alias is a JSON Pointer `$ref`, such as `{ "$ref": "#/color/gray/900/$value" }`, and the build rejects a curly-brace alias such as `"{color.gray.900}"`. A translucent color points at the three channels of its base color with `#/<token>/$value/components/0` to `2`, and sets its own `alpha`.

`alpha` is a number from 0 to 1, or a `$ref` to a `number` token. Todae's translucent colors take theirs from the `opacity` scale, where `opacity.<n>` is n percent, for example `"alpha": { "$ref": "#/opacity/12/$value" }`. The build emits the alpha as that token's CSS variable.

## Letter case

DTCG 2025.10 has no type for letter case, so Todae adds one: `textTransform`, whose value is `none`, `uppercase`, `lowercase` or `capitalize`. `font.text-transform.default` holds `none`, and Button, Tabs, Label, the Table header and Text's label role each read their own `font.text-transform` token, which points at it. Tools that only know the DTCG types may not accept a `textTransform` token. When DTCG adds a standard type for letter case, Todae will move to it.

## Status tones

Four tones carry status: `info`, `success`, `warning` and `critical`. Each is three tokens per appearance: `color.status.<tone>.fg` for text and icons, `.bg` for the fill, and `.border`. The build checks `fg` on `bg` at Lc 75 and `fg` on `color.bg.surface` at Lc 60. [Alert](/alert) reads them through its `alert.<tone>` contract tokens. `info` is neutral ink, matching the accent; a company can give it a hue in its token package.

## Category tones

Eight tones label categories such as tags or people: `color.category.1` to `color.category.8`, each with `fg`, `bg` and `border` per appearance. They are numbered rather than named after hues, so a company can change a hue in its token package without renaming anything. The build checks `fg` on `bg` at Lc 75. [Badge](/badge), [Chip](/chip) and [Avatar](/avatar) take them as the tones `category-1` to `category-8`, and [categoryTone](/utilities/category-tone) picks one from a string, such as a user id.

## Focus ring

`focus.ring`, `focus.ring-width` and `focus.ring-offset` describe Todae's focus ring. Each component's `ring.focus` color token, such as `button.primary.ring.focus` or `field.ring.focus`, points at `focus.ring`, so changing it recolors those rings. A component's own token still overrides it for that component. Read the three tokens to draw the same ring on a focusable element of your own:

```css
.my-card:focus-visible {
  outline: var(--todae-focus-ring-width) solid var(--todae-focus-ring);
  outline-offset: var(--todae-focus-ring-offset);
}
```

## Motion

A component that animates as it opens and closes has motion tokens of its own: `motion.duration.enter`, `motion.duration.exit`, `motion.easing.enter` and `motion.easing.exit`, such as `dialog.motion.duration.enter`, and one that only fades in, as Tooltip, Alert and ErrorMessage do, has only the enter pair. How far something moves is a token beside its timing, such as `popover.motion.scale`, `dialog.motion.offset` and `toast.motion.offset`. A part that draws on another component moves with that component's tokens, as Menu and the field pickers move with Popover's, unless it has motion tokens of its own: Coachmark's popup is a Popover surface timed by `coachmark.motion`, in step with its scrim. Every `motion.easing.enter` points at the core `motion.easing.enter`, which slows as it settles, `cubic-bezier(0.2, 0.8, 0.2, 1)`, and every `motion.easing.exit` at the core `motion.easing.exit`, which speeds up as it leaves, `cubic-bezier(0.4, 0, 1, 1)`. Changing a core curve changes every component's, and changing one component's curve token changes only that component. An exit is as short as its enter or shorter.

Each component's enter and exit durations point at a motion role, which points at the core `motion.duration` scale. Changing a role's `duration.enter` or `duration.exit` retimes every component in that role, and changing one component's own token retimes only that component. The catalog below shows which role each component's tokens point at, and how long each role lasts.

- `motion.reveal`: content that opens in place.
- `motion.popup`: a surface anchored to its trigger.
- `motion.window`: a window centered over the page.
- `motion.panel`: a panel that slides in from an edge.
- `motion.notice`: a short-lived message.

Roles hold durations only. A change between two states that both stay on screen, such as a toggle's thumb, a slide between views, a resize or a hover fade, points its `motion.duration` at the core scale instead of a role, and a loop keeps its own cycle length and may keep its own curve, as Skeleton's pulse does with `skeleton.motion.easing`, since a pulse eases both ways. A control's hover fade stops at once for a press, keyboard focus, a pressed toggle, the current page or a disabled state, fades back when that ends, and never fades the focus ring.

Two more kinds of motion follow the same rules. Progress and Meter glide their fill to a new value with `progress.motion.fill.duration` and `progress.motion.fill.easing`, a change between two states, and jump under reduced motion. Alert and ErrorMessage fade in as they appear with `alert.motion.duration.enter` and `alert.motion.easing.enter`, and `field.error.motion.duration.enter` and `field.error.motion.easing.enter`; they go at once, so they have no exit pair, and they keep fading under reduced motion.

When the user prefers reduced motion, nothing slides, scales, rises or turns, and loops hold still. Fades keep their tokens, since they move nothing.

## Descriptions

Todae's semantic and density tokens and each component's token group carry a DTCG `$description` that says what they are for. A token with no description of its own takes the nearest enclosing group's in the same file. The token catalog (`tokens.json`) and the MCP token tools return it as `description`. Describe a token that changes with appearance or density once, in one context's file. A company token package describes its own tokens the same way. Its description of a Todae token, in any context, replaces Todae's; an override with none keeps Todae's.
