# Popover

Non-modal `popover="manual"`. Controlled `open`. Outside click and Escape call `onOpenChange(false, reason)`. `hidePopover()` runs only after `open` is false, so a veto keeps it shown.

No focus trap, no `aria-modal`, no scroll lock, no inert. No portal — the surface stays in the React tree so `ThemeProvider` vars inherit.

Positioning is CSS anchors only. `Popover.Trigger` sets `anchor-name`. Content uses `position-anchor` and `top: calc(anchor(bottom) + var(--todae-popover-offset))` with `--todae-popover-offset: var(--todae-space-1)` (`4px`). Flip is `@position-try --todae-popover-flip-block` plus `flip-block` or `position-try: top` when the engine supports those. There is no JS pin, no `getBoundingClientRect` follow, and no rAF scroll glue.

A browser without CSS anchors keeps the UA popover default. The surface does not follow scroll and does not flip. Todae does not polyfill that. Safari 26+ has anchors. Safari 26 documents `position-try` with `position-area` names. `flip-block` is Chrome’s tactic. iOS before 26 has `popover` and no CSS anchors.

The surface is the top-layer hit target: `position: fixed; inset: unset; pointer-events: auto`. Taps on content do not pass through. `Option` selects on `click` so closing the menu cannot leave a leftover click on the page.
